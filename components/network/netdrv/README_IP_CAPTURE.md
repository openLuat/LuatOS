# IP 包通过日志口导出 PCAP

当前在启用 `LUAT_USE_NETDRV_IP_CAPTURE` 的 Air1601 CH390H 上实现抓包，观察点统一在 `luat_netdrv_pkg` 公共包层。BK/Air8101 SDK 保持原版，本轮不启用抓包；共享 netdrv 在抓包宏关闭时保持兼容，不需要 BK 提供抓包发送接口。

## Lua 控制

网卡初始化后、启动 DHCP 前启用，可以同时记录 DHCP 过程：

```lua
-- 每张网卡独立配置，默认关闭。
local ok, err = netdrv.ctrl(socket.LWIP_ETH, netdrv.CTRL_IP_CAPTURE, 1500)
assert(ok, err)

-- 最多保留每个 IP 包的前 128 字节。
netdrv.ctrl(socket.LWIP_ETH, netdrv.CTRL_IP_CAPTURE, 128)

-- 关闭指定网卡。
netdrv.ctrl(socket.LWIP_ETH, netdrv.CTRL_IP_CAPTURE, 0)
```

第三个参数为每包截取长度，范围 `0..1500`，单位字节，包含 IP 头。返回 `boolean, integer`，成功为 `true, 0`，失败为 `false, -1`。只有支持此功能的固件提供 `netdrv.CTRL_IP_CAPTURE`。

只输出 IPv4/IPv6，剥离以太网头、最多两层 VLAN 标签及填充。ARP 不输出。RX 在 netdrv 输入处理前观察，TX 在对应网卡输出前观察，包括经过这些路径的 NAPT 报文。同一个包经过两个已开启的网口时，两侧各有一条记录。

## 公共 pbuf 收发接口

- `luat_netdrv_pkg_input_pbuf(id, src, p)`：借用单段或链式 pbuf。HW 接收先抓包，再处理订阅观察和 NAPT；LWIP 发送只有订阅该层时才展开链式缓冲并交给用户接管。没有对应订阅的普通 TX 不展开完整包。
- `luat_netdrv_pkg_output_pbuf(id, dst, p, sender, userdata)`：最终硬件发送观察点，抓包后调用原驱动 sender，直接返回 sender 的结果。公共层不展开、不增加引用、不释放 pbuf，也不保存它的指针。
- CH390 普通 TX 经公共 pbuf 输入检查和输出接口；NAPT/raw TX 经 `pkg_output`、驱动连续数据适配，再汇入同一公共 pbuf 输出接口。两条路径均只由原 sender 将整包复制到 SPI 队列一次，驱动内不包含抓包调用。
- `luat_netdrv_pkg_attach_native()` 保留为可选的原生网卡公共输出接入口。原版 BK SDK 不调用该接口，继续使用原有 Wi-Fi 发送路径；BK 抓包适配暂缓。
- SDK 的旧 `luat_netdrv_napt_pkg_input_pbuf()` 作为兼容入口委托公共 pbuf 输入。原 1520 字节上限只限制这条路径的 NAPT 处理，不限制抓包和 HW 观察。

公共层根据网卡 Ethernet 标志区分以太网帧与裸 IP，不根据通道号猜测格式。Lua 仅订阅 HW 观察时，不会消费 LWIP TX；订阅 LWIP 时，连续和链式发送包都可接管。展开失败返回错误，CH390 将错误反馈给 lwIP，不把失败当作已消费成功。

CH390 原来的队列/分配失败返回方式保持不变，因此公共出口保留 sender 返回值不代表所有硬件排队失败都会反馈给 lwIP。TX 抓包表示提交到驱动发送入口的报文，不保证最终已上线路。

回归检查可用主机 GCC 和 Python 运行 `tests/test_pkg_pbuf.py`，无第三方 Python 依赖。它执行实际公共包/抓包源码及 CH390 路由，覆盖开关抓包两种构建、链式拦截、HW-only 订阅、每条 TX 路径单次抓包/队列复制、NAPT/VLAN、原生网卡回环、失败处理和所有权。

## 模块到 Luatools

沿用 SOC A5 外层帧，命令号 `21`。载荷头固定 20 字节，所有多字节字段为小端：

| 偏移 | 字段 | 长度 | 含义 |
| --- | --- | --- | --- |
| 0 | version | 1 | 固定为 1 |
| 1 | adapter | 1 | 网卡编号 |
| 2 | direction | 1 | 0 RX，1 TX |
| 3 | flags | 1 | 保留，固定为 0 |
| 4 | sequence | 4 | 全局序号，允许回绕，丢弃也消耗序号 |
| 8 | device_tick_ms | 8 | 设备单调毫秒时间 |
| 16 | original_len | 2 | 原 IP 包长度 |
| 18 | captured_len | 2 | 实际截取长度 |
| 20 | packet | captured_len | 原始 IP 字节 |

抓包在当前网络收发任务中截取、编码，并直接非阻塞提交到平台已有日志缓冲，不创建独立抓包 task 或队列。每包临时分配最多 1520 字节记录缓冲，提交返回后立即释放。内存或日志发送空间不足时直接丢弃抓包记录并累计计数，可通过 `luat_netdrv_capture_dropped()` 和日志协议序号间隙统计，不在网络回调中额外打印丢包提示。配置关闭后，已进入平台日志缓冲的记录仍可能完成发送。模块不限制累计抓包字节数，也不接收 PCAP 文件大小配置。

Air1601 复用 `soc_cmd_response()` 及原有 CRC/转义编码器。编码器使用原 64 字节暂存区，向响应 FIFO 的局部元数据副本写入；全部成功后只发布真实写指针，保留中断推进的读指针，不另行分配整帧缓冲。接口返回 0 表示已提交，负数表示失败，旧调用可以忽略返回值。命令 21 拒绝中断、未初始化和非缓存模式，不走阻塞直发路径。没有额外的 4096 字节上限或 1024 字节预留，容量按完整帧最坏长度校验。普通日志状态机保持 SDK 原版，本次未合入通用日志修复。

BK 专用发送器、配置开关及共享 SOC 日志帧锁已撤回。BK 抓包功能留待后续独立适配。

## Luatools 文件生命周期

Luatools 使用正常串口日志解析入口接收命令 21，不占用普通命令响应槽。

- 每次开始串口日志接收，在首条有效 A5 帧解出时新建 PCAP，即使尚未收到 IP 包。
- 同次连接中，所有已选网卡合并到一个文件，使用 PCAP 2.4、`LINKTYPE_RAW=101`，保留每条记录的实际长度和原长度。
- PCAP 保存于已配置的日志目录下的 `pcap` 目录，文件名包含本机时间、串口和轮转编号。
- 单文件总大小上限为 `200 * 1024 * 1024` 字节，包含文件头和记录头。下条完整记录会越界时先创建新文件，不拆分记录。
- 断开、接收异常或任务取消时关闭文件；重连后使用新文件和新的解包状态，不续写旧文件。
- 文件时间戳由设备时间映射到主机时间。模块在连接中重启时重新映射，时间戳保持不倒退，当前文件继续使用。
- PCAP RAW 格式不保存额外的网卡编号或方向字段；这两个字段仅存在于日志协议中。

日志带宽不足时抓包可能不完整，序号间隙可用于统计丢失记录。截取长度较小时，Wireshark 显示报文被截断属于预期。
