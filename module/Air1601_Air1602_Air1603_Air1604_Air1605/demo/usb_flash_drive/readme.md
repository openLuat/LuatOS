# Air860x U 盘挂载与读写测试 项目说明

## 项目概述

本项目演示在 Air1601/Air1602/Air1603 系列模组上，把 USB 切到主机模式、接入 U 盘（MSC 大容量存储设备）、挂载到 `/udisk` 后循环读写文件。

目前适配的板型：

| 板型 | 主控 | U 盘 VBUS 使能脚 | 命中后补拉的共轨 |
| --- | --- | --- | --- |
| Air8601 | Air1601 | GPIO73 | 无 |
| Air8605 / Air8605B | Air1601 / Air1602 | GPIO58 | GPIO12 |
| Air8603 | Air1603 | GPIO58 | 无 |

固件烧进任意一块上述板子都能直接跑，脚本会自己判断是哪块板、开对应的供电脚，不需要改代码。

涉及的库：`usb`（主机模式与 MSC 事件）、`fatfs`（挂载文件系统）、`io`（列目录与读写文件）、`gpio`（VBUS 使能脚）、`pm`（模组 USB 主机内部供电开关）。

## 功能说明

本 demo 按下面 5 步工作：

1. **读主控型号**：`hmeta.model()` 取当前模组型号，据此筛选候选板型，主控对不上的板子不会被试。

2. **探测接口**：按候选顺序逐个只拉高该板型的 VBUS 脚，等 2.5 秒看有没有设备枚举上来。谁能枚举出 U 盘就是哪块板，命中后再补拉共轨脚（8605 的 GPIO12），并把这个配置锁定，后面整段循环不再重判。

3. **挂载**：设备接入后等 500ms（枚举到 MSC 就绪需要 200~400ms），调用 `fatfs.mount` 挂到 `/udisk`；失败最多重试 5 次。

4. **循环读写**：每秒一轮，先把 `/udisk` 下的每个条目按 `[序号] 类型 大小 文件名` 打印出来，再覆盖写 `udisk_test.txt`，写完读回逐字节比对，最后打印本轮结果。

5. **热插拔**：U 盘拔掉时按 `usb.EV_DISCONNECT` 事件立即卸载；如果读写连续失败 2 次也会自动卸载，等重新插入后再挂载，不会对着已经掉线的设备一直刷错误。

## 演示硬件环境

1、Air8601 / Air8603 / Air8605 开发板其中一块；

2、TYPE-C USB 数据线一根，连接板上丝印标注 `USB1` 的烧录口（若电脑 USB 口供电不足导致烧录失败，可改用外部稳压电源从 VIN 供电）；

3、U 盘一个，插到板上的 Type-A 母座上，文件系统为 FAT32 或 exFAT（exFAT 已实测可正常挂载）；

4、注意这几点：

- Air8603 的 Type-A 母座和 USB 摄像头共用同一路 5.5V，插 U 盘时不要同时接摄像头，摄像头与 U 盘只能二选一；
- 主机模式只识别大容量存储类（MSC）设备，接鼠标、键盘、USB 网卡不会被枚举成 U 盘；
- 插盘后如果日志里一条 USB 事件都没有，先用万用表量 Type-A 母座 1、2 脚对 GND，正常应有 5.1~5.5V，为 0V 说明 VBUS 使能脚没真正生效，先查硬件再看代码。

## 演示软件环境

1.[Luatools 工具](https://docs.openluat.com/air780epm/common/Luatools/)；

2.内核固件文件（底层 core 固件文件）：

本 demo 开发测试时使用的固件为 `LuatOS-SoC_V1029_Air1601_101_20261102_120331.soc`（Air1601/1602/1603 通用）。

**必须选 101 版固件**，不能选 102 版：102 版没有编入 fatfs，脚本里拿到的 `fatfs` 是 nil，一上来就会打印 `固件缺 usb 库或 fatfs.USB`。

3.luatos 需要的脚本和资源文件：

- 本目录的 `main.lua` 一个文件即可，没有额外的资源文件；
- lib 脚本文件：使用 Luatools 烧录时，勾选"添加默认 lib"选项，使用默认 lib 脚本文件。

4.准备好软件环境之后，将本目录的 `main.lua` 烧录到开发板中。烧录建议先执行一次"整片擦除"再下载固件和脚本，否则可能出现脚本区挂载失败（日志表现为 `soc_flash_lfs_init mount fail=-84`，之后看门狗超时重启，脚本一行都不会执行）。

2、Luatools 烧录内核固件和本目录的 `main.lua`；

3、烧录成功后自动开机运行，U 盘供电脚会在脚本启动 0.5 秒后被拉高；

4、在日志中查看运行结果，正常流程依次是下面三段。

- 第一段：脚本加载与板型识别

  ```

  I/user.U盘 主控: Air1601 | 候选: Air8601 / Air8605

  如果 U 盘没插，会看到 `探测: GPIO73 无接入（Air8601）`、`探测: GPIO58 无接入（Air8605/8605B）`，最后是 `所有接口都没枚举出 U 盘` 和 `模块: xx | 未插盘，按主控推测`，插上盘后自动继续。

  ```

  I/user.U盘   [03] FILE    21316  udisk_append.log
  I/user.U盘 写: 成功  AIR860X 第1轮 2026-11-04 17:05:41
  I/user.U盘 [第 1 轮] 读 成功 / 写 成功
  ```

- 第三段：持续循环读写，每秒一轮，轮次编号递增

  ```
  I/user.U盘 写: 成功  AIR860X 第2轮 2026-11-04 17:05:43
  I/user.U盘 [第 2 轮] 读 成功 / 写 成功
  I/user.U盘 写: 成功  AIR860X 第3轮 2026-11-04 17:05:46
  I/user.U盘 [第 3 轮] 读 成功 / 写 成功

## 关键实现说明

- **`usb.on` 必须在 `usb.mode` 切主机、USB 上电之前注册**，否则会漏掉第一个设备的接入事件；回调形参是 `usb_id, class, app_id, event` 等 7 个，判断设备类用 `class == usb.MSC`。
- **`fatfs.mount` 第 8 参 `auto_format` 必须显式传 `false`**。该参数默认是 `true`，会在挂载失败时把用户的 U 盘格式化。
- **USB 主机只初始化一次**。反复 `pm.power(pm.USB, false)` + `usb.mode` 会让第二次枚举失效，表现就是"单板能挂，板型表里多开一个型号就挂不上"。本项目用 `usb_host_once()` 保证全程只初始化一次，探测阶段改为只切 GPIO 脚。
- **供电脚只能用 `gpio.setup(pin, 1)` 一次到位，且整机只驱动一次**。`gpio.setup` 的第二参 `0` 是"输出低电平"、`1` 是"输出高电平"、`nil` 才是输入，所以 `gpio.setup(pin, 0)` 后面再 `gpio.set(pin, 1)` 会给 VBUS 使能脚打一次低电平毛刺，USB 栈当场按拔盘处理并重新枚举，结果就是"探测命中后第一次挂载必然失败（NOTRDY）"。
- **探测阶段只拉 VBUS 脚、不拉共轨**。共轨脚可能正是另一种板型的 VBUS 脚，一起拉会让板型判定出错。
- **探测失败后也不把脚拉低**。8605 板上 GPIO73 是另一路电源使能，拉低可能把 U 盘那路一起关掉。
- **`io.lsdir` 返回两个值，用 `pcall` 包必须接三个**：`local ok, ret, data = pcall(io.lsdir, ...)`。另外设备掉线后 `opendir` 仍能成功、`readdir` 读不到东西，返回的是 `true` + 空表，所以空表也要当成失败。
- **掉线只信 USB 事件**。fatfs 不会自己感知设备消失，断开那一刻主任务可能正在读写，`sys.publish` 的消息会因为没人等待而被丢弃，所以本项目用标志位（`M.unplugged`）记录状态，消息只当唤醒用。

## 注意事项

- 主控相同、供电脚也相同的板型没有硬件上的区别，本项目按板型表的顺序先报告靠前的那一个（例如 Air1601 + GPIO58 会判为 Air8605/8605B，而不是 Air1601 开发板 V1.2）。要固定成某一块板，把 `BOARDS` 表里其他项注释掉即可。
- Air8603 的 GPIO73 是 `AUDIOPA_EN`（功放使能），**不要拉高**；8603 的 485 使能是 GPIO58 经 R128 0R 与 `UVC_EN` 二选一，改板时注意不要和 485 冲突。
- Air8605 上与 U 盘无关的使能脚：GPIO56 = 9V_EN、GPIO12 = 5V_EN（屏与外设）、GPIO44 = 12V_EN、GPIO45 = 5VOUT_EN、GPIO14 与 GPIO46 是 485。U0022 的 VIN 直接取自 12V 母线，不经过 12V_EN，所以 U 盘只要拉 GPIO58。
- 拔盘前尽量先 `fatfs.unmount`，直接拔不会损坏代码逻辑（会走掉线分支自动卸载），但正在写入时硬拔有丢数据和文件系统损坏的风险。
- 本 demo 只做 U 盘存在性与读写通路的验证，不做测速；要测吞吐请用大文件读写计时，不要用这个每秒一轮的小文件循环。
