## 2. 项目背景

Air8201G 是 Air8201 系列中的功能扩展型定位/近场通信产品，基于 Air780EGH 模组，面向整机出厂默认软件场景。默认出厂软件需要在设备首次烧录后提供稳定的联网、诊断、升级、传感器采集、蓝牙通信和 AirCloud 数据上传能力，用于整机出厂验证、功能演示、产测联调和后续项目二次开发基线。

本项目不以单一 demo 为目标，而是将 Air8201G 常用出厂能力组合为一个模块化工程，默认以 4G 联网为主链路，保留 Air8201G 支持 SPI 外挂 CH390H 以太网卡和多网卡优先级的扩展空间。

## 4. 软件目标

### 4.1 总体目标

构建 Air8201G 默认出厂软件工程，实现设备开机后自动完成基础初始化、4G 联网、异常诊断配置、远程升级准备、传感器状态采集、蓝牙初始化、AirCloud 连接与数据上传，并通过日志输出关键状态，便于出厂验证和问题定位。

### 4.2 交付目标

1. 提供完整、可维护的默认出厂软件工程结构。
2. 主入口仅负责加载模块，业务逻辑全部模块化拆分。
3. 支持 4G 默认联网，并保留 SPI 以太网、多网卡、PC 模拟器网卡切换空间。
4. 支持 errDump 自动上报合宙服务器的默认场景，保留自建 UDP 服务器和手动读取能力的设计入口。
5. 支持整机方案 FOTA 升级流程接入。
6. 支持 G-sensor 震动检测和计步数据采集。
7. 支持气压传感器数据采集。
8. 支持 Air8201G 板载 Air5101 蓝牙能力初始化和 BLE 外围设备通信能力。
9. 支持 AirCloud 设备认证、数据上报、远程控制/下行消息处理、运维日志、文件上传能力设计。
10. 提供可执行的软件测试方案和验收标准。

## 6. 软件总体设计

### 6.1 总体架构

```text
main.lua
  ├── config.lua                 -- 项目配置：版本、云端参数、周期、开关
  ├── netdrv_device.lua           -- 网卡选择入口，默认 4G
  │   └── netdrv/netdrv_4g.lua     -- 4G 网卡
  ├── factory_selftest.lua         -- 出厂自检流程
  ├── diag_errdump.lua             -- errDump 诊断
  ├── fota_app.lua                 -- FOTA 升级
  ├── sensor_gsensor.lua           -- 震动检测与计步
  ├── sensor_baro.lua              -- 气压传感器
  ├── ble_app.lua                  -- 板载 Air5101 BLE
  ├── aircloud_app.lua             -- AirCloud 连接、上报、下行、文件上传
  ├── data_model.lua               -- 上报数据组包
  └── status_led.lua               -- 可选：状态指示
```

### 6.2 模块职责

| 模块 | 职责 |
| --- | --- |
| main.lua | LuatOS 应用入口，定义 PROJECT/VERSION，加载功能模块，调用 sys.run。 |
| config.lua | 保存项目级配置，如云端鉴权参数、上报周期、传感器周期、功能开关、版本信息。 |
| netdrv_device.lua | 选择网络适配器，默认加载 4G 网卡；保留 SPI 以太网、多网卡、PC 模拟器配置入口。 |
| factory_selftest.lua | 组织出厂自检流程，收集各模块初始化和运行状态。 |
| diag_errdump.lua | 配置 errDump，支持自动上报到合宙服务器，预留自建 UDP 服务器和手动读取能力。 |
| fota_app.lua | 管理远程升级检查、升级触发、升级状态记录和版本确认。 |
| sensor_gsensor.lua | 完成 G-sensor 初始化、震动事件检测、计步数据读取和状态上报。 |
| sensor_baro.lua | 完成气压传感器初始化、周期采样、异常处理和数据上报。 |
| ble_app.lua | 初始化 Air8201G 板载 Air5101 蓝牙，维护 BLE 广播、连接和数据交互状态。 |
| aircloud_app.lua | 使用 excloud 扩展库接入 AirCloud，处理认证、心跳、上报、下行、运维日志和文件上传。 |
| data_model.lua | 统一组装 AirCloud 上报载荷，屏蔽各业务模块的数据结构差异。 |
| status_led.lua | 可选模块，用于展示联网、云端、异常、升级等状态。 |

### 6.3 运行流程

```text
设备上电
  ↓
LuatOS 启动 main.lua
  ↓
加载 config 与基础模块
  ↓
初始化 4G 网卡
  ↓
等待 IP_READY
  ↓
并行启动：errDump / FOTA / 传感器 / BLE / AirCloud / 自检
  ↓
周期采集传感器与设备状态
  ↓
组包上传 AirCloud
  ↓
处理云端下行、升级触发、异常诊断
  ↓
持续运行，网络断开后等待恢复并自动重连云端
```

### 6.4 系统消息设计

| 消息 | 方向 | 说明 |
| --- | --- | --- |
| IP_READY | netdrv → 业务模块 | 某种网卡已经获取 IP，业务模块可启动联网操作。 |
| IP_LOSE | netdrv → 业务模块 | 网卡掉线，AirCloud、FOTA 等联网业务进入等待恢复状态。 |
| FACTORY_SELFTEST_DONE | selftest → 全局 | 出厂自检完成，携带各子项结果。 |
| SENSOR_DATA_UPDATE | sensor → data_model | 传感器数据更新。 |
| AIRCLOUD_READY | aircloud → 全局 | AirCloud 已连接并认证成功。 |
| AIRCLOUD_DOWNLINK | aircloud → 业务模块 | 收到云端下行控制或配置更新。 |
| FOTA_STATE_UPDATE | fota → 全局 | 升级状态变化。 |
| DIAG_EVENT | errDump → data_model | 诊断状态或异常事件。 |

## 7. 软件详细设计

### 7.1 4G 网卡上网

#### 7.1.1 设计依据

Air8201G demo 中的 HTTP、NTP、WebSocket、errDump、AirCloud 等工程均使用 `netdrv_device.lua` 管理网卡，并提供 `netdrv_4g`、`netdrv_eth_spi`、`netdrv_multiple`、`netdrv_pc` 等网卡方案。Air8201G 默认出厂软件以 4G 网卡为默认联网方式。

#### 7.1.2 默认策略

1. 默认加载单 4G 网卡。
2. 插入可上网 SIM 卡并安装 4G 天线后，设备开机自动联网。
3. 监听 IP_READY 和 IP_LOSE 消息。
4. IP_READY 后启动 NTP、AirCloud、FOTA 等联网业务。
5. IP_LOSE 后暂停联网业务发送，等待网络恢复。

#### 7.1.3 扩展策略

Air8201G 引出了 SPI 接口，可通过 SPI 外挂 CH390H 以太网卡，因此工程结构保留以下网卡切换空间：

- 单 4G 网卡：`netdrv_4g`
- SPI 以太网卡：`netdrv_eth_spi`
- 多网卡优先级：`netdrv_multiple`
- PC 模拟器网卡：`netdrv_pc`

默认出厂版本启用 `netdrv_4g`，其他网卡作为二次开发或专项测试能力保留。

### 7.2 errDump 诊断

#### 7.2.1 设计依据

官方 API 索引中，errDump 属于 LuatOS 系统内核核心库，用于远程诊断上报。Air8201G errDump demo 说明中提供以下能力：

1. 自动上报异常日志到 iot 平台。
2. 自动上报异常日志到自建 UDP 服务器。
3. 手动读取异常日志并通过 TCP 传输。

Air8201G 未做 UART 异常日志读取演示，因此默认出厂软件不依赖 UART 读取异常日志。

#### 7.2.2 默认策略

1. 默认启用自动上报到合宙服务器。
2. 自建 UDP 服务器上报和手动读取作为配置项保留。
3. 自动上报和手动读取互斥，不同时启用。
4. 异常上报状态纳入出厂自检和 AirCloud 运维状态。

#### 7.2.3 验收点

- 正常运行时，errDump 模块初始化成功。
- 构造脚本异常后，异常信息进入配置的上报路径。
- Luatools 日志中可看到 errDump 初始化和上报状态。

### 7.3 FOTA 远程升级

#### 7.3.1 设计依据

Air8201 fota demo 说明中明确：Air8201H 基于 Air780EHM，Air8201G 基于 Air780EGH，两款模组均属于 Air780EHM_Air780EHV_Air780EGH 系列，fota 功能与用法一致，可复用该系列 demo。官方文档中 fota 为 LuatOS 系统底层固件升级模块，支持从数据流或文件系统读取升级包进行升级，并支持灵活存储配置。

#### 7.3.2 默认策略

1. 项目固定维护 PROJECT 和 VERSION。
2. 出厂版本默认具备 FOTA 入口，但是否主动检查升级由配置决定。
3. 升级参数支持合宙 iot.openluat.com 平台或客户自建平台方案。
4. 升级状态写入日志，并纳入 AirCloud 运维数据。
5. 升级成功后重启并输出新版本号。

#### 7.3.3 验收点

- 设备启动日志包含项目名和版本号。
- 平台下发升级后，设备可执行下载、校验、升级和重启流程。
- 升级后 VERSION 变化可在日志和云端状态中确认。

### 7.4 G-sensor 震动检测和计步

#### 7.4.1 设计依据

Air8201G 官方资料显示支持 G-sensor 计步能力。Air8201G gsensor demo 说明中明确：Air8201G 基于 Air780EGH，属于 Air780EHM_Air780EHV_Air780EGH 系列，gsensor 功能与用法可复用该系列 demo。

#### 7.4.2 默认策略

1. 开机初始化 G-sensor。
2. 支持震动/运动事件检测。
3. 支持计步数据读取。
4. 将震动状态、步数、更新时间写入 data_model。
5. 出厂自检中加入 G-sensor 初始化和动态变化检测项。

#### 7.4.3 验收点

- 静止状态下，计步值稳定或低频变化。
- 震动整机后，震动事件或运动状态有日志输出。
- 步行动作后，计步值发生合理变化。
- AirCloud 上报数据中包含 G-sensor 相关字段。

### 7.5 气压传感器

#### 7.5.1 设计依据

Air8201G 系列产品简介中显示 Air8201G 支持气压传感器，且核心特性中包含气压传感器能力。

#### 7.5.2 默认策略

1. 开机初始化气压传感器模块。
2. 周期读取气压数据。
3. 将气压数据写入 data_model，并周期上报 AirCloud。
4. 传感器初始化失败或读取失败时记录日志，出厂自检标记该项失败。
5. 数据字段保留传感器原始值与工程换算值扩展空间。

#### 7.5.3 验收点

- 开机后气压传感器初始化成功。
- 周期日志中可看到气压数据。
- AirCloud 上报数据包含气压字段。
- 传感器异常时，日志中有明确失败原因，自检结果可体现异常项。

### 7.6 蓝牙功能

#### 7.6.1 设计依据

Air8201 BLE demo 说明中明确：Air8201G 基于 Air780EGH，已板载蓝牙，板载 Air5101 通过 UART2 连接，无需外挂蓝牙模块；Air8201G 需要在复用 demo 基础上调用 `exril_5101.config_uart(2)` 将 uart_id 设置为 2。

#### 7.6.2 默认策略

1. 默认按 Air8201G 板载 Air5101 方案初始化蓝牙。
2. 蓝牙 UART 使用 UART2。
3. 支持 BLE 外围设备模式，用于出厂连接验证。
4. 蓝牙初始化状态、连接状态、收发统计写入 data_model。
5. 蓝牙配置参数集中在 config.lua 或 ble_app.lua 顶部维护。

#### 7.6.3 验收点

- 开机后蓝牙模块初始化成功。
- 手机或 BLE 测试工具可扫描到设备。
- 连接后可完成基础数据交互。
- AirCloud 上报数据包含蓝牙状态。

### 7.7 AirCloud 数据上传

#### 7.7.1 设计依据

Air8201G AirCloud demo 说明中明确：AirCloud 是 LuatOS 物联网设备云服务通信协议，提供设备连接、数据上报、远程控制和文件上传等核心功能；excloud 扩展库是 AirCloud 协议实现，可快速接入云服务平台。Air8201G demo 演示设备连接与认证、数据上报与接收、运维日志管理、文件上传功能、心跳保活机制。

Air8201G socket 长连接 demo 中也包含 `aircloud_data.lua`，用于定时产生符合 AirCloud 格式的数据并发送给服务器。

#### 7.7.2 默认策略

1. 4G 网络 IP_READY 后启动 AirCloud 连接。
2. 通过配置项维护 excloud.setup 所需参数。
3. 默认周期上报设备状态、网络状态、传感器数据、蓝牙状态、升级状态和诊断状态。
4. 支持云端下行控制，用于触发状态查询、配置更新、传感器即时采样、FOTA 检查等动作。
5. 支持运维日志和文件上传能力，作为出厂调试和客户交付后的远程运维基础。

#### 7.7.3 上报数据建议

| 字段分类 | 字段示例 | 说明 |
| --- | --- | --- |
| 设备信息 | imei、版本号、开机时长 | 标识设备和软件版本。 |
| 网络状态 | 网卡类型、IP 状态、信号状态 | 判断设备联网质量。 |
| G-sensor | 震动状态、步数 | 验证运动检测能力。 |
| 气压 | 气压值、采样时间 | 验证气压传感器能力。 |
| 蓝牙 | 初始化状态、连接状态、收发统计 | 验证 BLE 能力。 |
| FOTA | 当前版本、升级状态 | 远程升级运维。 |
| errDump | 诊断状态、最近异常时间 | 远程异常定位。 |
| 自检 | 自检总结果、失败项列表 | 出厂验证闭环。 |

#### 7.7.4 验收点

- 修改 excloud.setup 参数后，设备可连接 AirCloud。
- 设备周期上报结构化数据。
- 云端可下发控制或配置，设备可处理并输出日志。
- 文件上传和运维日志能力可按 demo 流程验证。

## 10. 风险与约束

| 风险/约束 | 影响 | 处理策略 |
| --- | --- | --- |
| AirCloud 参数未配置 | 设备不能完成云端认证 | 出厂默认使用占位配置，量产前替换为正式参数。 |
| SIM 卡或天线异常 | 4G 联网失败，AirCloud/FOTA/errDump 自动上传受影响 | 自检中明确输出网络失败项。 |
| 气压传感器硬件异常 | 气压数据不可用 | 传感器模块独立失败，不阻塞其他功能。 |
| 蓝牙 UART 配置错误 | BLE 初始化失败 | Air8201G 固定按 UART2 初始化板载 Air5101。 |
| FOTA 包版本策略错误 | 升级失败或版本不符合预期 | 版本号、升级包、平台配置需在发布前做专项验证。 |
| errDump 模式冲突 | 日志读取/上报行为异常 | 自动上报和手动读取互斥配置。 |

## 12. 结论

Air8201G 默认出厂软件项目以 4G 联网为基础，组合 errDump、FOTA、G-sensor、气压传感器、蓝牙和 AirCloud 能力，形成面向整机出厂、演示验证和二次开发的统一软件基线。工程实现时应严格采用模块化结构，保持 main.lua 简洁，将网络、诊断、升级、传感器、蓝牙、云端和自检逻辑拆分为独立模块，确保出厂验证可追踪、问题定位可闭环、后续客户项目可快速扩展。
