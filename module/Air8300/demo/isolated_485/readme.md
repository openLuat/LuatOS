## 演示模块概述

1、main.lua：主程序入口；

2、rs485_reply.lua：隔离 485 串口应答应用模块（管脚复用、串口初始化、数据接收与应答）；

## 演示功能概述

本 demo 演示的核心功能为：

1、将 Air8300 的隔离 485 接口（UART1）配置为串口应答模式

2、串口板（USB 转 485）发送数据给工控板，工控板收到一帧后回复固定内容 `Air8300 OK`

注意事项：

1、该示例程序不依赖扩展库，使用内核固件自带的核心库即可

2、串口接收回调中不能调用 sys.wait，所以回调只负责缓存数据并重启帧间隔定时器；
   总线静默 100ms 认为一帧接收结束，再由主任务执行回复

3、回复内容由 main.lua 中的 `reply_data` 决定，波特率由 `baud_rate` 决定，
   修改后需要与串口板保持一致

4、调试接线时可以把 main.lua 中的 `heartbeat_enable` 置为 true，
   工控板会每 3 秒主动发送一次 `PING`，用于单独验证"板子 → 电脑"方向是否正常

## 演示硬件环境

1、Air8300 双网口双 485 工控板一块

2、TYPE-C USB 数据线一根

3、USB 转 485 串口板一块

4、双绞线或杜邦线若干

接线（使用隔离 485 接口）：

| 工控板     | 串口板 |
| ---------- | ------ |
| A          | A      |
| B          | B      |
| 隔离侧 GND | GND    |

板上开关：

1、3.3V/5V 供电开关：拨到 5V，为隔离 485 逻辑侧供电

2、AGND/SEL/VISO 开关：拨至 AGND，总线侧电平为 3.3V

## 常见问题

1、串口初始化成功，但收不到任何数据

- 先确认 main.lua 中的 `pins.setup(pwr_pin, "GPIO29")` 和 `gpio.setup(pwr_gpio, 1)` 已执行，
  485 芯片供电脚（GPIO29 / 物理 PIN18）没有拉高时收发器不工作，日志里不会有任何接收记录

2、能收到数据，但回复不出去

- 检查方向脚是否已重映射：`pins.setup(28, "GPIO37")`，
  PIN28 上电默认是 LCD 功能，不重映射时方向脚不受控

3、供电和管脚都正常，仍然收不到数据

- 检查 A/B 是否接反（可以先对调试试）
- 检查是否与串口板共地，隔离口要使用隔离侧的 GND
- 检查板上 3.3V/5V 供电开关是否打开
