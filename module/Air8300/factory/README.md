# 边缘采集网关（Air8300 演示样板）

基于 **Air8300（Air8000W）双网口双 485 工控板**的工业数据采集与远程控制网关演示工程，打通
「设备采集 → 上云 → 展示/控制 → 远程运维 → FOTA 升级」端到端全链路。

核心卖点：**多网融合（以太网 > WiFi > 4G 逐级切换）** 与 **双 485 工业总线接入（采集 + 控制）**。

- 项目名（PROJECT）：`Air8300_EdgeGateway`
- 项目版本（VERSION）：`001.999.001`
- 云服务：合宙 AirCloud（excloud 扩展库 / TCP，iot.luatos.com）

## 一、功能模块介绍

1、main.lua：主程序入口，定义 PROJECT / VERSION 并按顺序加载各功能模块，仅含 require 与 sys.run()；

2、net_config.lua：网络配置管理，管理网口选择（eth1/eth2/none）、IP 获取方式（dhcp/static）、网卡优先级、WiFi STA 账号密码、时区，使用 fskv 持久化；

3、time_sync.lua：NTP 时间同步（全工程唯一授时点），等待网络就绪后授时；

4、net_drv.lua：多网融合驱动，统一管理以太网（CH390H）+ WiFi STA + 4G 的接入与优先级切换；

5、comm_core.lua：Modbus RTU 主站公共封装层，提供建站、读寄存器、写线圈、命令帧构建、CRC16-Modbus 校验、总线互斥与总线静默期；

6、temp_sensor.lua：温湿度采集，非隔离 485（UART3）以 Modbus RTU 主站周期读取温湿度变送器（从站 1）；

7、relay_ctrl.lua：继电器控制，隔离 485（UART1）以 Modbus RTU 主站控制 4 路继电器模块（从站 1），支持单路开/关/翻转、全开/全关、状态回读；

8、net_watchdog.lua：网络业务看门狗，多源喂狗（云端收发成功 / 网卡就绪），超时兜底判定网卡存活后才软件重启；

9、airlbs_app.lua：airlbs 基站定位，每 15 分钟请求一次经纬度（收费服务，需替换项目凭证）；

10、aircloud_data.lua：AirCloud 数据上报与命令处理，周期组包上报设备数据、解析平台下行命令并应答，内置云端链路自愈机制；

11、fota_app.lua：libfota3 远程升级封装，开机网络就绪检查一次 + 每 12 小时检查一次；

12、app_main.lua：业务编排层，汇总温湿度 / 继电器 / 定位等设备状态并提供查询接口；

13、libfota3.lua：FOTA 升级扩展库，随工程分发；

14、test_relay.lua：继电器本地测试脚本（默认在 main.lua 中不加载，需要时取消注释即可启用）。

## 二、演示功能概述

1、多网融合（F-001）

- 同时支持 4G（SIM 卡，演示必备兜底链路）、WiFi STA、双以太网（CH390H）；
- 链路优先级 **以太网 > WiFi > 4G**，由 exnetif 统一管理，高优先级网卡就绪即优先使用，断链自动降级、恢复后自动切回；
- 以太网采用单网口供网（一次只启用一个网口，由 `eth_enable` 选择 eth1/eth2/none），IP 获取方式支持 DHCP（默认，插上路由器即可上网）与静态两种；
- WiFi 仅保留 STA 上网模式。

2、485 采集（F-002）

- 非隔离 485（UART3）以 Modbus RTU 主站模式，9600 8N1，每 **5 秒**读取温湿度变送器（从站 1）保持寄存器 0x001E / 0x001F；
- 采集值做合理区间校验（温度 -40~125℃、湿度 0~100%RH），越界即丢弃并告警；寄存器缺失不更新缓存，不再用 0 覆盖。

3、485 控制（F-003）

- 隔离 485（UART1）以 Modbus RTU 主站模式控制 4 路继电器模块（从站 1）；
- 通道编号 **0~3**（与 Modbus 线圈地址 0x0000~0x0003 一一对应），**风扇 = 通道 0、LED = 通道 1**；
- 支持单路开/关/翻转（功能码 0x05）、全开/全关（功能码 0x0F）、状态回读（功能码 0x01）；
- 继电器路数只由 `relay_ctrl.CH_COUNT` 一处决定，换 8 路模块只需改这一个常量。

4、云服务上行（F-004）

- AirCloud 周期上报（每 **3 分钟**）：温度、湿度、4G 信号、SIM ICCID、CPU 温度、VBAT 电压、经纬度、继电器状态；
- 组包后统一做**字段有效性过滤**：空值字段（如未定位时的经纬度、SIM 未就绪时的 ICCID）会被剔除，避免单个空字段导致整包上报失败；
- 上报失败后 30 秒快速重试一次，不必干等一个完整上报周期。

5、云服务下行（F-005）

- 平台下发 JSON 命令，设备解析执行后以 `CONTROL_RESPONSE(20)` 应答回传；
- 同时兼容平台「控制命令」`CONTROL_COMMAND(19)` 与「透传消息」`IRTU_DOWN(21)` 两种下行方式；
- 命令执行放在独立协程任务中（socket 回调上下文不可阻塞等待），执行后自动回读继电器状态并广播。

6、运维日志（F-006）

- 启用 AirCloud 运维日志（4 个文件块、追加写入），关键业务事件（上电、连网、认证、采集、命令、重建、FOTA 等）写入云端日志，便于远程运维诊断；
- 重建类日志做 60 秒节流，避免频繁重建反复写 flash、消耗平台消息额度。

7、FOTA 远程升级（F-007）

- 方案：libfota3 扩展库 + 合宙升级服务器；
- 触发逻辑：开机网络就绪后检查一次 + 每 12 小时检查一次。

8、定位服务（F-008）

- airlbs 基站定位，每 15 分钟请求一次经纬度并上报。

9、网络看门狗（F-009）

- 多源喂狗（云端收发成功、网卡 IP_READY 均重置计时），喂狗超时 10 分钟；
- 超时后兜底判定默认网卡是否仍持有 IP：持有则判定网络环境正常、继续运行不重启；仅「网卡无 IP 且长期无喂狗」才软件重启。

## 三、演示硬件环境

1、Air8300 工控板（Air8000W）一块 + 可上网的 SIM 卡一张 + 4G 天线一根 + WiFi 天线一根 + 网线一根：

- SIM 卡插入工控板的 SIM 卡槽；
- 天线装到工控板上；
- 网线一端插入工控板网口，另一端连接可以上外网的路由器网口。

2、485 外设：

| 外设 | 接入口 | 从站地址 | 串口参数 | 说明 |
|------|--------|----------|----------|------|
| 温湿度变送器 | 非隔离 485（UART3） | 01 | 9600 8N1 | 读保持寄存器 0x001E / 0x001F |
| 4 路继电器模块 | 隔离 485（UART1） | 01 | 9600 8N1 | 通道 0~3；风扇 = 通道 0、LED = 通道 1 |

3、TYPE-C USB 数据线一根 + USB 转串口数据线一根，Air8300 工控板和数据线的硬件接线方式为：

- Air8300 工控板通过 TYPE-C USB 口供电；
- TYPE-C USB 数据线直接插到工控板的 TYPE-C USB 座子，另一端连接电脑 USB 口。

4、供电与接线要点：

- 板卡本体：Type-C 供电；
- 485 外设 + 负载：共用一路 **12V 5A 适配器**（温湿度变送器、继电器模块、经继电器触点的负载统一供电，GND 共地）；
- 负载串接在继电器 COM-NO 之间；
- 固定供电演示场景，无需低功耗设计。

5、板内关键引脚（工程内已按此配置，换板需同步核对）：

| 用途 | 说明 |
|------|------|
| 网口1 | SPI 片选 21、供电使能 16 |
| 网口2 | SPI 片选 20、供电使能 17 |
| RS485 芯片电源 | GPIO29（统一由 net_drv 初始化） |
| 非隔离 485 | UART3，方向脚 GPIO36 |

## 五、平台侧配置

### 5.1 数据点登记

| 平台数据点 | 编号 | 数据类型 | 来源 | 是否需要新建 |
|-----------|------|----------|------|-------------|
| 温度 | 256 | FLOAT | temp_sensor | 已有标准字段 |
| 湿度 | 257 | FLOAT | temp_sensor | 已有标准字段 |
| CPU 温度 | 263 | INTEGER | adc.CH_CPU | 已有标准字段 |
| GNSS 经度 | 512 | ASCII | airlbs | 已有标准字段 |
| GNSS 纬度 | 513 | ASCII | airlbs | 已有标准字段 |
| 4G 信号强度 | 782 | INTEGER | mobile.csq() | 已有标准字段 |
| SIM ICCID | 783 | ASCII | mobile.iccid() | 已有标准字段 |
| VBAT 电压 | 799 | INTEGER | adc.CH_VBAT | 已有标准字段 |
| 继电器状态 | 268 | ASCII | relay_ctrl | 已有标准字段 |

继电器状态说明：

- 使用自定义数据点 `268`（属协议「传感采集类」区间 256~511 内的空闲编号），**需在 AirCloud 平台项目下新建**：名称「继电器状态」、编号 `268`、类型「字符串」；
- 值为**英文逗号分隔**的状态串，`1` = 吸合、`0` = 断开，从左到右依次为通道 0、通道 1 ……；4 路形如 `1,1,0,0`，8 路自动变长为 `1,1,0,0,0,0,0,0`；
- 字段个数天然等于路数，扩展 8/16 路时格式不变、平台登记一次即长期有效。

### 5.2 下行命令

平台向设备下发 JSON 文本（可走「控制命令」或「透传消息」），格式：`{"type":"<命令>","channel":<通道号>}`

| 命令 | 参数 | 说明 |
|------|------|------|
| relay_open | channel（0~3，默认 0） | 打开指定通道 |
| relay_close | channel（0~3，默认 0） | 关闭指定通道 |
| relay_toggle | channel（0~3，默认 0） | 翻转指定通道 |
| relay_all_open | - | 全开 4 路 |
| relay_all_close | - | 全关 4 路 |
| relay_read | - | 回读继电器状态 |
| read_temp / read_humi | - | 读取当前温度 / 湿度 |
| read_vbat / read_cpu | - | 读取 VBAT 电压 / CPU 温度 |
| read_csq / read_iccid | - | 读取 4G 信号 / SIM ICCID |
| read_time | - | 读取设备当前时间戳 |

下发格式：{"type":"relay_open","channel":0}，{"type":"read_temp"} 

应答格式：`CONTROL_RESPONSE(20)`，ASCII JSON，例如 `{"relay":[1,1,0,0],"result":"success","channel":0}`。

## 六、演示核心步骤

1、搭建好硬件环境；

2、按需修改 net_config.lua 中的网络配置（默认已可用）：

- `eth_enable`：启用的网口，可选 `"eth1"`（cs=21，默认）/ `"eth2"`（cs=20）/ `"none"`（不供网）；
- `eth_mode`：IP 获取方式，`"dhcp"`（默认）/ `"static"`；
- `wifi_ssid` / `wifi_pwd`：WiFi STA 账号密码；
- `priority`：网卡优先级，默认 `{"eth1","wifi","4g"}`（高 → 低）；
- `timezone`：时区，默认 `UTC+8`。

3、按需修改第三方服务凭证：

- aircloud_data.lua 中的 AirCloud 项目 key；
- airlbs_app.lua 中的 airlbs `project_id` / `project_key`（收费服务，demo 中为占位凭证，量产前必须替换）；
- fota_app.lua 中的 libfota3 `project_key`。

4、用 Luatools 下载代码到工控板并运行，开机后在 Luatools 上查看日志，确认以下关键日志依次出现：

```
I/user.main Air8300_EdgeGateway 001.999.001
I/user.excloud excloud.setup 初始化成功
I/user.excloud excloud.open 服务已开启
I/user.aircloud_data 连接成功
I/user.aircloud_data 认证成功
I/user.aircloud_data 云端心跳已启动, 间隔 120 秒
I/user.aircloud_data 上报成功
```

5、在 AirCloud 平台查看设备数据：设备应显示**在线**，温湿度 / 信号 / ICCID / CPU / 电压 / 经纬度 / 继电器状态按 3 分钟周期刷新；

6、在 AirCloud 平台下发控制命令（例如「控制命令」填入 `{"type":"relay_open","channel":0}`）：

- 设备日志出现 `收到命令: relay_open` → `命令执行完成, 应答: {...}`；
- 继电器通道 0 对应触点吸合（风扇启动），平台「继电器状态」对应位置由 `0` 变为 `1`；

7、观察多网融合：插上网线后设备自动切到以太网（默认网卡变化），拔出网线后自动降级回 WiFi / 4G，云端链路能自动重建并恢复在线；

8、观察 FOTA：设备开机联网后自动检查一次版本，之后每 12 小时检查一次；在合宙升级服务器上传新版本脚本即可触发升级。
