# motor_hmi — 电机 HMI（Air8603 / plcui / Modbus RTU）

> **看门狗提醒**
>
> 860X 板载合宙 Air153D 看门狗芯片，未喂狗约 12 分钟会重启。
> 本工程已在 `main.lua` 中调用 `exair153x_wdt`，固件若不带该库会打印警告。

基于 **plcui** 核心库（Air1603 104 号固件起提供）实现的变频器操作面板：
布局写 XML、观感靠切图、逻辑在 Lua，三者分离。
**注意：plcui 与 airui 不能同时使用**，本工程已完全移除 airui。

## 界面

三页，1024×600：

| 页面 | 内容 |
|---|---|
| 监控 | 变频器→电机链路图（小窗实时显示设定频率 F）、状态胶囊、四行状态、76 号大字实际频率；右侧启动/停止/急停 + 两个复位 |
| 报警 | 9 行表格（表头 + 8 条记录），清空 / 复位 |
| 设置 | 启动间隔延时，点输入框弹数字键盘，写入掉电存储 |

设计稿在 `design/index.html`，**是布局的唯一事实来源**；`code/main.xml` 的坐标由它导出。

## 变频器侧准备（缺一不可）

台达 VFD-M（v3.09 以上）：

| 参数 | 值 | 说明 |
|---|---|---|
| P88 | 01 | 站号，须与 `conf.motors[].station` 一致 |
| P89 | 01 | 9600 bps |
| P92 | **06** | Modbus RTU 8,N,1 |
| P157 | 01 | Modbus 协议 |
| P00 | 00 | 频率由面板数字设定（P14） |
| P14 | 50.00 | 固定转速 |
| P01 | **03** | 运转指令由 RS-485 |
| P91 | **2.0** | 通讯超时 2s —— 断线保护 |

> P91 是断线兜底：2 秒收不到合法帧就报 `Cu` 并停车。
> HMI 以 500ms 轮询，天然满足；HMI 死机或线缆脱落时变频器自行停车。
> **手动单帧调试期间**两条之间超过 2 秒会触发 `Cu`，可临时设 P91=0.0，正式运行改回 2.0。

## 寄存器

**写（06）**：`2000H` 运转命令（`0x0012` 正转 / `0x0001` 停止）、`2002H` 复位（写 `2`）

**读（03）**：一帧读 5 个寄存器 `2100H`~`2104H`

| 地址 | 内容 | 缩放 |
|---|---|---|
| `2100H` | 故障码 | — |
| `2101H` | 状态位 | bit12 运行 / bit3 正转 / bit4 反转 |
| `2102H` | 频率指令 | ÷100 = Hz |
| `2103H` | 输出频率 | ÷100 = Hz |
| `2104H` | 输出电流 | ÷10 = A（本机型测不到小电流） |

`2108H`（转速）实测恒为 0，本固件未实现，界面不使用。

## 改界面怎么改

**不要直接改 `main.xml` 的坐标**，改 `design/index.html`，再按 HTML 里的 x/y/w/h 同步到 XML。
两边不一致时，以 HTML 为准。

几个 plcui 的硬约束，改的时候容易踩：

1. **`on-click` 必须配 `clickable="true"`**，否则点了没反应；
2. **XML 里每个 `on-*` 都必须在 `ui.handlers` 里有同名函数**，缺一个 `plcui.load` 直接失败（`E_HANDLER`）；
3. **属性名只有 `font_size` 用下划线**，其余一律连字符（`max-length`、`col-widths`），写错报 `Unknown attribute`；
4. **label 的 h 必须等于 `font_size + 3`**，y 按 `目标y + (目标h - 行高)/2` 反算，否则文字不垂直居中；
5. **切图文件名 <23 字节、纯 ASCII、全工程不重名**（打包后全部平铺到 `/luadb`）。

## 切图是怎么来的

`design/assets/*.svg` → 无头浏览器按精确尺寸截图（透明背景）→ `code/*.png`。

真实按钮（启动/停止/急停）烘 2 倍图再缩显，边缘更平滑；扁平按钮烘 1 倍图，保证 1px 边框不发虚。

**状态类元素靠切图表达颜色**，因为 plcui 的 label 只能 `set_text`、容器改不了背景：

| 元素 | 做法 |
|---|---|
| 在线指示灯 | `dot_g.png` / `dot_r.png` 两张，`set_src` 切换 |
| 状态胶囊 | `pill_ok` / `pill_off` / `pill_err` 三张，文字已烘进图里 |
| 在线/故障/通讯文字 | 绿色、红色两个 label 叠在同一坐标，`set_hidden` 显示其一 |

## 五个容易踩的坑

1. **事件回调里不能做阻塞串口操作。** 回调不在协程里，`sys.waitUntil` 会抛
   `attempt to yield from outside a coroutine`。所有涉总线的动作都经 `ui.defer()` 丢进独立 task。
2. **切页后旧句柄全部失效**（`E_OBJECT_CLOSED`）。所以不缓存句柄，每次重新 `find`；切页后延时 30ms 再访问新页组件。
3. **`require` 的写法有两条硬规矩。**
   一是后面不能跟两个字符串——`require("x").y()` 会被贪婪匹配成 `x").y`，报"缺少 xxx.lua"；
   二是**必须写成字面量** `require "x"`。合并工具靠静态扫描 `require` 后面那个字符串决定打包哪些 `.lua`，
   把模块名藏进变量（`require(v)`）会让文件根本不打进脚本区，运行时报 `module not found`。
   `exair153x_wdt` 就踩过这个坑，它现在已经作为脚本文件放在 `code/` 下。
4. **`plcui.init` 与 `display.init` 可能冲突。** 本工程先调 `board.init()`（含 `display.init`）再 `plcui.init`；
   若日志报 `E_DISPLAY_BUSY`，把 `board.init()` 里的 `display_on()` 去掉，让 plcui 自己接管屏幕。
5. **模拟故障按钮是调试用的。** `ui.lua` 的 `on_sim_fault` + `app_data.force_fault` 投产前应连同 XML 里的按钮一起删掉。

## 排障

| 现象 | 排查方向 |
|---|---|
| 屏幕全黑 | `plcui.load` 是否成功（看 `E_SCHEMA` / `E_RESOURCE` / `E_HANDLER`）；背光是否点亮 |
| 点按钮无反应 | 触摸未绑定（`device_bind_touch` 必须在 `plcui.init` 之后）；`clickable="true"` 是否漏写 |
| 界面不刷新 | 采集任务是否在跑；`ui.start()` 的刷新循环是否起来 |
| 顶栏一直离线 | 站号不符；P92 不是 06；A/B 接反；485 芯片未供电（GPIO64） |
| 启动后马上停，面板显示 Cu | P91 太短而轮询没跑起来，或 HMI 卡死 |
| 电流一直 0.0 | 已知现象：1.5kW 驱动器测不到 0.12kW 电机的电流 |
| 中文显示成方框 | 字库缺字形。已验证不支持：`——`（U+2014）、全角空格（U+3000）、`●`（U+25CF） |
| 约 12 分钟重启一次 | 看门狗未喂，检查 `exair153x_wdt` |

## 急停的定位

**软急停不具备安全等级。** RS485 有几十毫秒延迟，HMI 死机或断线时软急停失效。

真正的安全急停必须用**硬件常闭触点切断变频器前端接触器**。
本工程保留软急停是为了操作便利（一键停全部），不能替代硬件回路。
软件侧另有一道兜底：变频器 P91 = 2s，通讯一断它自己停车。
