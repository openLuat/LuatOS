# motor_hmi — 电机 HMI（Air8603 / 10 寸 1024×600）

> **看门狗提醒**
>
> 860X 板载合宙 Air153D 看门狗芯片，未喂狗约 12 分钟会重启。
> 本工程已在 `main.lua` 中调用 `exair153x_wdt`，固件若不带该库会打印警告，需自行确认。

通过 RS485 走 **Modbus RTU** 控制/监视台达 VFD-M 系列变频器，
界面提供启停、状态显示、顺序启动间隔设置与故障报警。

## 对应需求

| 需求 | 实现位置 |
|---|---|
| 1. 启动 / 停止 / 急停（软按钮） | `ui_dash.lua` 右侧控制面板 → `app_seq.lua` |
| 2. 画面显示一台电机运行状态 | `ui_dash.lua` 左侧状态卡 |
| 3. 触摸屏直接输入启动间隔延时 | `ui_settings.lua`（数字键盘 + `airui.textarea`） |
| 4. 故障报警弹窗 + 记录故障位 | `app_alarm.lua` + `ui_alarm.lua` |

## 变频器侧准备（缺一不可）

台达 VFD-M（固件 v3.09 以上），按顺序设：

| 参数 | 值 | 说明 |
|---|---|---|
| P88 | 01 | RS-485 站号，必须与 `conf.motors[].station` 一致 |
| P89 | 01 | 9600 bps |
| P92 | **06** | Modbus RTU 8,N,1 |
| P157 | 01 | Modbus 协议 |
| P00 | 00 | 频率由面板数字设定（P14），本 HMI 只管启停 |
| P14 | 50.00 | 固定转速 |
| P01 | **03** | 运转指令由 RS-485 |
| P91 | **2.0** | 通讯超时 2s —— 断线保护 |

### 关于 P91

它是变频器的断线兜底：2 秒收不到任何合法帧就报 `Cu` 并停车。
本 HMI 以 `conf.poll_ms = 500ms` 轮询，天然满足心跳；
HMI 死机或线缆脱落时变频器会自行停车，这是设计上的第二道防线。

**调试注意**：如果用串口助手手动发单帧，两条之间超过 2 秒就会触发 `Cu`。
手动调试期间可把 P91 临时设为 0.0，正式运行必须改回 2.0。

## 寄存器表

### 写入（功能码 06）

| 地址 | 内容 | 值 |
|---|---|---|
| `2000H` | 运转命令 | `0x0012` 正转启动 / `0x0001` 停止 |
| `2002H` | 复位 | Bit1 = 1，即写 `0x0002` |

### 读取（功能码 03）

一帧读 5 个寄存器（`2100H`~`2104H`），一次拿全：

| 地址 | 内容 | 缩放 |
|---|---|---|
| `2100H` | 故障码 | — |
| `2101H` | 状态位 | bit12 运行 / bit3 正转 / bit4 反转 |
| `2102H` | 频率指令 | ÷100 = Hz |
| `2103H` | 输出频率 | ÷100 = Hz |
| `2104H` | 输出电流 | ÷10 = A（本机型测不到小电流，仅参考） |

### 已知失效项

`2108H`（电机转速）实测在 50Hz 运行时仍返回 0，本固件未实现，
**界面不做转速显示**，改显示输出频率。

## 报文参考（可用串口工具核对）

HMI 实际发出的四帧，HEX 发送、HEX 接收：

```
采集  读 2100H~2104H（5 个）   01 03 21 00 00 05 8F F5
启动  写 2000H = 0012          01 06 20 00 00 12 02 07
停止  写 2000H = 0001          01 06 20 00 00 01 43 CA
复位  写 2002H = 0002          01 06 20 02 00 02 A2 0B
```

采集响应示例（故障 13、状态 0x02CA、频率指令 5000、输出 0、电流 0）：

```
01 03 0A 00 0D 02 CA 13 88 00 00 00 00 <CRC>
```

解析：`00 0D` = 13（Cu）、`02 CA` = 状态字、`13 88` = 5000（50.00Hz）。

调试时如需手动发帧，注意两条之间间隔要小于 P91 设定的 2 秒，
否则变频器会先报 `Cu` 停车。

## 常见故障码

| 码 | 含义 | 码 | 含义 |
|---|---|---|---|
| 1 | 过电流 OC | 11 | 减速过流 OCd |
| 2 | 过电压 OU | 13 | 通讯超时 Cu |
| 3 | 过热 OH | 14 | 运行中欠压 Lu |
| 4 | 变频器过载 OL | 16 | 输出缺相 PH2 |
| 5 | **电机过载 OL1** | 17 | 外部中断 bb |
| 6 | 外部异常 EF | 18 | 自学习失败 EA |

5 和 4 被 `conf.overload_codes` 标记为过载类，报警文案会写成「电机过载：…」。

> 说明书第 17 页与第 19 页的故障码编号不一致。实测面板显示 `CU` 时 `2100H` 读到 **13**，
> 与第 17 页一致，本工程按此映射。

## 多电机扩展

当前 `conf.motors` 只有 1 台。加第 2 台只需：

```lua
conf.motors = {
    { key = "m1", name = "1 号电机", station = 1, freq_hz = 50.0 },
    { key = "m2", name = "2 号电机", station = 2, freq_hz = 50.0 },
}
```

再把第 2 台变频器的 P88 设成 2。界面、轮询、顺序启动、报警全部自动适配，无需改代码。

**启动间隔** 在设置页填数字，范围 0~60 秒，掉电保存。
它是「相邻两台之间的间隔」：第 1 台立即启动，第 2 台等 N 秒，第 3 台再等 N 秒。
单台时看不到延时效果，这是正常的。

## 急停的定位

**软急停不具备安全等级。** RS485 有几十毫秒延迟，HMI 死机或断线时软急停失效。

真正的安全急停必须用**硬件常闭触点切断变频器前端接触器**。
本工程保留软急停是为了操作便利（一键停全部），不能替代硬件回路。

软件侧另有一道兜底：变频器 P91 = 2s，通讯一断它自己停车。

## 排障

| 现象 | 排查方向 |
|---|---|
| 顶栏一直显示离线 | 站号不符；P92 不是 06；A/B 接反；485 芯片未供电（GPIO64） |
| 能读不能写 | P01 未设 03；参数被 P76 锁定 |
| 启动后马上停，面板显示 Cu | P91 太短而轮询没跑起来，或 HMI 卡死 |
| 频率显示 0 但状态是运行 | P00 不是 00 或 P14 不是 50.00 |
| 电流一直 0.0 | 已知现象，见上文 |
| 日志出现 `attempt to yield from outside a coroutine` | 在定时器回调或 LVGL 事件回调里做了阻塞串口操作。所有涉总线的动作必须经 `theme.defer`（内部是 `sys.taskInit`，真协程），不能用 `sys.timerStart` |
| 停止偶发无效，日志写「串口忙」 | UI 写命令与 500ms 轮询撞车。`transact` 会自动等总线释放（最多 1.5s）；若仍报此错，说明有事务卡死未释放 busy |
| 约 12 分钟重启一次 | 看门狗未喂，检查 `exair153x_wdt` 是否可用 |

## 烧录注意：require 的写法限制

烧录时的脚本合并工具会**静态扫描 `require` 后面的字符串**来判断要打包哪些文件，
而且匹配是贪婪的——它会取该行 `require` 之后**最后一个引号**之前的内容。

所以下面这种链式写法会直接导致合并失败：

```lua
require("ui_main").show("alarm")
-- 被扫描成 "ui_main\").show(\"alarm" → 报"缺少 ui_main\").show(\"alarm.lua"
```

PC 模拟器不会报错，因为它是运行时解析模块，两者行为不同。

**三条规则：**

1. 不要链式调用 `require(...)` 的返回值，先赋值给局部变量；
2. 一行里 `require` 之后只出现一个字符串；
3. 固件内置库（如 `exair153x_wdt`）的模块名放进变量再 require，
   否则会被当成"缺失的脚本文件"：

```lua
local wdt_lib = "exair153x_wdt"
local wdt = require(wdt_lib)
```

本工程中 `ui_alarm` 跳转到报警页的能力由 `ui_main` 通过 `set_nav()` 反向注册，
就是为了绕开这条限制，同时也消除了模块循环依赖。

## 与 melsec_hmi 的关系

板级部分（`board.lua`、`drv_lcd_rgb.lua`、`drv_tp_gt911.lua`、`ui_theme.lua`）沿用
`melsec_hmi` 的成熟实现，硬件完全相同。

`drv_modbus.lua` 沿用了 `drv_fxlinks.lua` 验证过的平台适配结论：

- 485 方向脚交给 `uart.setup` 的 `pin485` 自动换向，Lua 侧不碰方向脚；
- 收发等待用常驻 10ms 循环定时器，不用 `sys.wait(ms)`——
  后者每次调用都新建/销毁 C 层定时器，在 SDK 的定时器删除窗口里会丢唤醒；
- 平台首次写出的帧在总线上无效，初始化时先发一帧哑请求消耗掉。
