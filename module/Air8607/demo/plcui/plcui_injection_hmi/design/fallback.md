# 降级清单 · 智能注塑车间 1# 产线监控总览

> 参考稿：`工业HMI界面/hmi-prompt-lab/case-06.html`（1400×872）
> 目标：Air8607 / 1024×600 / PLCUI（九种组件白名单）
> 原则：**能做到的一律照资料实现，做不到的显式降级 + 记在这里**，不许静默照抄然后在设备上翻车。

判据只有一条：**这个效果在设备上会不会随数据变。** 不变的烘成 PNG（质感全留在图里，所以下面大半"降级"其实是无损的）；会变的必须是活组件。

## 一、无损降级（视觉一致，只是实现换了）

这些在设备上**看起来和参考稿一样**，区别只在实现路径 —— 网页用 CSS 实时算，设备用像素烘死。

| 原参考效果 | PLCUI 为什么做不到 | 改成了什么 | 影响 |
|---|---|---|---|
| 46 处 `linear-gradient`：金属拉丝、面板斜边、按钮凸起、槽底凹陷 | 九种组件里没有渐变 / 背景图属性，`image` 只吃一张位图 | 整块烘成 PNG（`tools/tiles.py` 49 张瓦片 + 4 张整页底图） | 无。质感本来就是静态的 |
| 19 处 `radial-gradient`：辉光、玻璃高光、指示灯晕 | 同上，且 PLCUI 无 `box-shadow` / `filter` | 一并烘进 PNG | 无 |
| 6 处 `conic-gradient`：仪表金属圈、旋钮刻度盘 | 同上 | 烘图（`gauge` 表盘底图 + `knobsp` 旋钮） | 无 |
| 59 处 `box-shadow`：按钮投影、面板内阴影、指示灯外发光 | 无阴影属性 | 烘图；留白靠瓦片的 `pad` 预留（导出时 `x-pad` 外扩，视觉位置不变） | 无 |
| 9 处 `text-shadow`：数值辉光、数码管泛光 | `label` 无文字发光 | 辉光烘进底图，数字用 `label` 叠在上面 | 数值变化时辉光不跟着变（参考稿里辉光本身也不随数值变，一致） |
| 18 处 `border-radius`：圆角面板、圆形按钮、胶囊页签 | 无圆角属性 | 烘图（圆角在像素里） | 无 |
| `filter: saturate()` 暗态按钮去饱和 | 无滤镜 | 暗态单独出一张瓦片（`btnstart_p` 等） | 无 |
| `font-weight: 700/800` 粗体 | `label` 只有字号 / 颜色，无字重 | 用 MiSans 自带字形 + 提高对比度补偿 | **肉眼略细一点**，可接受 |
| `letter-spacing` 字距 | 无字距属性 | 放弃，靠居中对齐保持观感 | 长标题比参考稿紧 1~2px |

## 二、有损降级（视觉或交互与参考稿不同）

| 原参考效果 | PLCUI 为什么做不到 | 改成了什么 | 影响 |
|---|---|---|---|
| **急停二次确认弹窗**（`.mask` + `.dialog` 模态遮罩） | 九种组件里没有模态 / 弹层；`container` 不能改变层叠顺序，也无法拦截下层点击 | **两级按**：第一次按下进入「待确认」（按钮切 `src-pressed` 态、顶部状态文字变「急停待确认」），**5 秒内再按一次**才真正停机；超时自动解除 | 交互语义一致（防误触），但没有遮罩和文字弹窗。现场培训时要说清"按两下" |
| 报警表的**行内滚动**（`overflow: auto` + 自定义滚动条） | `table` 无滚动属性，行数固定 | 固定 7 行（含表头）；超出部分靠「一键确认」清空后再显示 | 一屏最多看 6 条报警，多于 6 条要确认后翻屏 |
| 趋势曲线下方的**渐变填充区**（`<path fill="url(#grad)">`） | `chart` 只有折线 / 柱状，无面积填充 | 只画折线，网格与刻度全在背景图上 | 曲线的"体积感"弱一些，读数不受影响 |
| 曲线上的**阈值虚线 + 标注气泡** | `chart` 不支持参考线 | 阈值虚线烘进背景图；实时数值用页面右下角的四个统计盒承担 | 阈值线是**固定值**，改阈值要重出底图 |
| **悬停态**（`:hover` 提亮） | 电容触摸屏没有 hover | 取消，只保留 普通 / 按下 / 选中 / 禁用 四态 | 无（触屏本来就没有 hover） |
| 页签上的**红点徽标**（`.tab .badge` 子元素，带数字） | `image` 不能有子组件；位置必须绝对坐标 | 拆成两个组件：`badge`（圆点图）+ `tab_num`（数字 label），未确认数为 0 时一起 `set_hidden(true)` | 位置靠绝对坐标对齐，改页签尺寸要同步改这两处坐标 |
| 管路**流动条纹动画**（CSS `@keyframes` 位移） | 无动画属性；`animimg` 只做整图多帧，且不能只动局部 | 4 帧透明 PNG（`flow_0`..`flow_3`）轮播，200ms 一帧，停机时定格第 0 帧 | 条纹是"跳帧"前进而非平滑位移，8px 步进下肉眼接近连续 |
| 按钮**按下的下沉位移**（`transform: translateY(1px)`） | 无位移属性 | 按下态图里已经把高光/阴影画成凹陷，视觉上有下沉感 | 位置不动，靠光影表达 |
| 表格**斑马纹 + 悬停高亮** | 无 hover | `alternate-color` 保留斑马纹，去掉 hover | 无影响 |
| 表格**已确认行整行置灰**（参考稿用内联 `color:#5a6468`） | `table` 的配色是整表级的（`color` / `alternate-color`），`set_cell` 只写文本，不能逐格改色 | 保留斑马纹，靠「状态」列的 **已确认 / 未确认** 文字区分；行级灰度改用斑马纹 + 文字表达 | 已确认行不置灰，扫视时比参考稿多花一点注意力 |
| 输入框**聚焦高亮边框** | `textarea` 只有静态配色 | 靠软键盘弹出这一动作本身提示"正在输入" | 聚焦态不明显 |
| 顶栏**返回箭头**（`btn_back`） | 与面板内容层叠冲突，且页签已能回总览 | 直接删除 | 少一个入口，功能不缺 |

## 三、按能力边界必须改写的结构

| 参考稿写法 | 改成 | 原因 |
|---|---|---|
| 面板 `.panel` 作为绝对定位容器，子元素坐标相对面板 | 运行时把 `.panel` 归一化成整页透明定位层，可见饰板换成新 `.plate` | PLCUI 的 `container` 子元素坐标相对容器内容区，1024×600 里嵌多层会让坐标算不清；改成**全页面绝对坐标**，与 XML 一一对应 |
| 一台仪表 = 一个 `.gauge` div（含 conic 圈 + 刻度 + 指针 + 读数） | 拆成 4 个组件：`nd_t`（指针 image，绕 pivot 旋转）+ 表盘底图（烘进背景）+ `v_t`（读数 label）+ `g_cap`（中心盖） | 指针会转 → 必须活组件；其余不变 → 烘图 |
| 状态灯 `.lamp--run/idle/alarm` 靠 CSS 类切换 | 三张独立 PNG（`lamp_run` / `lamp_idle` / `lamp_alarm`），`set_src` 切换 | `image` 只能换图 |
| 开关 `.sw.on` 靠 CSS 类改颜色 | 两张 PNG（`sw_on` / `sw_off`）+ `src-checked` | 同上 |
| 数值 `<span>` 靠 JS 改 `textContent` | `label` + `set_text` | 标准做法 |
| 曲线 `<polyline points="...">` 由 JS 重算 | `chart` 组件 + `set_values`（整条原子更新） | 标准做法 |

## 四、没有降级的部分

以下参考稿里的效果**在设备上一模一样**，逐条核过：

- 四色配色（`--m1`~`--m4` + amber/cyan/green/red/led）全部原值搬运
- 1024×600 布局按 1400×872 同倍率 0.731 换算后落到 4px 栅格
- 按钮四态（普通 / 按下 / 选中 / 禁用）齐全
- 软键盘（数字键盘 `kb_num`）—— `keyboard` 组件原生支持，拼音也有
- 输入确认 / 取消（`on-submit` / `on-cancel`）—— textarea 原生事件
- 页面切换（4 页，延时 30~40ms 刷新）
- 数据刷新（1s 一次，曲线 2s 推一点）
- 滑块拖动 + 实时反馈（温度设定、背光亮度）

## 五、接入真机前必须确认的三件事

1. **固件要开 `LUAT_USE_PLCUI`** —— 没开的话 `plcui.init` 直接失败，界面不起来（日志会打「plcui.init 失败」）。
2. **图片必须与 `main.xml` 同目录** —— luadb 不支持子目录，`code/res/` 下所有文件平铺到 `/luadb`。
3. **`code/res/` 里 52 个资源 + 27.6KB XML 一起烧** —— 只烧 lua 会缺图，现象是整屏黑只有文字。

## 六、上台架后修正的四处（2026-11-16 实测）

真机日志 + PC 模拟器跑通之后回头改的，都属于「原型能跑、PLCUI 不认」这一类：

| 现象 | 根因 | 处理 |
|---|---|---|
| 整页加载失败，日志只有 `E_SCHEMA: Integer attribute is invalid or out of range`，不给属性名 | 软键盘 `kb_num` 的 `w/h` 是 **0** —— 原型里 `.kb{display:none}`，`getBoundingClientRect()` 对隐藏元素恒返回 0；而 PLCUI 的 `w/h` 是必填整数，下限是 1 | 导出钩子对隐藏元素回退到内联样式取值；导出器遇到 `w/h<1` 直接报错中止；`check.py` 按 PLCUI 源码补齐了整型取值域校验（连 4 个负向用例一起验过） |
| `E_RESOURCE: Slider knob image must match its square knob dimensions` | 旋钮图是 16×22 的胶囊 | PLCUI 要求旋钮图**正方形**且**边长等于滑块短边**，滑块高 24 → 旋钮必须 24×24；原型与瓦片同步改成圆钮 |
| 满屏文字显示成 `table: 0x02FFD4C0` | `ui_app.refresh` 把整个数据表 `v` 传给了 `apply_bind`，`tostring(表)` 的结果被 `set_text` 画了出来 | 改成 `apply_bind(b, v[b.var])`。这条只有真正渲染出来才会暴露，静态检查抓不到 |
| `—`、`▣`、`⚠` 渲染成空心方块 | 这版固件的 `hzfont` 不是全 GB2312：实测 `± · ℃ ° ■ ★ ▲ ① × ÷` 有字形，`— ▣ ⚠ ▶ ✓` **没有** | 占位符 `—` → `--`，标题 `▣` → `■`，告警前缀 `⚠` → `▲`，报警表「处理」列的 `—` → `已归档`；`check.py` 增加字形白名单校验 |

另外两条日志是**噪声**，不用管，已在 `boot_app` 注释里写明：

- `E/pwm setup ch 3` —— `luat_lib_pwm.c` 在 `LUAT_CONF_PWM_MAXID` 未定义时**无条件**打这行错误日志；通道 3 在 1..5 内，`pwm.setup` 实际是成功的。
- `W/gpio gpio setup fail pin=17 ret -1` —— 这版固件 pinmux 把 GPIO17 关掉了（LCD 供电由硬件常使能），返回 0 属正常；代码已降级成 info 并继续。
