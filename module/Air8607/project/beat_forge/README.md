# BEAT FORGE - Air8607 可演奏鼓机 / 步进音序器

> 一台上电就开嗨的 16 步 8 轨鼓机：声音是 Lua 现场合成的 PCM，画面和声音共用同一台采样时钟。
> 10 寸屏 + 触摸编曲 + 真喇叭出声，零图片素材、零音频素材。

- 适用固件：`luatos@air8607@10i_v0`
- 适用硬件：Air8607 大屏音视频最小系统板（Air1603）+ 10 寸 RGB 屏 1024x600（免序列）+ GT911 电容触摸 + 喇叭（内置 DAC + HT6873 功放）
- 画布与动画：`airui` 2.19.0（airui@ec071fd），`airui.set_rotation(0)`，1 tick = 1 次 LVGL 刷新
- 编码 / 换行：UTF-8 / CRLF

## 这台 APP 是什么

把一台舞台鼓机搬上 10 寸屏：

- **16 步 x 8 轨音序器**：点格子即编曲，点亮的格子当场出声；
- **真实音频输出**：8 种鼓声（底鼓 / 军鼓 / 拍手 / 闭镲 / 开镲 / 通鼓 / 边击 / 贝斯）
  在开机时由包络 + 正弦扫频 + 确定性噪声合成成 PCM，混音任务按采样位置精确调度后
  经 `exaudio` 流式推给 DAC；
- **节拍反应堆**：左列大圆盘是 8 轨 VU 辐条 + 自转刻度圈 + 拍脉冲双环，
  节奏、发声、动画三者同源；
- **示波器**：画的是**真实送进 DAC 的那段 PCM**（混音缓冲快照），不是假动画；
- **4 个图案槽 A/B/C/D**：出厂预置舞曲 / 碎拍 / 氛围 / 加花四套，随手切换随手改；
- **加花键**：一下把尾拍推成通鼓滚奏 + 军鼓渐强。

没有 exaudio（如 PC 模拟器）时自动进静音模式：混音照跑、示波器照画、节拍照走，
界面功能 100% 保留，只是不出声。

## 声音引擎（engine.lua）

### 采样时钟是唯一时间真相

`sample_clock` 记录已产出的采样数（16000/秒）。混音任务每轮产出一整个 PCM 缓冲：

1. 缓冲内的所有步边界按**采样位置**调度（不是按帧），鼓点零漂移；
2. 命中的鼓声混进缓冲，跨缓冲的尾巴留在 `pending` 里下一轮继续混；
3. 推进时钟、拍波形快照（示波器数据源）、int16 LE 打包（256 个一批拼格式）；
4. `exaudio.play_stream_write(data)` 流式推走；等待时长 = 缓冲时长 - 本轮耗时，
   采样时钟和墙钟始终同速。

### 摇摆（swing）

偶数步（0 基）长 `base + swing_off`、奇数步短 `base - swing_off`，
两步均值恒等于 `base`——鼓组"摇"起来但 BPM 不漂。

### 合成（synth.lua）

零音频素材。每个鼓声 = 包络 +（正弦扫频 | 高通噪声 | 谐波叠加）：

| 轨 | 合成方式 | 时长 |
|----|----------|------|
| KICK | 正弦扫频 160Hz->45Hz + 低通软化起振 click | 0.28s |
| SNARE | 185Hz 基音 + 低通白噪声双包络 | 0.22s |
| CLAP | 3 个间隔 9ms 的低通噪声短爆 + 拖尾 | 0.20s |
| HAT-C / HAT-O | 限带噪声 + 单阶高通 + 低通，快 / 慢衰减 | 0.06 / 0.28s |
| TOM | 正弦扫频 235Hz->105Hz | 0.24s |
| RIM | 1650Hz 短音 + 低通 click | 0.05s |
| BASS | 55Hz 基音 + 2/3 次谐波 | 0.42s |

噪声用自带 LCG（不用 `math.random`）：每次开机合成结果完全一致，示波器波形可复现。

**音质要点**（"不好听/太尖锐"的三大元凶，全在热路径上）：
1. **输出削波（最大元凶）**：混音缓冲的数值单位是"样本 x 32767"（`mix_span`
   的增益含 32767 因子），打包必须除回 32767。1.x 之前漏除，PCM 输出常年
   满幅硬削波——方波化的爆音，任何包络整形都救不回来。现已折进 `pack_gain`
   （`recalc_vol` 一并算好，热路径仍是纯乘法），修复后峰值稳定在 0.3 满幅。
2. **首尾归零**：每个样本经 `shape()` 包络整形（淡入 1~4ms + 淡出 6~45ms），
   且必须排在软饱和 / 抛光之后做。非零截断 = DAC 端直流阶跃"咔哒"声。
3. **噪声限带 + 软饱和**：白噪声先保持插值压到 6kHz 内（`noise_new`）再低通，
   全体过 tanh 近似软饱和添"暖"。纯白噪直顶奈奎斯特是"太尖锐"主因。

**内存策略**（真机 `not enough memory` 修复）：8 个样本以 int16-LE 紧凑字符串
存储（约 56KB，而非数字表的 200KB+）；混音时逐片段 `string.unpack` 解码累加进
复用缓冲区，PCM 以 1024 样本（2KB）分片直接写 `play_stream_write`，**全程零
`table.concat`、零垃圾分配**。打包批大小固定 512（与 `synth.pack16` 同规格——
单批 1024 时引擎输出出现样本错乱，PC 可复现，512 规避）。PC 回归自检：8 秒
打包灌注仅剩一次性结构残留（`<500KB` 断言）。

### 音量

滑块走混音侧数字缩放（打包前乘系数），行为在有 / 无音频硬件时完全一致。
`exaudio.vol` 没有调用：官方流式 demo 不调也能正常出声，少一处不确定性。

### 功放（PA）

功放 PA（GPIO73）跟随播放状态：出声开、停止/退出关。

## 真机验证方法

1. 上电即自动开播：默认 124 BPM 图案 A，喇叭约 1 秒内出声（音频流有启动缓冲）；
2. 点任意步进格：立刻听到对应鼓声（触摸到发声 < 1 缓冲）；
3. 拖 BPM 到 180 再回 60：节拍连贯无跳变，反应堆脉冲跟着变快变慢；
4. 点轨名 KICK 静音：底鼓消失、VU 辐条熄灭、示波器低频包络变小；
5. FILL -> PLAY：尾拍滚奏能听见；CLEAR：静音；PAT B/C/D：四种律动明显不同；
6. 日志确认 `音频就绪 流式缓冲 4096 字节`；若出现 `进静音模式` 检查固件是否含 exaudio；
7. 日志 `静态层图元` 约 170，状态栏 `图元` 稳定在 150..260（随亮格数浮动）。

## 回退检查单

- [ ] 喇叭不出声但界面正常：看日志是否有 `exaudio 初始化失败 / 无 exaudio 库`（静音降级是预期行为）；否则查 AUDIOPA_EN=GPIO73 与 `theme.audio` 参数
- [ ] 触摸无响应：`tp.init` 失败先于动画任务绑定；w/h 必须传，缺了 EINVAL 静默失败
- [ ] 上电花屏：背光在 UI 就绪后才点亮，检查 `power_on()` / `backlight_on()`
- [ ] 网格错位：所有图元坐标由 `theme.lua` 推导，勿在 `ui.lua` 里散写魔法数
- [ ] 节拍越走越偏：摇摆只在 `engine.advance_step` 一处加减 `swing_off`，别在第二处改
- [ ] 真机 `not enough memory for buffer allocation`：说明又有人往混音路径里加了
  临时表 / `table.concat`。热路径只允许复用模块级缓冲（`pack_buf` / `mix_span` 的
  `pk` / `fmt_cache` / `parts`），PC 自检的 8 秒内存回归必须过
- [ ] 鼠标 / 触摸点击有"咔哒"声：先查该音色首尾样本是否归零（`synth` 自检有断言），
  再查混音缓冲边界——`pack_buf` 每片固定 1024 样本对齐，勿改成任意长度
- [ ] 声音发闷 / 爆 / 尖：先抓真实 PCM 看峰值（验证器 `pcmstat`），贴 32767 就是
  单位换算又丢了（`pack_gain` 必须含 1/32767）；再看 `rough` 指标（踩镲约 1.0、
  军鼓 0.3、底鼓 0.03，涨一个数量级 = 噪声限带失效）
- [ ] 声音断断续续：看混音任务是否还在"产一块等一块"。必须保持约 2 缓冲的
  "领先量"（`TARGET_LEAD`），UI 忙帧挤占调度时先补产再睡

## 设计取舍记录

1. **声音和画面同一台时钟**：示波器画的是真混音缓冲快照，不是装饰动画。
   代价是 UI 读引擎状态必须克制（只读 `st` + `playhead()`），换来"看到的就是听到的"。
2. **暗格静态层 / 亮格动态层**：128 个格子如果每帧全画，30fps 下图元量直接翻倍。
   拆开后动态层只有亮格 + 播放头（默认图案约 34 格），预算稳定可自证（状态栏 `图元`）。
3. **音量走混音侧**：`exaudio.vol` 与数字缩放二选一，选后者因为它在静音模式下语义不变，
   滑块行为在 PC 和真机完全一致，少一类"真机才复现"的问题。
4. **停止即关**：STOP 立即关功放并清空 pending，尾巴随停止截断（PA 跟随出声状态）。
5. **点格子即出声**：编曲时能立刻听到结果，比"编完再播放"的交互省一半来回。
6. **样本存紧凑字符串而非数字表**（真机 OOM 修复）：8 个样本从 Lua number 表
   （约 200KB 常驻）改为 int16-LE 字符串（约 56KB），混音按 16 样本批展开解码。
   代价是代码绕一点（`string.unpack` + 手写展开），换来常驻内存降 70% 且热路径零垃圾。
7. **分片直写代替 concat**：`table.concat` 需要一整块连续 4KB，是碎片化嵌入式堆上
   最后的稻草。改成 1024 样本 / 2KB 分片直接 `play_stream_write`，拼接整个消失。
8. **UI 控制层按需重绘**：控制面板从每帧全量重建改为 `ctl_dirty` / 闪烁触发，
   消息面板空闲时跳过——顺带缓解真机 `airui refresh retry posted` 的刷新队列积压。
9. **单位换算折进增益常量**（真机"太尖锐"的真根因）：`mix_span` 增益带 32767
   因子、打包要除回，两处失配就是满幅削波。教训：数值单位写进变量声明处的
   注释（`vol_gain` / `pack_gain`），并用假 exaudio 抓真实 PCM 断言峰值——
   上一轮"波形峰恰好 1.000"其实就是削波，被当成了正常。
10. **流式写入用"领先量"节拍**（"不连贯"的真根因）：产一块等一块的零余量节拍，
   被 UI 忙帧挤一次就饿流（官方文档明言断供会停止播放）。改为保持约 2 缓冲
   余量、不够立刻补产；写失败重试同一片，绝不丢片。
11. **房间胶合（反馈 delay）**：击打之间垫 128ms 反馈回声（回声路径低通逐圈变闷），
   干巴巴的孤立"嗒"连成一片。`theme.audio.room_*` 三参数可调，湿声 0.18 起。
