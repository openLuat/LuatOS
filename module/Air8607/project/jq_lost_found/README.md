# 失物招领公示（Lost & Found Notice Board）

> 一块挂在公共场所的触摸公示屏：捡到 / 遗失的物品集中登记、公示、检索，认领（不分拾得/遗失）必须凭身份证核对并登记联系方式。
> 纯离线运行：内置示例数据，无网络也能完整演示。

- 适用硬件：Air8607（Air1603）+ 10 寸 RGB 屏 1024x600 + GT911 电容触摸
- 编码 / 换行：UTF-8 / LF

## 提示词（Prompt）

做一个「失物招领公示」公示屏：

- 每条记录区分 **拾得** 与 **遗失** 两类，字段包含物品名称、时间、地点、联系方式。
- 支持按 **物品名称、时间、拾得/遗失类型、公示中/已认领状态** 组合搜索。
- 支持 **新增条目** 与 **认领**。
- 认领（不分拾得/遗失）**必须凭身份证核对**（18 位身份证号校验位校验）**并登记联系方式**。
- 拾得人联系方式**不公示**，仅在详情页可见；遗失人联系方式正常公示。
- 已认领的条目仍可点击查看（含认领人证件尾号与联系方式）。
- 界面要丰富、友好：颜色区分拾得/遗失、状态徽标、统计、分页列表 + 详情面板。

## 三、功能与操作

| 操作 | 效果 |
|---|---|
| 点「搜索框」 | 弹出软键盘 + 拼音候选，输入关键词后回车，按名称/地点/联系方式过滤 |
| 点「拾得/遗失」chip | 按类型过滤 |
| 点「公示中/已认领」chip | 按状态过滤（已认领条目也可单独筛出查看） |
| 点「今天/近7天」chip | 按时间过滤 |
| 点「＋ 新增条目」 | 弹出表单：类型 + 名称 + 时间 + 地点 + 联系方式，点字段弹键盘编辑 |
| 点列表卡片 | 右侧详情面板显示完整信息（含拾得人联系方式）与操作按钮 |
| 点「凭身份证领取」 | 弹浮层：录入 18 位身份证号 + 登记认领人联系方式，校验通过后标记已认领 |
| 已认领条目 | 仍可点击查看，详情显示认领人证件尾号与联系方式 |
| 点「删除该条目」 | 删除当前条目 |

### 中文输入

固件未开 `LUAT_USE_PINYIN` 时，airui 键盘的 IME 候选为空。本项目用 `pinyin.lua` 的应用层词表兜底：
打拼音（如 `qianbao`）→ 底部候选行出现「钱包」→ 点击上屏。词表覆盖物品名称、地点、招领高频词，
新增词条只需在 `pinyin.lua` 的 `ENTRIES` 加一行 `{ "拼音", "词" }`。

## 四、身份证校验（GB11643）

`store.valid_id` 校验 18 位身份证号的**校验位**（前 17 位数字 + 加权求和取模 + 查表）。
`conf.SAMPLE_ID` 是合成的合法示例号（`110101199001011237`），认领浮层里的「示例」按钮一键填入，方便演示。

认领规则（拾得 / 遗失通用）：
- 必须输入 18 位身份证号，校验位核对通过；
- 必须登记认领人联系方式（数字）；
- 通过后标记为已认领，保存证件尾号与联系方式（脱敏），完整身份证号不落盘。

隐私：拾得人的联系方式不在公示列表中显示，仅点击条目进入详情页可见；遗失人的联系方式正常公示。

## 五、硬件引脚（与 factory/config/eng_8607_10i_v0.lua 对齐）

```
LCD_DISP = GPIO15      LCD 供电 = GPIO17（低有效）
背光     = PWM3 (GPIO13)   SD_EN = GPIO74
GT911    = I2C1 轮询模式, pin_rst = 14, pin_int = 51
功放 PA  = GPIO73（默认关断）
```

## 六、烧录与运行

1. LuatTools 把 `code/` 目录**整体加入**，入口 `main.lua`。
2. 上电串口应看到：
   ```
   I/user.main      lost_found 1.0.0
   I/user.store     失物招领数据初始化 8 条
   I/user.main      显示初始化完成 display 1024 600
   I/user.main      失物招领公示已就绪 ...
   ```
3. 点卡片查看详情；点「＋新增」登记；点「凭身份证领取」走身份证核对流程。
4. 改标题、示例数据、每页条数：只改 `conf.lua`。

## 七、扩展点

| 数据 | 现在 | 真机怎么接 |
|---|---|---|
| 持久化 | 内存（重启丢） | `store.lua` 的写操作落盘到 TF 卡 / `fskv`（若固件支持） |
| 时间 | 依赖系统 RTC | 通过 NTP / 网络校时，`os.time()` 自动正确 |
| 数据来源 | 本地手工登记 | 对接后台接口同步条目 |
| 身份证 | 校验位核对 | 接读卡器 / 摄像头 OCR，识别后调 `store.claim` |

## 八、已知限制

- 数据仅在内存，重启后回到示例数据（扩展点见上）。
- 列表为分页（每页 5 条），未做滚动容器。
- 中文输入依赖 `pinyin.lua` 词表，未收录的词无法上屏（需手动扩充词表）。
