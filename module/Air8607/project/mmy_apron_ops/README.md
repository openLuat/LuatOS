# AeroDeck 机坪运行指挥大屏（mmy_apron_ops）

> Air8607（Air1603）+ 10.1 寸 1024×600 RGB 屏 + GT911 电容触摸 + AirUI
> 面向机场机坪夜航值守场景的"运行指挥"大屏：雷达态势、航班保障全流程、跑道气象与资源调度。

---

## 1. 产品定位

机坪是机场里最"碎"的一块：一个宽体机位 45 分钟内有 8 个保障环节接力，任何一环掉链子，
飞机就只能压在地面吃延误。AeroDeck 把机坪值班员真正盯的四件事压在一屏：

| 盯什么 | 界面落点 |
|--------|----------|
| 哪架飞机在哪（含推出去的） | 主页圆形机坪雷达 + 航迹点，可直接点开 |
| 每架飞机保障到哪一步 | 主页航班列表进度条 + 详情页 8 节点时间轴 |
| 天气还让不让飞 | 跑道风 / 能见度 / RVR / 道面摩擦系数 / LVP 状态 |
| 车和人够不够 | 除冰车、加油车、摆渡车、行李拖车的容量与占用 |

配色为"夜航"主题：深蓝底 + 雷达青主色 + 琥珀（滑行道灯）+ 橙（除冰）+ 红（告警），
全部图形由 `airui.shape` 的线/圆/弧/矩形拼绘，无图片资源依赖。

## 3. 页面导览

### 3.1 主页 `ui_apron`

- **机坪雷达**：同心距离环 + 方位刻度 + 旋转扫描扇区（每帧 6°）。
  12 个机位按极坐标排布，每架在坪航班一个航迹点；已推出的航班沿滑行道向外移动，
  离场后航迹点移出画布。点任意飞机 → 该航班详情。
- **航班保障列表**：6 行，航班 / 航司 / 机位 / 计划 / 当前动作 / 16 段进度条 / 等级。
  异常航班的等级点会呼吸闪烁。
- **运行指标**：在场航班、保障准点率、机位占用、待除冰 + 平均延误。
- **跑道气象**：罗盘风向、风速阵风、能见度 / RVR / 温度（超限自动变色），点击进气象页。
- **运行事件**：最近 6 条，按等级着色。

### 3.2 航班详情 `ui_flight`

- 头部：航班号、机型、宽/窄体、机位、计划起飞、当前状态、保障进度。
- **保障节点时间轴**：靠桥 → 下客 → 保洁 → 配餐 → 加油 → 装行李 → 登机 → 关舱推出。
  已完成 / 进行中 / 待执行三态，各节点给出计划时刻。
- **舱单与载重**：旅客、行李、航油、已延误。
- **现场操作**：推进下一节点 / 全部推进 / 完成除冰 / 返回。
- **机位改派**：12 个机位的占用矩阵，点空闲机位直接改派；宽体机不允许停窄体位，
  目标机位被占会拒绝并提示。

### 3.3 跑道气象 `ui_weather`

- 跑道风：±15° 调风向、±2 m/s 调风速，实时给出阵风与侧风分量。
- 能见度 / RVR：±500 m 调节，一键压到 LVP 门限 800 m。
- 道面状态：干 / 湿 / 雪浆 / 结冰，摩擦系数 μ 同步；低温 + 冰雪道面会让在坪航班
  自动变成"待除冰"。
- 气象趋势：能见度 / 风速 / 温度三条曲线切换，画正常区间绿带。
- 运行影响：LVP 是否生效、建议跑道方向、放行能力（架次/时）、除冰需求，附处置建议。

### 3.4 设置 `ui_settings`

- 机坪资源：除冰车 / 加油车 / 摆渡车 / 行李拖车，逐台增减；资源耗尽会红框报警。
- 演示控制：暂停 / 继续、单步推演、重置演示。
- 机位总览：12 格占用矩阵，点已占机位进对应航班。
- 系统信息与关于。

## 4. 交互与联动（不是各画各的）

```
气象（能见度/风/道面）
   ├─ 能见度 < 800m  → LVP 生效 → 放行能力 36→14 架次/时 → 主页告警
   ├─ 侧风 > 12 m/s  → 建议跑道切 36R → 气象页处置建议
   └─ 低温 + 冰雪道面 → 在坪航班标记待除冰 → 除冰车排队
航班保障节点推进
   ├─ 机位占用 / 在坪架次 / 准点率 / 平均延误 实时变化
   ├─ 过了计划时刻仍未推出 → 延误累计，>5 分钟关注、>15 分钟异常
   └─ 关舱推出 → 航迹点沿滑行道离场 → 雷达上消失并记事件
资源数量
   └─ 除冰车满负荷 → 除冰请求被拒 → 事件流告警
```

## 5. 接真实数据

`sim.lua` 是唯一的数据源，接口边界已收口：

- `sim.tick()`：演化入口，接真实系统时把内部随机游走替换为报文解析结果；
- `sim.flights()` / `sim.wx()`：读模型，UI 只读不写；
- `sim.set_*` / `sim.advance` / `sim.set_gate`：写操作，对应人工干预与后端下发。

对接 AODB / 气象报文时，建议在 `tick()` 里按 `M.sim_min` 触发解析任务，
把结果写进 `flights[i]` 与 `wx`，其余代码不用改。

## 6. 移植到其它尺寸

所有坐标按 1024×600 手工排布，常量集中在各 `ui_*.lua` 顶部（`RADAR / LIST / KPI / WXC / EVT`
之类的表）。改屏只需改 `conf.W/H`、`main.lua` 的分辨率与触摸尺寸，再按新尺寸调整这些常量表。

## 7. 已知限制

- 演示数据由本地模型生成，不接受外部推送；
- 雷达为示意性极坐标图，非真实机场航图；
- 未做屏幕旋转与横竖屏切换（固定 0°）；
- 字体仅加载 `theme.SZ` 的 6 档字号，新增字号必须在 `conf.font` / `theme.SZ` 里补充，
  否则该字号文字不出字。
