# IMM-6 注塑六号单元 · 伺服注塑机 PLC 主控

Air8607（Air1603）+ 10.1 寸 RGB 1024×600 触摸屏的注塑单元操作面板。
整屏用 LuatOS `airui`（LVGL 9）纯 Lua 绘制：总览页是一台可动的注塑机剖面——移动模板随合模动作滑动、
螺杆在注射时前移、熔料色块跟着变化；梯形图页把六条 rung 按 PLC 扫描顺序实时着色；
点位页给出 DI / DO / AI / AO 四个映像区与可点按的强制表。

机台为虚构演示对象，工艺量全部由 `code/sim.lua` 的本地模型演化，不接真实控制器。

## 硬件

| 项目 | 参数 |
|------|------|
| 主控 | Air8607（Air1603） |
| 屏幕 | 10.1 寸 RGB 1024×600（免序列） |
| 触摸 | GT911 电容触摸，I2C1，RST=GPIO14，INT=GPIO51 |
| 背光 | PWM3（GPIO13），默认 82% |
| 显示 | `exd_air8607_rgb.setup({ pin_rst = 15 })` |

## 五个页面

**总览（overview）**
- 机台剖面：底座、四根拉杆、后模板、机铰、移动模板（容器整体滑动）、动模/定模、固定模板；
  注射单元的料筒、五段加热圈、螺杆（注射时前移）、料斗与干燥热风管
- 剖面下方是七段周期进度条，右侧给周期时间、模号与启动按钮
- 4 个 KPI：成型周期、锁模力、注射压力、模腔压力
- 周期环：弧长按时长分配，当前段加粗并带游标，环心显示周期与阶段名
- 料筒温度：五根竖柱，虚线为设定值，柱色按偏差分档；底部一行汇总模温与冷却水
- 执行与联锁：安全门 / 模到位 / 料温 / 手原点四个联锁灯 + 八个 DO 输出灯
- 报警与事件：最近三条，按等级着色

**工艺（cycle）**
- 双序列曲线：注射压力（熔料橙）与模腔压力（琥珀），120 秒窗口，带参考线
- 螺杆位置细条与当前值
- 阶段耗时表：七段的设定 / 实测 / 偏差，两列四行
- 料筒五段温度：横向条 + 设定刻度 + 偏差值，超带宽转琥珀
- 模温回路：供水管上三个站点（模温机 / 定模 / 动模），水流粒子沿管移动，
  另有进水温度、流量、加热功率与管路说明
- 工艺参数：八项设定值带量程条

**梯形图（ladder）**
- 六条 rung：运行自锁、合模允许、注射条件、保压与冷却、开模顶出、安全链
- 触点（常开 / 常闭）、线圈、左右母线、R1 的自锁并联支路都按真实梯形图画法排布
- **通电着色**：从左侧母线按扫描顺序逐级传递，导线、触点、线圈分别着色；
  常闭触点取反判断，并联支路与主路做或运算
- CPU 卡：扫描周期、负荷条、RUN/STOP、任务与机架
- 变量表：M0.0-M0.5 与 T1/T2 的实时位状态

**点位（io）**
- DI / DO 各 16 点，双列排布，灯色跟随映像
- AI 8 通道、AO 4 通道：位号、名称、实测值、量程条
- 强制表：四个可强制的点，点按切换；强制值优先于实时映像，卡片右上角统计强制数量
- 背板模块：六个槽位的在线状态与摘要

**系统（settings）**
- 显示与背光：滑块直接写 PWM3，另有夜间 / 标准 / 明亮三档
- 演示模型：采样次数、运行时长、事件条数，暂停 / 恢复、重置数据
- 设备体检：六项按 lo / hi 分级着色，超出 dhi / dlo 转红
- 系统信息：分辨率、显示驱动、触摸、字库、Lua 内存、运行时长
- PLC 诊断：扫描周期、CPU 负荷、任务数、背板模块 + 扫描趋势 + 诊断缓冲
- 设备档案与使用说明

## 数据说明

所有工艺量由同一个状态机演化，彼此保持因果，而不是各自随机：

- 成型周期七段共 28.0 秒，`conf.sim.clock_step = 1`，一次采样推进 1 秒机台时间
- 合模段锁模力按 S 曲线升到 1800 kN；注射段液压升到约 1450 bar、螺杆从 90 mm 前移到 8 mm；
  保压段压力落到 620 bar、模腔压力从 560 衰减到 380；冷却段螺杆边旋转边后退完成熔胶
- 料筒五段各自跟随设定值做一阶惯性，超温故障时二段目标抬升 14 ℃，用于演示联锁
- 模具温度由注射/保压段的熔料加热与冷却段的回水共同决定，模温机加热功率按偏差反算
- 安全门打开 → `running=false` 且阀输出全零；复位后需“操作员按启动”，六拍后自动恢复
- `conf.scenario` 在第 42 / 128 / 208 拍注入门开、超温、机械手未回原点三次故障，第 58 / 156 / 222 拍恢复

接入真实控制器时，把 `evolve()` 里的目标值换成 PLC 采集写入 `M.push(key, value)` 即可，UI 层无需改动。

## 降载策略

总览页每秒要刷新近 60 个字段（文本 + 颜色 + 进度条），单帧容易超过 110 ms 的采样周期，
把 SoC 的静态事件池顶满，出现 `soc_send_event_to_task ... no free static event` 告警。现在的做法：

- **值不变不写**：`st / sc / sb` 三个缓存分别拦截文本、颜色、进度条
- **分时刷新**：前排（阶段条与读数）每秒刷，后排（周期环、温度、联锁、事件）隔秒刷；
  按钮操作走 `refresh(true)` 全量刷
- **事件按签名跳过**：没有新事件就不动那 9 个标签
- **图元按量化档位重建**：料筒温度柱按 0.5 ℃、周期环按 1/40 进度、模温块按 1/10 档重建
- **移动模板与螺杆用缓动跟随**：采样是 1 秒一次，直接用量化值会一顿一顿；
  `frame()` 里按 9 fps 缓动追上目标值，容器只做 `set_pos`，不碰图元数组
- **梯形图用 container 画符号**：改色只调 `set_color` / `set_border_color`，不重建图元
- **曲线按 10 px 抽样、每两秒重绘一次**：120 点两条序列约 120 个线段

`conf.debug.profile = true` 会在日志里每 10 秒输出一行 `[prof] 10s 帧耗时 avg / max / refresh max`，
单帧超过 90 ms 时另有一条告警。定位完成后改成 `false` 即可关闭，关闭时零开销。

## 关键实现约定

- **屏幕坐标以 px 绝对定位**，五张页面都按 1024×544 手工排布，布局常量写在每个 `ui_*.lua` 顶部
- **container 会裁剪子对象**：`art.imm` 里移动模板组、螺杆组都是容器，容器尺寸必须大于子对象，
  否则模板只剩一条边（这个坑在首版就踩到了）
- **container 没有 `set_size`**，进度条统一用 `airui.bar`（原生控件，支持 `set_value`），刻度类用 `theme.segbar`
- **hzfont 只按已加载字号出字**，`main.lua` 遍历 `theme.SZ`（12/14/16/20/26/40）逐个加载
- **页面切换即销毁重建**，每页返回 `{ refresh, slow, frame, destroy }`，`destroy` 置 `alive=false`
- **页面模块必须用字面量 `require`**：PC 模拟器默认开启依赖裁剪，`app.lua` 的 `PAGE_LOADERS` 是给静态分析的登记表
- **字形避坑**：GB2312 子集缺 `·`、`³`、`²`、`µ`、`—`，工程内统一改用 `，`、`m3`、`m2`、`μ`
- **`do` 是 Lua 保留字**，配置表里输出点表用 `dout` 而不是 `do`
- **Lua 5.4 的 `%d` 不接受浮点**，凡进 `%d` 的量先过 `theme.n()`；`dec = 0` 的体检项统一用 `%.0f`
- **轻提示最后创建**：LVGL 后创建的对象在上层，先建会被内容区盖住
- 所有跨页组件操作都用 `pcall` 包裹，避免回调打到已销毁的 LVGL 对象

## 运行

把 `code/` 目录下的 lua 文件烧录到设备文件系统（保持同目录），重启后自动进入总览页。

PC 模拟器上可以直接验证版面：

```powershell
cd bsp\pc
build\out\luatos-lua.exe --headless --agent-ctl=127.0.0.1:9930 ^
    ..\..\module\Air8607\project\mmy_injection_plc\code
```

再用 `agent-ctl` 的 `screenshot` / `pointer` 方法取图与点击页签，适合在真机之前校形。
