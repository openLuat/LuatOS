# 星河一号 · 发射指挥中心（mmy_launch_control）

一块摆在展厅墙上的运载火箭发射指挥大屏。用 Air8607 + 10 寸 1024x600 RGB 屏，
把**一次完整发射**从待命、自检、倒计时、起飞、分离到入轨，压缩进 58 秒里跑完。

- 平台：Air8607 / 10 寸 RGB 1024x600 / GT911 电容触摸
- 框架：airui（LVGL 9），界面全部矢量图元绘制，**不使用任何图片资源**
- 数据：内置飞行仿真引擎（时序、弹道、推进剂消耗都是算出来的，不是播动画）
- 语音：主发动机点火、最大动压、级间分离、整流罩分离、二级关机五个里程碑自动播报

## 交互

| 区域 | 操作 | 效果 |
|------|------|------|
| 开始倒计时 | 点一下 | 待命 → 8 项系统自检（每 0.4 秒过一项）→ T-10 倒计时 → 起飞 |
| 紧急中止 | 点一下 | 自检/倒计时/上升段任意时刻切断发动机，进入中止态，时序停在当前项 |
| 重置任务 | 点一下 | 回到待命，时序、余量、弹道全部归零 |
| 自动演示 · 开/关 | 点一下 | **默认关闭（手动发射）**；开启后待命静置 6 秒自动发射，入轨/中止后静置 9 秒自动重来（展厅模式） |
| 语音 开/关 | 点一下 | 关掉同时拉低功放使能，夜里没有底噪 |
| 全屏 | — | 无弹窗设计，所有反馈走右下角 2.2 秒轻提示 |

**开机进待命后不会自己飞**，必须点「开始倒计时」才启动；自动演示是可选开关，
开关状态在「重置任务」后保持，不会被清回默认值。

按钮都会明确告知失败原因（例如倒计时中点"开始倒计时"会提示"当前阶段不能启动"），
不会出现"点了没反应"。

## 飞行时序（`code/conf.lua`）

任务时间以秒计，起飞前为负。飞行段按 **6 倍速** 播放（1 实时秒 = 6 任务秒）。

| T（秒） | 事件 | 语音播报 |
|---------|------|----------|
| -10 | 终端倒计时 | 阶段切换时播 |
| -3 | 主发动机点火 | ✅ |
| 0 | 起飞 | 阶段切换时播 |
| 12 | 程序转弯 | — |
| 58 | 通过最大动压 | ✅ |
| 150 | 一级分离 | ✅ |
| 152 | 二级点火 | （与一级分离合并成一句） |
| 175 | 整流罩分离 | ✅ |
| 230 | 二级关机 | ✅ |
| 260 | 载荷入轨 | 阶段切换时播 |

8 项自检：一级增压 / 航电总线 / 液压舵机 / 遥测链路 / 塔架撤收 / 气象窗口 / 测控跟踪 / 逃逸系统。

弹道由 12 个关键帧（时间、高度、速度）做平滑插值，**曲线卡画的"计划弹道"和发射台视图用的是同一份数据**，
所以实线永远贴着虚线走，不会出现两处对不上的情况。

## 语音播报（`code/voice.lua`）

只念**里程碑**，不念数字。发射场景下人是盯着屏的，语音的作用是"提醒你抬头"，
所以宁可少说：一句一个事件，说完就闭嘴。

后端按固件能力自动降级，PC 模拟器落到静音模式（界面照常，点语音键会提示"仅界面模式"）：

| 优先级 | 后端 | 条件 | 起播方式 |
|--------|------|------|----------|
| 1 | `ex_tts` | `exaudio` + (`audio_v2.tts` 或 `audio.tts`) | `exaudio.play_start{type = 1, content = 文本}` |
| 2 | `av2_tts` | 只有 `audio_v2.tts` | 自己配 DAC + PA，`audio_v2.tts()` |
| 3 | `aud_tts` | 只有旧框架 `audio.tts` | `audio.config` + `setBus(DAC)` + `audio.tts()` |
| 4 | silent | 都没有 | 只打日志，不影响大屏 |

两个坑写在代码注释里，改这块时别删：

1. **起播前重建通路**：`play_stop` → `setup` → 音量 → `pm(RESUME)`。少了这段，第二句起
   `play_start` 可能返回 true 却不出声；
2. **结束回调会丢**，所以每句都挂按字数估算的看门狗，回调带播报代次 `gen`，过期回调直接丢弃 ——
   否则 `busy` 一焊死就永久静音。

音量、功放脚、优先级都在 `code/theme.lua` 的 `M.audio` 里。

## 工程结构

```
mmy_launch_control/
├── README.md
└── code/
    ├── main.lua                入口（PROJECT / VERSION / sys.run）
    ├── conf.lua                板级参数 + 任务时序 + 遥测关键帧 + 刷新节拍
    ├── theme.lua               设计令牌：配色 / 控件工厂 / 音频参数
    ├── kit.lua                 通用件：缓动 / 格式化 / 折线 / 面积 / 条形 / 圆环
    ├── mission.lua             任务状态机（阶段、时序、遥测插值、事件订阅）
    ├── ui_pad.lua              发射台视图（塔架 / 箭体 / 尾焰 / 烟云 / 卫星 / 相机跟随）
    ├── ui_panels.lua           四块数据卡：弹道曲线 / 自检 / 箭体余量 / 飞行时序
    ├── ui_board.lua            顶栏（阶段胶囊 + 大倒计时 + 时钟）与底部指令条
    ├── ui_main.lua             整屏装配 + 主循环（33ms 节拍，分层节流）
    ├── voice.lua               语音播报（三后端自动降级 + 静音开关）
    └── exd_air8607_rgb.lua     10 寸 RGB 屏显示 IC 初始化
```

状态机与 UI 完全解耦：`mission.lua` 只管推进时间、发射事件，UI 通过 `mission.subscribe(fn)`
收 `phase / event / say / checks` 四类消息，想换一套界面不用动任务逻辑。

## 性能设计

10 寸 1024x600 没有 GPU，一次全屏重绘就是 61 万像素，所以按"脏区"分频重绘
（参数都在 `conf.tick`）：

| 图层 | 周期 | 面积 |
|------|------|------|
| 发射台动态层（尾焰跳动、烟云扩散、速度条纹） | 66ms（15fps） | 328x456 |
| 顶栏文字 / 倒计时 | 120ms（且内容不变不写） | 局部 |
| 弹道曲线 | 200ms | 352x260 |
| 箭体余量 | 250ms | 172x188 |
| 自检 / 飞行时序 | 仅 `rev` 变化时重绘 | 170x188、306x456 |
| 背景 / 卡片 / 标题 / 刻度 | 开机一次 | — |

另外两条硬规矩：

- **先建 shape 后建 label**：`shape` 是独立 LVGL 对象，后建的会盖住先建的。中途插一个图形层，
  整张卡的字就集体消失（这个坑踩过，四块卡都已按此顺序建）；
- **整型字段进图元表前必须取整**：airui 的 shape 图元字段走 C 层 `airui_marshal_integer` →
  `lua_tointeger`，它只能转换"整数值的浮点"：`42.0` 得到 42，`42.7` **静默得到 0**。
  曲线插值、相机滚动都会产生小数，漏掉取整会让整条线段塌到 shape 左上角（典型症状：
  曲线贴着卡片顶部成一条直线、末端突然出现一条竖线）。所有 `set_items` 统一走
  `theme.set_items()`，由 `theme.fix_items()` 对坐标/线宽/透明度做 floor —— 不要绕过它直接
  调 `shape:set_items()`。

## 硬件注意

- 背光 PWM3（GPIO13），LCD 供电使能 GPIO17，显示复位 GPIO15
- 触摸 GT911：I2C1，RST=14，INT=51；`tp.init` 必须给 `w/h`，否则 input 适配器静默拒绝，
  表现为"初始化成功但点不动"
- 背光在首帧画完后才点亮，避免上电花屏
- 语音走芯片内置 DAC + 板载功放，功放使能 `AUDIOPA_EN = GPIO73`（高有效）

启动顺序（`main.lua`）：

```
上电 → LCD 复位 → exd.setup → airui.init → 字体加载 → 根容器
     → voice.init → 订阅任务事件 → 装配界面 → 首帧预绘制 → 触摸初始化 → 点亮背光
```

## 接到真实火箭数据

仿真只是占位。UI 只读 `mission.st`，所以接管真实数据只需改 `mission.lua` 的两处，
**界面一行都不用改**：

1. `M.telemetry_at(t)` —— 计划弹道插值，改成读遥测帧里的高度/速度表；
2. `update_telemetry()` —— 每个 tick 会把 `st.mt / st.alt / st.vel / st.acc / st.fuel.*`
   按仿真模型覆盖一遍。接真机时在此处改为"外部数据优先"：

```lua
local mission = require "mission"
local st = mission.st

-- 采集任务里（100~500ms 轮询）直接写字段
st.mt   = 42.5      -- 任务时间（秒，起飞前为负）
st.alt  = 5.5       -- 当前高度 km
st.vel  = 320       -- 当前速度 m/s
st.acc  = 2.1       -- 轴向过载 g
st.fuel = { lox = 78, rp1 = 81, s2 = 100, power = 97 }
```

注意 `fuel` 整体替换而不是逐字段改（`reset()` 也是整体重建），并且写入后要跳过
`update_telemetry()` 的仿真覆盖，否则一帧就被算回去。

典型数据源：测控站转发的 UDP/TCP 遥测帧、MQTT 主题、串口 Modbus。
曲线、仪表、发射台视图都会在下一个刷新周期自动跟上。
