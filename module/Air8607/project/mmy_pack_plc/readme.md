# PACK-3 储能模组装配线 · PLC 主控屏（PLCUI）

Air8607 / Air1603 + 10.1 寸 RGB 1024×600 触摸屏，用 **PLCUI**（XML 定布局 + Lua 更新数据）做的五页主控屏。
整套界面只有 **一张 4×4 透明 PNG** 作为点击热区，其余全部是纯色块、原生表格与原生图表。

## 硬件与运行环境

| 项目 | 参数 |
|------|------|
| 主控 | Air8607（Air1603） |
| 屏幕 | 10.1 寸 RGB 1024×600（免序列） |
| 触摸 | GT911，I2C1，RST=GPIO14，INT=GPIO51 |
| 背光 | PWM3（GPIO13），默认 82% |
| 固件 | 需含 PLCUI 的 102 / 103 号固件（**104 号已移除 PLCUI**） |
| 开发验证 | `bsp/pc` PC 模拟器（PLCUI 1.0.2 已编入） |

## 五页

**总览** — 深色顶栏（5 页签 + 时钟）+ 状态横幅 + 产线拓扑（7 工位，蓝条标出当前工位）+ 当班产出 4 格 + 拧紧四轴 + 报警三行。

**趋势** — 两条实时曲线（拧紧扭矩 M1/M3 + 上下限、气密压力 + 限值）、拧紧结果表（4 轴扭矩/角度/判定/复拧）、焊接与测试六项参数。
曲线不是静态贴图：进入拧紧/气密工步时先把曲线压平，再按 200 ms 采样从左往右逐点画出，工步结束后冻结在这一模组的完整结果上。

**步序** — 七工步清单（已完成点绿点、当前行蓝色高亮、状态词文字说明）+ 工位联锁矩阵表（5 条件 × 4 工位）+ 配方参数与切换记录。

**点位** — DI / DO / AI 三张表 + 强制表（可点按切换，强制点前有琥珀标记）+ 背板六模块 + 扫描诊断。

**系统** — 设备信息表 + 当班统计 + 背光滑块与三档预设 + 运行诊断 + 版本说明。

## 数据流

```
boot_app（1 Hz）→ data_app.step() 推进工步与工艺量
                → ui_app.refresh()：
                    ① 按 ui_vars.bind_list(当前页) 逐条 set_text
                    ② 当前页特有的部分：工位/步序高亮移动、三张点位表、静态表首次填充
                    ③ plcui.refresh() 统一提交

ui_app.chart_tick（200 ms）
                → 不在趋势页则立即返回
                → 工步序号变了且进入拧紧/气密：chart:set_values 把该系列整条压平（也把环形游标拨回起点）
                → data_app.sample() 给出瞬时扭矩/压力：检测工步按进度插值，其余工步沿用最后一次采样值
                → chart:add_point 追加，plcui.refresh 提交
```

曲线这一块的三个取舍：

1. **PLCUI 的 chart 没有 clear 方法**，只有固定长度环形缓冲的 `add_point`。所以「清空重画」是用 `set_values` 灌一条等值数组实现的——顺带把环形游标归零，等价于清空。
2. **`set_values` 要求数组长度严格等于 XML 的 point-count**，多一个少一个都返回 `E_SCHEMA`。所以点数不写死在 Lua 里，而是每次用 `chart:state().point_count` 现取——改 XML 不会和代码脱节。
3. **进度用自驱动计数，不读时基**。`mcu.ticks()` 的单位在不同 BSP 上不一致（按毫秒算会直接把进度顶到 1，曲线全程平在平台段）；改成「采样函数自己数拍子、换工步清零」，进度严格单调，也不会被 1 Hz 推进打断出锯齿。
4. **非检测工步沿用最后一次采样值**，不留模型保持值。否则拧紧结束那一刻扭矩从 8.5 跳回保持值，曲线上会多一道垂直台阶。
5. 环长 30 / 24 点（6 s / 4.8 s 窗口），比单工步采样数（约 20 / 17）长一些，这样工步结束后能看到「脉冲 + 保持段」，滚动出去后回到平线——和真实趋势一致。

七工步共 42.2 秒一循环：上料 6.2 / 堆叠 12.4 / 极耳焊 8.8 / 入箱 5.6 / 拧紧 4.1 / 气密 3.5 / 打码 1.6。
拧紧在工步内从 6.8 N·m 爬到 8.5，气密先加压到 25 kPa 再缓慢衰减，其余工步保持上一次结果。

## PLCUI 的能力边界（决定了这版长什么样）

写之前核对了 `components/plcui` 的源码，四条约束直接影响了设计：

| 事实（源码位置） | 设计后果 |
|---|---|
| **只有 `image` 能收 `clickable` / `on-click`**（`luat_plcui_xml.c` 的 image 分支） | 每个可点区域（25 个页签热区、强制行、背光档位）都铺一张 4×4 透明图做热区，标签叠在上面显示 |
| **label 没有 `set_color`，container 也没有**（binding 方法表） | 文本颜色一律静态；状态色改由「预制色块 + `set_hidden`」表达：横幅圆点、步序绿点、强制琥珀标记、工位蓝条 |
| **table 单元格只有一种字色**（table 的 `color` 是整表属性） | ON/OFF、合格/超差靠文字本身，不靠颜色 |
| **chart 不画坐标刻度**（`hdiv`/`vdiv` 控制网格，无刻度文字） | 曲线下方补一行图注写清量程（纵轴 0-10 N·m，横轴 0°-60°） |
| `PLCUI_MAX_WIDGETS = 512` | 当前 433 个，留 79 个余量；加页面前先数 |

## 与设计稿的降级清单

`design/index.html` 是设计基准，落到 PLCUI 有四处降级，均为能力所限、非取舍偷懒：

1. **彩色数值**（KPI 的绿字、拧紧角度的绿字）→ 数值统一墨色，状态靠色块与文字。OEE/良率仍保留绿字（这两处始终是好的，用静态绿即可）。
2. **表格内的红绿状态**→ 单色文字。
3. **曲线周围带刻度的坐标轴** → 改为图注。
4. **工位卡片的整块蓝色高亮**（当前工位）→ 改为左侧 4px 蓝条 + 移动定位，省下 7 套双色标签。

## 字体：为什么看着发虚，以及能改到什么程度

PLCUI 的 label 只认 `builtin="hzfont"`（`requested_hzfont()` 里写死），字形由 hzfont 现场光栅化，
抗锯齿取的是**全局超采样率**：

| 值 | 采样 | 观感 |
|---|---|---|
| 1（默认） | 2×2 | 笔画硬边，小字号发糊 |
| 2 | 3×3 | 明显细腻，代价适中 |
| 3 | 4×4 | 最锐，光栅化与缓存压力最大 |

默认取 `TTF_SUPERSAMPLE_RATE` 宏，全仓库没有定义 → **实际就是 1**。
PLCUI 每取一个字形都会读这个全局值（`current_supersample()`），但**没有暴露 Lua 接口**。

`lcd.drawHzfontUtf8(x, y, s, size, color, antialias)` 的第 6 个参数能改它，前提是 `lcd_dft_conf` 已初始化；
本工程走 `display` 后端，实测日志是 `E/lcd lcd not init`，这条路径走不通。

所以 Lua 层能做的只有排版：标题 18→20 拉开层级、二级/三级墨色加深（`#5A6676`→`#46566B`、`#8B97A7`→`#6E7E93`）、
KPI 数值 38→40、当班统计 34→36。要真正锐利，得在固件编译时加 `-DTTF_SUPERSAMPLE_RATE=3`（推荐 2，性价比最好）。

### 字形缓存

PLCUI 自己在首帧才初始化 hzfont，缓存容量用的是默认 **256 条**。本工程五页共 9 档字号，
静态统计就有 **463 个「字符 × 字号」组合**，再加上数字随值变化，256 条必然反复淘汰重绘，
日志会出现 `hzfont缓存size=256已满，请提高缓存大小`。

`luat_hzfont_init` 在已初始化时会直接返回成功并跳过（防止沙箱重复初始化导致堆损坏），
所以 `boot_app.font_cache_tune()` 在 `ui_app.load()` **之前**按 1024 初始化，
PLCUI 后面那次调用就变成空操作，容量按我们的来。真机内存不够时依次退到 512、再退默认 256，
失败只影响性能不影响启动——日志里能看到实际生效的档位。

**字形覆盖的两个坑**：hzfont 没有 `U+3000`（全角空格）与长破折号 `—`，都会渲染成空心方块；
文本里只用 ASCII 空格与 `-`。`·`、`→`、`○`、`●`、`°`、`×`、`±`、`℃` 都是有的，可以放心用。

## 已知限制

- 趋势页**只在当前页可见时采样**：切走后曲线停止推进，切回继续（同一工步内），跨工步则从头重画。
- 曲线形状只出现在**拧紧（4.1 s）与气密（3.5 s）**两个工步，其余 34 s 是一条保持线——这是工艺决定的，不是卡住。想看全周期都在波动的量，把其中一条换成伺服电流或节拍趋势即可。
- 200 ms 采样在巡视趋势页时是 5 Hz 的 `plcui.refresh()`；不在该页时这条定时器第一行就返回。真机上若觉得占带宽，把采样降到 250 ms 即可。
- 背光滑块在 PC 模拟器上不生效（`pwm` 不可用），真机才有效果。
- 页签切换后组件句柄要重新 `find`，`ui_app.show()` 里延时 40 ms 再刷首帧，这是 PLCUI 的既有约束。
