# A. 完整需求书

```text
# 任务
在 module/<型号>/project/<项目名> 从零实现一个音乐播放器（Lua + airui），是新建项目，不是改现有代码。
屏幕 <宽>x<高>，目标板 <型号>。

# 环境基线（不要自行假设，一律照此）
- 固件 <固件包名>，已开 LUAT_USE_AIRUI（含 hzfont 矢量字库）
- 硬件：<屏规格> + <触摸型号> + <音频通路> + SD 卡
- 引脚严格对齐 <factory 配置路径>：
  LCD pin_rst=<n> / pin_pwr=<n>（<有效电平>）/ 背光 <PWM 通道> / SD_EN=<n> / AUDIOPA_EN=<n>（<有效电平>）
  <触摸型号>: i2c<n> 400kHz, pin_rst=<n>, pin_int=<n>
- 不改任何 C 代码；不要读 components/airui/lvgl9/ 目录

# 界面：零图片素材，全部用 airui.shape + airui.label 绘制
五区布局（坐标写死，全部整数）：
  顶栏   <x>,<y> <w>x<h>    标题 | 音源与曲目数 | FPS
  列表   <x>,<y> <w>x<h>    卡片 + 8 行可视 + 上一页/下一页
  舞台   <x>,<y> <w>x<h>    五种画面风格切换
  面板   <x>,<y> <w>x<h>    曲名/歌手、进度条、时间、音量滑块、5 个风格键、歌词状态
  控制栏 <x>,<y> <w>x<h>    模式、上一曲、播放/暂停、下一曲、音量 −/+
控件只用这 6 类：airui.win / label / button / slider / container / shape。
需要别的控件（table/chart/tabview/textarea/keyboard…）时，先停下来告诉我理由和降级方案，我确认后再动。

# 功能
1. 音源：扫 SD 卡 /sd/music/ → /sd/audio/ → /sd/mp3/ → /sd/ 根，含一级子目录，
   扩展名 mp3/wav/amr，按路径字典序；一首都没扫到就播脚本内置 res/*.mp3 兜底。
2. 音频后端：优先 audio_v2（真暂停 + DMA 进度），退回 exaudio，都没有则进"演示时钟"模式（画面照常走）。
3. 歌词：同名 .lrc 自动查找（同目录 / /sd/lyric/ / /sd/lrc/ / /sd/lyrics/，大小写都认）。
   支持 [mm:ss.xx]、[mm:ss.xxx]、[mm:ss:xx] 三种变体、一行多时间戳、[ti:][ar:][al:][by:][offset:]。
   网易云那种文件头带 JSON 的歌词，跳过 JSON 行只取标准 LRC。
4. 播放模式：顺序 / 随机 / 单曲循环，播完自动续播。
5. 交互：点行播放、翻页、上一/下一曲、暂停继续、音量滑块与 ±5、5 个风格键。
6. 五种舞台风格（给视觉目标和图元上限，具体细节你自己设计）：
   唱片    黑胶盘 + 沟槽 + 旋转高光 + 唱臂 + 进度环              ≈110 图元
   歌词    7 行柔性滚动 + 当前句高亮 + 卡拉OK 进度 + 上浮光点     ≈30 + 7 label
   柱状    32 段柱 + 倒影 + 峰值帽 + 扫光                         ≈100
   波形    三层相位波形 + 网格 + 播放游标                         ≈140
   玻璃    多层光晕 + 涟漪 + 旋转高光 + 环绕光点                  ≈40
   注意：本平台没有 PCM 出口，频谱是合成的（多路正弦 + 节拍包络），不要试图读真实音频数据。

# 文件分工（每个文件单一职责，不要堆在 main.lua）
main.lua            上电时序、显示/触摸/背光初始化、任务编排
exd_<型号>.lua      屏显示 IC 初始化（只做显示，不管供电/背光/触摸）
ui_theme.lua        设计令牌：配色、布局坐标、字号、帧率预算 —— 全项目唯一的坐标来源
fx_core.lua         绘图工具库：图元对象池、颜色混合/明暗、时间格式化、文本裁剪
lrc.lua             歌词解析与查找
app_audio.lua       音频后端、SD 挂载与扫描、播放列表、播放控制、进度、歌词加载
ui_styles.lua       五种画面的绘制
ui_main.lua         界面搭建、交互、逐帧调度

# 硬约束（违反会直接崩或明显掉帧）
- 所有位置/尺寸/颜色/角度必须是整数：set_pos/set_color 走 luaL_checkinteger，传浮点抛
  "number has no integer representation" 会重启 VM；shape:set_items 更糟，浮点被静默转 0，图元凭空消失
- sys.wait / rtos.timer_start 的等待值必须取整（24.999999 会抛错）
- 图元必须走对象池复用，禁止每帧 new 几百个表（150 图元/30fps = 每秒 4500 个临时表，GC 会肉眼可见卡顿）
  池的 finish() 要把尾部置 nil —— set_items 用 lua_rawlen 取长度，残留会画出上一帧的图元
  每个写入方法都要写满该图元的全部字段，不能依赖上一帧的默认值
- 每帧图元预算 <150；主循环帧节拍 33ms（≈30fps）；面板文字/进度 200ms 刷新一次
- 字号控制在 8 档以内（hzfont 字形缓存有限，档位多了会反复栅格化）
- 点击回调里禁止做文件 IO 和换曲（会阻塞几十毫秒），一律 cmd() 入队，由 pump 任务串行执行
- 暂停 = dt 传 0 且视觉时间不推进，不要额外加状态位；唱片停转、频谱定格靠这一条自然实现
- 风格懒加载 + set_hidden 隐藏不销毁，反复切换不能涨内存
- 文字只在内容变化时 set_text，比较结果缓存在表里

# 已知坑（不要再试错，直接按结论实现）
- fatfs.mount 的 auto_format 必须 false，否则会格式化用户卡
- DAC 模式只有 exaudio.setup({model="dac", pa_ctrl=<n>, pa_on_level=<n>}) 才配好功放，否则无声
- 要真暂停和准确进度，必须自己调 audio_v2.play() 拿 request_index；
  exaudio 把它藏在内部变量里，业务层拿不到。调 av2.play 前先 exaudio.pm(exaudio.RESUME)
- 起播瞬间不能立刻判"播放结束"：av2 要连续 3 次 is_busy=false，exaudio 要 >800ms
- mcu.ticks() 是 tick（约 20ms/tick），必须按 mcu.hz() 折算成毫秒，且是 uint32 要处理回绕
- io.lsdir 单次上限 100 条需要翻页，d_size 可能恒为 0
- LRC：先剥 UTF-8 BOM；offset 语义是"展示时刻 = 时间戳 - offset"；
  tonumber(s:gsub(...)) 必须写成 tonumber((s:gsub(...)))，否则替换次数被当成进制
- 固件没有 iconv，歌词只认 UTF-8；识别到非法序列只提示"请转成 UTF-8"，不能让乱码刷屏
- MP3 时长按首帧码率估算（CBR 准，VBR 偏）；结果 >4 小时按 0 处理，UI 显示 --:--

# 启动顺序（顺序错了会花屏或"点不动"）
1 供电：背光占空比先给 0、LCD 供电、SD_EN、PA 关断、i2c 400kHz
2 exd.setup() 显示初始化（复位 + RGB 时序 + 帧缓冲）
3 airui.init() + font_load(hzfont, cache 3072) + set_rotation(0)
4 ui.build() —— 只创建控件，不做耗时操作
5 触摸初始化 + airui.device_bind_touch()，必须在动画任务之前
  （否则表现为"日志说初始化完成但点不动"）；tp.init 必须带 w/h，缺了会被 input 适配器静默拒绝
6 起音频任务（SD 挂载 + 扫歌要几百毫秒，不能挡主流程）和逐帧动画任务
7 界面就绪后再点亮背光（否则上电花屏）

# 交付节奏（严格按序，每步等我确认再继续）
第 0 步：文本线框图 + 每区控件清单与坐标 + 你要用的 airui API 清单
        每项标注「已确认 / 待确认」；待确认的只读 luat_lib_airui_<控件>.c 里对应的那一个函数，
        不要整文件读。超过 3 个 API 拿不准就停下来问我，不要边猜边写。
第 1 步：ui_theme + fx_core + lrc（纯逻辑，可先在 PC 模拟器单独验证）
第 2 步：骨架跑起来 —— 静态布局 + 空舞台，PC 模拟器无报错
第 3 步：音频 + 列表 + 全部交互
第 4 步：五种风格 + 逐帧动画
第 5 步：README（布局表、SD 目录约定、LRC 格式、已知限制、调优旋钮）

# 验收
- PC 模拟器：用 bsp/pc 下的构建脚本编译，luatos-lua.exe 跑起来不报错
- 8 个 .lua 全部通过语法/加载检查
- LRC 解析用 5 首真实网易云歌词验证（含一行多时间戳、offset、三位小数、JSON 头跳过）
- 串口最后打印「音乐播放器已就绪」
```

# B. 复用指引

## B1. 哪些段落可以长期照抄（骨架，约 40%）

| 段落 | 为什么可复用 |
|---|---|
| `环境基线` | 换成新板子只需改型号与引脚，结构不变 |
| `控件白名单 + 熔断规则` | 这是 AirUI 通病：未验证控件必然导致读绑定源码 |
| `硬约束` | 整数陷阱、对象池、帧预算、字号档位，与业务无关 |
| `启动顺序` | 上电时序在任何 AirUI 项目上都一样（背光最后点、触摸在动画前） |
| `交付节奏` | 第 0 步先出 API 清单，是通用抗返工手段 |
| `验收` | 换成新项目的验收项即可 |

## B2. 哪些段落是一次性的（约 60%）

| 段落 | 为什么 |
|---|---|
| `五区布局坐标` | 与屏幕分辨率、功能数量强绑定 |
| `功能` | 业务本身 |
| `五种风格` | 视觉设计，每个项目都不同 |
| `已知坑` | 这些是**这次踩出来的结论**：换音频后端、换硬件、换控件都会变 |

## B3. 换新功能时怎么用

1. 抄 A 段全文。
2. 改 `<占位符>`（见 B4 表）。
3. 替换 `界面 / 功能 / 文件分工` 三段为新功能。
4. **删掉 `已知坑` 整段**——没趟过的坑写不出来，硬编会误导 AI。
5. 先按 `交付节奏` 只发第 0~2 步，拿到骨架确认后再发 3~5 步。
6. 新趟出来的坑，追加回本文档 A 段 `已知坑` 里，下次就变成骨架。
