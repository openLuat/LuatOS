# WIDGET GALLERY 大屏组件橱窗（Air8607 + 10 寸 1024x600）

> 18 个工业看板组件的橱窗：**仪表 / 图表 / 状态**三组各 6 张卡，3 列 x 2 行同屏对比。
> **零图片素材**，环形进度、指针表盘、液位、热力图、雷达、时间轴全部由 `airui.shape`
> 的 `line / circle / rect / ellipse` 图元每帧实时计算。
> 数据来自 `app/demo_data.lua` 本地模拟（确定性 LCG，固定种子 20261023），不联网、不读传感器。

- 适用固件：`luatos@air8607@10i_v0`
- 适用硬件：Air8607 大屏音视频最小系统板（Air1603）+ 10 寸 RGB 屏 1024x600（免序列）+ GT911 电容触摸
- 画布与动画：`airui`（版本看串口 `大屏组件橱窗已就绪` 日志），`airui.set_rotation(0)`，主循环节拍 30ms
- 作者：江访
- 编码 / 换行：UTF-8 / LF

## 这台 APP 是什么

它要回答的问题只有一句：**看板上常见的那些部件，用 `airui.shape` 画出来能有多好看**。
所以视觉上刻意做得中性克制——深空蓝底、卡片只留 1px 描边 + 一道顶部高光，
颜色全部由组件本身提供；橱窗里最亮的东西永远是"正在变化的那个数"。

顶栏 HUD 两行：上行 = 标题 + 当前分组名 + `FPS 脚本/LVGL`；下行 = 分组说明 + `图元 n  计算 x.xms  HH:MM:SS`。
`FPS` 的第一个数是本脚本的动画更新率，第二个数来自 `airui.debug()`，是 LVGL 真实的画面刷新率——
两者对比就能判断慢在哪：计算耗时高 + 两个 FPS 都低 = 脚本侧吃亏；计算耗时低 + LVGL FPS 低 = 渲染刷屏侧吃亏。

## 交互

| 操作 | 效果 |
|------|------|
| 点「仪表 / 图表 / 状态」 | 切分组：旧组 `set_hidden(true)`，新组首次进入才 `build`；重复点当前分组直接返回，不重绘 |
| 点「自动轮播」 | 开 / 关自动轮播（上电默认开），开着时每 8 秒自动切下一组，三组循环 |
| 无操作 | 数据自己在动：曲线每 0.35 秒推一格，仪表 / 柱状 / 雷达每帧平滑趋近 |

没有滑块、没有长按、没有二级页面——这台是橱窗，交互只负责"看哪一组"。
按钮一律走 `on_click`（`on_pressed` 在本板触发不了，见设计取舍 10）。

## 数据源（`app/demo_data.lua`）

UI 只读字段、不关心来源，真机联调时把 `D.tick(dt)` 换成真实采集回调即可，组件代码一行不用改。

| 容器 | 内容 | 值域 |
|---|---|---|
| `series` | temp / hum / co2 / lux / flow / power 六条趋势，各 48 点 | 0..1 归一化 |
| `raw` | 与 series 同步反算的带单位读数 | temp 18..34 C、hum 35..90 %、co2 400..1400 ppm、lux 0..120 klx、flow 0..60 m3/h、power 80..400 kW |
| `gauge` | a / b / c / d 四个仪表读数 | 0..1 |
| `bar` | 柱状 10 根 | 0..1 |
| `spark` | 4 条火花线，各 48 点 | 0..1 |
| `dev` | 12 台设备：`state`（1 运行 / 2 待机 / 3 告警 / 4 离线，由 `simT` 缓慢翻转）+ `load` + `tag` | load 0..1 |
| `alarms` | 5 条告警：`level`（1 提示 / 2 注意 / 3 严重）+ 文案 + 来源 + 相对秒（每秒 +1） | — |
| `radar` | 6 轴 | 0..1 |
| `heat` | 12 列 x 4 行 | 0..1 |
| `kpi` | oee / output / yield / cycle / energy / down | 带单位真实值 |
| `clock` | 从 08:30:00 起走的模拟时钟 | `clock_str()` → `HH:MM:SS` |

- **确定性随机**：自带 LCG（`seed = seed * 16807 % 2147483647`），固定种子 **20261023**，
  每次开机序列完全一致，截图、比对、复现问题全都做得到（`math.random` 做不到）。
  LCG 只在 `init` 里消耗；运行期会变的量（设备状态、告警相对秒）一律由 `simT` 推——
  伪随机序列一旦按帧数消费，换个帧率画面就变了。
- **平滑值噪声**：`noise1(x)` 一维 smoothstep 插值，曲线有起伏但不毛糙。
- **采样与帧率解耦**：曲线按固定步长 `SAMPLE_SEC = 0.35` 秒推一格，跑 20fps 和 30fps
  时曲线推进速度一致；仪表 / 柱状 / 雷达则每帧按 `dt` 平滑趋近目标。
- **单位换算只在一处**：给图元画的量一律 0..1 归一化，给 label 显示的量才带单位，
  绘图代码里不做量程换算。
- `kpi.energy` / `kpi.down` 只在数据源里维护，本版 KPI 卡只用前四项。

## 硬件引脚

与 `module/Air8607/project/factory/config/eng_8607_10i_v0.lua` 对齐：

| 功能 | 引脚 |
|---|---|
| LCD 复位 | pin_rst = 15（`exd.setup({ pin_rst = 15 })`） |
| LCD 供电 | pin_pwr = 17（`gpio.setup(17, 0)` 低有效） |
| 背光 | PWM3 (GPIO13)，`pwm.setup(3, 1000, 0)` 上电占空比 0，就绪后 100 |
| 触摸 | I2C1 400kHz（`i2c.setup(1, i2c.FAST)`），GT911 pin_rst = 14，pin_int = 51，`int_type = tp.FALLING` |

`tp.init` 的 `w` / `h` 必须传（`1024 / 600`）：缺了会让 input 适配器以 EINVAL 静默拒绝，
表现为"日志说初始化完成但点不动"。

## 启动流程

1. `power_on()` —— 背光 PWM3 占空比 0 / LCD 供电 / 复位脚 / I2C 引脚配置
2. `exd.setup({ pin_rst = 15 })` —— 显示初始化（复位 + RGB 时序 + 帧缓冲），失败直接 return
3. `airui.init(1024, 600)` + `airui.set_rotation(0)` + `airui.font_load` 载齐 11/13/16/22/26/30/48/64
4. `airui.debug(true)` —— 打开 AirUI 内置性能统计（HUD 第二个 FPS 的数据源）
5. `ui_main.build()` —— 搭橱窗：顶栏 HUD + 舞台 + 分组切换栏，默认进「仪表」组
6. `touch_init()` —— GT911 初始化 + `airui.device_bind_touch`（**必须早于动画任务**）
7. `ui_main.run()` —— 30fps 主循环（数据模拟 + 分组绘制 + HUD 刷新 + 自动轮播）
8. `backlight_on()` —— 界面就绪后点亮背光，防上电花屏

脚本必须平铺——require 用的是裸文件名（`require "theme"`、`require "wg_gauge"`），
带路径会找不到。

PC 模拟器：`bsp/pc/` 按 `build_windows_32bit_msvc_gui.bat` 出 GUI 版可直接跑界面。
模拟器上 `mcu.hz()` 不可用，`init_timebase` 会退回"1 tick / ms"，动画速度与真机一致。

## 实现要点

### 图元预算

| 分组 | 图元数（实测） | 主要构成（分段数取自代码） |
|---|---|---|
| 仪表 gauge | 约 326 | 环形 24 格刻度 + 三环 20/17/14 颗点串；指针表 22 点进度弧 + 17 格刻度 + 7 根红条；液位罐 + 3 根细管；分段条 4 行 x 12 格；扇形 14 扇区 x 2 圈；刻度尺 11 格 x 2 + 3 段区间带 |
| 图表 chart | 约 337 | 面积 18 柱（每柱 1~3 段）+ 18 点顶线；折线 4 路 x 11 点；柱状 10 柱；火花线 4 行 x 10 点；热力 12x4 = 48 格 + 12 段色标；雷达 3 圈 x 6 边 + 6 轴 + 6 点 |
| 状态 status | 约 250 | 设备 3x4 = 12 格（每格 4~6 图元）；告警 5 行；进度环 3 x 18 点 + 总进度条；KPI 4 x 10 点；步骤 5 道 x 3 图元；时间轴 5 节点 |

`airui` 是 LVGL 之上的图元合成，图元数直接决定每帧的遍历与绘制开销：
**每页控制在 350 以内**，超过 30fps 就开始吃力（HUD 的「图元」读数可以自证）。
所以面积图用 18 根柱而不是 48 根、折线降采样到 11 点、热力图不画描边、火花线 10 点。

`label` 对象同样计入 LVGL 开销：三组组件文字合计 **116** 个（gauge 23 / chart 24 / status 69），
另有 HUD 5 个。每个 label 的 `set_text` 都会重排文本并多出一块脏区，所以读数走 200ms 节流。

### 一个分组 = 一个 shape + 一批 label

6 张卡的动态图元全部写进同一个图元池，一帧只 `set_items` 一次：

```lua
-- build：画布先建（后建的子对象画在上层，画布建晚了会盖住所有 label）
o.shape = airui.shape({ parent = parent, x = 0, y = 0,
    w = T.inner.w, h = T.inner.h, items = {} })

-- update：每帧
P:reset()
obj.n = P:finish()
obj.shape:set_items(P.items)
```

若每张卡各挂一个 shape，LVGL 每帧要遍历 6 个对象、算 6 个脏区，开销直接翻倍而看不出好处。

### 时间基准与节拍

```lua
-- tick 必须经 mcu.hz() 折算：Air1603 约 20ms/tick（hz=50），PC 模拟器 1ms/tick
local hz = mcu and mcu.hz and mcu.hz()
if type(hz) == "number" and hz > 1 then
    TICKS_PER_MS = hz / 1000        -- hz=50 -> 0.05，即 1 tick = 20ms
else
    TICKS_PER_MS = 1                -- PC 模拟器：ticks 本身就是毫秒
end
```

- **动画步长用固定 30ms**，只有真的挂起过（实测超过 3 帧）才按真实时间补跳；
- **补偿式 `sys.wait`**：`sys.wait(x)` 是"至少睡这么久"，工作越重帧率越低会自我恶化，
  这里按实测耗时把睡眠补回来：

```lua
local w = T.perf.frame_ms - cost     -- 30ms 减去本轮实测耗时
if w < 2 then w = 2 end              -- 下限 2ms，别睡死
sys.wait(w)
```

## 已知限制与回退检查单

- [ ] **上电花屏**：背光在 UI 就绪后才点亮，检查 `power_on()` / `backlight_on()` 的顺序
- [ ] **触摸点不动**：`tp.init` 的 w/h 必须传（缺了 EINVAL 静默失败）；触摸绑定必须早于起动画任务
- [ ] **显示初始化失败直接 return**：查 pin_rst=15 / pin_pwr=17 与 `exd_air8607_rgb` 的 RGB 时序
- [ ] **动画慢 20 倍 / FPS 虚报 299**：时间基准没按 `mcu.hz()` 折算，把 tick 当 1ms 用了
- [ ] **动作一顿一顿**：动画 dt 用了 tick 差（tick 分辨率 20ms 比 30ms 帧间隔还粗）
- [ ] **帧率越跑越低**：主循环用了 `sys.wait(固定值)` 而不是补偿式 `frame_ms - cost`
- [ ] **label 全被图元盖住**：`airui.shape` 必须先于 label 创建（LVGL 后建的子对象画在上层）
- [ ] **卡片整体偏移 (15, 65)**：在 `wg_*.lua` 里写了屏幕绝对坐标，卡片矩形是舞台内容区相对坐标
- [ ] **按钮没反应**：`on_pressed` 改 `on_click`
- [ ] **图元"莫名消失"**（宽度 / 透明度变 0）：图元字段传了小数，必须过 `fx.int` / `math.floor`
- [ ] **文字显示方框**：hzfont 缺 `·` `°` `×` `±` `Ω` `μ`，界面文本只用 ASCII + 中文 + `/`
- [ ] **HUD 图元数 > 350 开始掉帧**：减柱数（`COLS=18`）、降采样（`DOWN=11`）、热力格别描边

真机现状（这版就是这么画的，不是 bug 但要知道）：

- **工艺步骤的当前工序 `cur = 3` 写死**在 `wg_status.draw_step`，不随数据变（演示取舍）。
- **`kpi.energy` / `kpi.down` 未上屏**，KPI 卡只用 oee / output / yield / cycle 四项。

## 设计取舍记录

1. **时间基准：`mcu.ticks()` 必须按 `mcu.hz()` 折算**。
   Air1603 约 20ms/tick（hz=50），PC 模拟器 1ms/tick。把每个 tick 当 1ms，
   整条时间轴缩放 20 倍——动画慢 20 倍、FPS 还虚报成 299（因为 20ms 里能跑完的活
   被算成"每帧只花 1ms"）。`hz <= 1` 时按 1 tick/ms 处理，两个平台都能算对。
2. **动画步长用固定 30ms，不用 tick 差**。
   tick 分辨率 20ms 比帧间隔 30ms 还粗，拿 tick 差当 `dt` 得到的是 20/40ms 的抖动值，
   指针会一顿一顿地跳。`sys.wait` 是 1ms 精度的软件定时器，固定步长反而最平滑。
   只有实测挂起超过 3 帧才按真实时间补跳，且 `dt` 限幅到 0.25s 以内。
3. **补偿式 `sys.wait`**。`sys.wait(x)` 是"至少睡这么久"，工作越重 → 帧越慢 →
   一帧里塞的工作越容易被挤 → 更慢，会自我恶化。按实测耗时补回来
   （`wait = 30 - cost`，下限 2ms）才能稳住帧率。
4. **一个分组 = 一个 shape + 一批 label**。6 张卡的动态图元写进同一个图元池，
   一帧只 `set_items` 一次。每张卡各挂一个 shape 的话 LVGL 每帧要遍历 6 个对象、
   算 6 个脏区，开销翻倍而看不出好处。
5. **分组懒加载 + `set_hidden`，不销毁重建**。切分组只隐藏旧 root、首次进入才 `build`，
   开机只付第一个分组的开销，也避免反复创建/销毁 LVGL 对象。
   root 是透明容器，隐藏它即隐藏整组（label 目前没有 `set_hidden` 接口）。
6. **z-order：shape 画布必须先于 label 创建**。LVGL 后建的子对象画在上层，
   画布建晚了会盖住下面所有 label，而且这种"看不见文字"的 bug 极难定位。
7. **坐标空间：卡片矩形是舞台内容区相对坐标**。分组 root 挂在舞台内容区原点（15, 65）上，
   卡片与 shape 都以它为父，写屏幕绝对坐标会整体偏移 (15, 65)。
   卡内图元再由 `content()` 从卡片矩形推导，两级都不写魔法数。
8. **图元预算：每页 ≤ 350**。超过 30fps 开始吃力（实测 gauge=326 / chart=337 / status=250）。
   预算不够用时的取舍顺序是：先降采样点数，再减分段，最后才动布局。
9. **文字节流：200ms 节拍 + 文本去重**。`set_text` 会让 LVGL 重排文本并额外产生一块脏区，
   29 处卡片读数每帧刷就是每秒上千次。三个 `wg_*.lua` 各带一个 `put(lb, txt, o)` 助手，
   `M.update` 开头按动画时间算节拍（`local beat = math.floor(t * 5)`，即每 0.2s 一格），
   `put` 只在 `o._hot` 为真、且文本与 `o._tx[lb]` 缓存不同时才真的 `set_text`。
   节拍从 `t` 推而不取外部时钟，换了帧率文字刷新仍然稳定在 5Hz；
   `o._tx` 以 label 对象为键，值没变连重排都不发生。
10. **按钮必须用 `on_click`**。`on_pressed` 在本板连点击都触发不了
    （agri_greenhouse / airui_showcase 验证过的结论）。`M.select` 内部有
    `curIdx == i` 的重复调用保护，连点同一按钮不会重建。
11. **图元字段必须是整数**。C 层用 `lua_tointeger` 读整型字段，传入 3.7 这种
    非整数浮点会**静默变 0**（Lua 5.3 只接受"整数值的浮点"）——宽度变 0 被夹成 1、
    透明度变 0 直接看不见，不报错，只在真机上"某个物件莫名消失"。
    所以 `fx.pool` 的所有写入方法都统一取整，坐标一律 `math.floor`。
12. **hzfont 缺字**。库里没有 `·` `°` `×` `±` `Ω` `μ`，用了显示方框。
    界面文本只用 ASCII + 中文 + `/`：温度写 `C`、光照写 `klx`、流量写 `m3/h`、
    频率写 `Hz`、百分号直接 `%`。
13. **面积 / 弧的画法**：`airui.shape` 只有 `line / circle / rect / ellipse` 四种图元，
    **没有多边形填充、也没有圆弧图元**。面积用一根根竖直矩形堆出来
    （顺带每根柱按高度做透明度渐变，比纯色填充好看）；粗弧用点串逼近。
    `fx.lua` 的 `P:arc` 用折线逼近时踩过"珠子"：圆头线段在顶点处鼓出半径 w/2 的半圆帽，
    当弦长小于线宽时（半径 180、线宽 13、8 段跨 30° 就是典型）会连成一串珠子。
    正确做法是线段一律平头画、两端单独补实心圆，段数按弦高 ≤ 0.5px 取。
14. **图元表池化**。每帧要重建 300+ 个图元表，每帧新建 Lua 表就是每秒上万个临时表，
    GC 周期性回收会带来肉眼可见的顿卡。`fx.pool` 复用同一批表，`finish()` 把尾部残留置 nil
    ——`shape:set_items` 用 `lua_rawlen` 取长度，尾部留旧表会把上一帧的图元也画出来。
    同理每个写入方法都重写该图元的**全部字段**，不依赖"上一帧的默认值"。
15. **数据用确定性 LCG，不用 `math.random`**。种子受平台实现影响时每次开机画面都不一样，
    截图、比对、复现问题全都做不到。固定种子 20261023 后，同一固件每次上电画面完全一致。
