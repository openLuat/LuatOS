# Air8784 AirCloud SIP 通话与任务配置示例

## 一、项目概述

本示例使用 Air8784、Air1103 和 AirCloud，实现设备与 SIP 软终端通话、两台设备互通、多设备轮拨，以及设备侧蜂窝电话与 SIP 之间的通话桥接。用户在网页配置任务，设备保存配置后，通过本机按键发起或停止通话。

本工程使用 4G 联网，一个设备只保存一个当前任务。任务类型分为 pair、round、phone；运行分支分为 single 和 phone，同一时间只加载一套通话与音频模块。

## 二、演示功能

| 场景 | 网页入口 | 任务类型 | 发起设备运行分支 |
| --- | --- | --- | --- |
| 设备与手机/电脑 SIP 软终端通话 | 双设备互通，目标选择本机对端账号 | pair | single |
| 两台 Air8784 设备互通 | 双设备互通 | pair | single |
| 按顺序呼叫多个设备或软终端 | 多设备轮拨 | round | single |
| 蜂窝电话与 SIP 通话桥接 | 设备与手机 | phone | phone |

pair 任务只有一个目标，round 和 phone 最多有三个目标。任务等待接听时间固定为 30 秒。轮拨过程中，未接通的目标结束后才会尝试下一目标；一旦某个目标接通，本轮后续不再继续拨打其他目标。

网页下发配置不会自动开始通话。发起设备通过 SOS 按键执行任务，UP 按键停止通话。single 分支收到来电时，SOS 用于接听。

任务保存并就绪后，本机会尝试播放“任务已生效”；没有主动任务的接收设备在运行模式发生切换并就绪后，播放两声短音。提示并非保存回执，具体触发条件及资源要求见第八章。

## 三、准备硬件

### 3.1 硬件清单

- Air8784 开发板及配套天线。
- 能正常联网的 SIM 卡；测试手机通话桥接时，还需具备可用的蜂窝语音业务。
- Air1103 音频模块、麦克风与喇叭。
- USB 数据线及稳定电源。
- 测试设备互通或轮拨时，准备相应数量的设备；测试软终端通话时，准备手机或电脑。

### 3.2 接线与按键

下面为当前脚本使用的配置，烧录前请与实际开发板原理图核对。

| 项目 | 当前配置 | 说明 |
| --- | --- | --- |
| Air1103 音频串口 | Air8784 UART1 | TX、RX 交叉连接，双方共地 |
| Air1103 电源控制 | GPIO22 | single_config.lua 中配置；single 和 phone 分支共用 |
| 按键参考电平 | GPIO23 | sip_task_keys.lua 中设置为高电平 |
| SOS 按键 | GPIO20 | 上拉输入，下降沿触发 |
| UP 按键 | GPIO21 | 上拉输入，下降沿触发 |

按键防抖时间为 150 ms。GPIO22 是脚本中的电源控制配置，具体供电接法以硬件电路为准，不应把普通 GPIO 的高电平输出当作 Air1103 的供电电源。

## 四、准备软件与配置

### 4.1 烧录工具与固件

使用 [Luatools](https://docs.openluat.com/air780epm/common/Luatools/) 烧录适配 Air8784 的底层固件和本目录全部 Lua 文件，并保留工程所需的默认核心库、扩展库。

**同时将本目录的 tv_ok.pcm 加入烧录文件，确保设备上可通过 /luadb/tv_ok.pcm 读取。** 该文件为 16 kHz、16 bit、单声道原始 PCM，不要用 WAV、MP3 文件直接改名替代。FOTA 更新时也需保留该资源。

当前 main.lua 的项目名称为 AIR8784_SIP_AIRCLOUD_SETTING，版本为 001.001.005。后续版本以实际代码为准。

固件必须支持实际选择的通话功能：

- SIP_CC 桥接需要相应的蜂窝电话及 SIP 桥接能力。
- single 与 phone 之间切换需要 cc.setBridge 和 rtos.reboot；缺少相关接口时，设备仅上报支持 phone 任务。
- 单 SIP 音频还需要 voip 的 PCM 输入、输出及重采样能力，以及 audio_v2、Air1103 支持。

桥接通话正常并不代表单 SIP 音频接口一定齐全。应结合初始化日志与网页读取到的能力、状态确认固件是否适配，不要仅凭版本号判断。

工程使用 sys、sysplus、exsip、exaudio、air1103、excloud 等库，并由它们加载相关依赖。FOTA 默认使用 libfota2。不要只烧录 main.lua，也不要混入其他 SIP 示例中的同名业务文件。

新增提示音使用 air1103.play_direct，phone 分支硬件就绪检查使用 air1103.get_rx_stats。请使用与当前工程配套的扩展库；旧库缺少这些接口时，可能无法播放提示或无法确认音频就绪。

### 4.2 SIP 与音频参数

| 文件 | 需要核对的内容 |
| --- | --- |
| main.lua | AirCloud 项目标识、FOTA 相关配置 |
| bridge_config.lua | SIP 服务器、端口、账号、认证信息、对端 URI、Air1103 串口与本地音频选项 |
| single_config.lua | 单 SIP 的串口、电源控制、喇叭档位、MIC 软件增益等 |
| task_voice_config.lua | 任务提示开关、提示音量、PCM 资源路径与超时时间 |

single_config.lua 复用 bridge_config.lua 的 SIP 连接参数。请使用实际分配的账号和认证信息，不要将文档中的占位内容作为可用账号。

本工程默认账号约定如下：

| 对象 | SIP 账号 |
| --- | --- |
| 设备自身 | 设备的 15 位 IMEI 后追加 0 |
| 该设备对应的软终端 | 同一 IMEI 后追加 1 |
| 网页选择其他设备时 | 选择其 15 位 IMEI，设备侧自动转换为 IMEI 后追加 0 |

### 4.3 配置手机或电脑 SIP 软终端

网页的“单设备体验”页面提供软终端配置说明。使用默认服务器时，可按下表填写；如已更换服务器，以自己的部署参数为准。

| 参数 | 填写内容 |
| --- | --- |
| 用户名/注册账号 | 本设备 IMEI 后追加 1 |
| 认证用户名 | 按服务器要求填写，通常与注册账号一致 |
| 密码 | 实际分配的 SIP 密码 |
| SIP 服务器/域名 | cc.luatos.com |
| 端口 | 8910 |
| 传输协议 | 按软终端和服务器配置选择 TCP 或 UDP |

不同软终端的字段名称有所不同。部分客户端在服务器地址中填写端口；MicroSIP 可在代理服务器字段填写 cc.luatos.com:8910。

软终端注册成功后，呼叫“设备 IMEI 后追加 0”可呼叫该设备。phone 分支的固定 SIP 对端由 bridge_config.lua 中的 remote_sip_uri 决定，修改账号约定后需一并核对。

## 五、网页端操作

控制台地址：[AirCloud SIP 配置控制台](https://iot.luatos.com/ai_app/luatos/SIP_setting/tasks.html?mode=pair)。

以下操作名称与流程按当前公开网页代码整理。控制台需要登录后才能读取和操作账号下的设备。

### 5.1 登录并确认设备

1. 打开控制台，按照页面提示使用合宙 IoT 账号登录。
2. 进入“我的设备”，确认设备已在当前账号下可见且在线。
3. 当前页面的项目列表筛选名称为 **8784_SIP** 的项目。若列表为空，先核对项目名称、设备归属以及固件中的 AirCloud 项目标识。
4. 进入需要的通话页面，选择项目及发起设备。
5. 点击“读取设备配置”，检查当前任务、运行模式、SIP 注册及音频就绪状态。

选择设备时页面可能先显示平台保存的最近一次快照；需要确认实时状态时，应主动点击“读取设备配置”。AirCloud 在线和 SIP 注册成功是两个独立条件。

### 5.2 双设备互通

以设备 A 呼叫设备 B 为例：

1. 确认两台设备均烧录配套脚本，已联网并接入同一账号可管理的项目。
2. 打开“双设备互通”，填写任务名称，选择 A 为发起设备。
3. 在目标中选择 B。该任务只允许一个目标。
4. 如需保留当前表单，点击“保存任务”；这一步只保存浏览器草稿。
5. 点击“检查并下发”，等待页面完成设备检查、模式准备及任务确认。
6. 页面提示任务配置完成后，按 A 的 SOS 键发起呼叫，按 B 的 SOS 键接听。
7. 按 UP 键停止通话，也可在网页选择相应设备后点击“停止通话”。

接收设备 B 不需要创建反向任务。网页会先检查参与设备，并在需要时将接收设备准备为 single 模式。

A 的任务保存并就绪后会尝试播放“任务已生效”。B 没有主动任务且本次发生模式切换时，就绪后播放两声短音；B 原本已在 single 模式时，不会仅因再次查询配置而重复提示。是否可以通话仍以设备实时状态为准。

测试设备与软终端通话时，在目标中选择“本机对端账号”（本机 IMEI 后追加 1），并确保软终端已注册。该软终端账号不作为 AirCloud 设备参与模式准备。

### 5.3 多设备轮拨

1. 打开“多设备轮拨”，填写任务名称并选择发起设备。
2. 使用“＋ 添加目标”添加目标，最多三个。
3. 使用“↑”调整顺序，使用“×”移除目标；不要重复添加同一目标。
4. 点击“检查并下发”，等待所有参与设备及发起设备准备完成。
5. 按发起设备 SOS 键开始按顺序呼叫。

每个目标等待接听 30 秒。未接通时，设备会先结束当前呼叫并等待通话资源释放，再尝试下一目标。任一目标接通后，本轮轮拨停止推进；这次通话结束后，不会接着呼叫剩余目标。

### 5.4 设备与手机

这里的“手机”指蜂窝电话号码，与手机上安装 SIP 软终端的场景不同。

1. 打开“设备与手机”，填写任务名称并选择设备。
2. 添加手机号码，最多三个；当前脚本接受以 1 开头的 11 位号码。
3. 按需要调整号码顺序，点击“检查并下发”。
4. 若设备原来运行 single 分支，等待其保存配置、空闲重启并重新上线。
5. 确认 phone 分支就绪，且 bridge_config.lua 指定的 SIP 对端已正确注册，再进行通话测试。

可验证以下流程：

- 按设备 SOS 键执行手机任务，按配置顺序尝试呼叫。
- SIP 对端呼叫设备 SIP 账号，设备使用当前 phone 任务中的号码进行手机轮拨。
- 手机呼入设备 SIM 卡号码，由 SIP_CC 分支连接配置中的 SIP 对端。

SIP 来电使用最新保存的 phone 任务号码；缺少可用 phone 任务时，不会使用一组隐藏的备用号码。手机轮拨切换目标前会等待蜂窝通话释放，并保留稳定间隔；若释放超时，则结束本轮，避免上一通尚未结束就发起下一通。

### 5.5 理解保存、下发与就绪状态

| 操作或状态 | 实际含义 |
| --- | --- |
| 保存任务 | 保存当前浏览器中的表单草稿，不修改设备 |
| 检查并下发 | 查询设备状态、准备运行模式、下发任务并复查 |
| 平台接受指令 | 平台已经接收请求，尚不能据此认定设备已保存 |
| 设备保存成功 | 设备已持久化配置，跨模式时仍可能等待重启 |
| 任务配置完成 | 网页已完成本次检查与配置确认，可以按键执行任务 |

当前网页先检查全部参与设备，再准备接收设备，最后配置发起设备并复查。就绪条件包括运行模式一致、没有待重启状态、SIP 已注册、音频已就绪以及通话空闲。

任务提示播放期间，设备任务状态可能短暂显示 busy，新的修改或删除请求也可能被拒绝。等待提示结束后再读取或操作；不能仅凭已经听到语音就判断所有参与设备都已配置完成。

操作期间请保持当前网页可见。切换页面或使页面进入后台可能暂停本次流程，**已经保存到设备的配置不会自动回滚**。返回后先读取设备配置，再按需要重新执行“检查并下发”。

接收设备存在 phone 任务等冲突时，网页可能终止本次配置并提示处理冲突。应按提示确认接收设备用途后再调整。

### 5.6 停止、删除与切换任务

- **停止通话**：向选中设备发送停止请求。请求受理后，需等待设备结束通话；可再次读取状态确认。
- **删除任务**：在确认对话框中确认删除设备当前任务。删除不会清除浏览器草稿，也不会自动切换设备运行模式。
- **pair 与 round 互换**：都使用 single 分支，通常不需要重启。
- **phone 与 pair/round 互换**：需要切换运行分支。设备保存后标记待重启，至少等待 3 秒，并确认通话和媒体均空闲后才重启。
- **设备正在通话**：修改、删除任务或切换模式可能被拒绝。先停止通话并确认空闲，再重试。

任务与运行模式独立保存。首次没有已保存模式时默认使用 phone 分支；删除 single 任务后仍可保持 single 模式接听来电。清除 Flash 数据可能同时清除持久化任务及模式。

## 六、代码运行流程

1. main.lua 加载系统库并启动 4G 网络。
2. sip_runtime.lua 根据持久化运行模式选择 single 或 phone 分支。
3. 对应业务模块初始化 SIP 和音频。
4. sip_task_adapter.lua 对接任务引擎及 AirCloud 控制。
5. 网页指令经 AirCloud 下发，设备校验后保存配置并上报结果；需要切换分支时等待空闲重启。
6. SOS 触发任务或接听来电，UP 停止通话；任务执行期间继续上报状态。

任务保存或运行模式改变时，任务引擎会持久化待提示标记。当前分支与保存模式一致，且 SIP、音频、通话状态连续满足播放条件约 1 秒后，先清除该标记，再触发本地提示。跨模式时由重启后的目标分支完成提示。

任务协议标识为 air8784.sip.v1。设备通过 AirCloud Tag 19 接收 JSON 指令，通过 Tag 20 上报配置、执行结果与状态。

当前指令包括 get、put、delete、stop、set_mode，分别用于读取、保存、删除、停止与设置运行模式。状态中包含任务版本、支持的任务类型、当前运行分支、保存的运行模式、待重启标志，以及 SIP、音频和通话空闲状态。

配置保存在 fskv 的 sip_task_v1 中。修改使用版本校验，避免旧页面覆盖新配置；遇到版本冲突时，应重新读取后再修改。当前协议未提供网页调整喇叭或麦克风音量的指令。

### 8.1 FOTA 升级

main.lua 启用 update.lua，当前默认使用 libfota2，周期检查间隔为 24 小时。升级配置需要与实际项目及固件匹配。

update.lua 会等待通话与媒体空闲，并保留空闲稳定时间，再进行升级相关操作。可通过 update.check_update 或 FOTA_CHECK_REQ 触发检查；当前任务网页没有对应的升级按钮。

不要仅凭某一个失败返回码判断“没有新版本”；应结合完整升级日志区分无需升级、网络异常及升级失败。

### 8.2 音量参数的作用范围

| 配置项 | 作用 |
| --- | --- |
| single_config.lua 的 volume | 单 SIP 分支本机 Air1103 喇叭档位，范围 0～31，当前为 31 |
| single_config.lua 的 mic_gain | 单 SIP 上行 PCM 重采样使用的软件增益，当前为 2 |
| bridge_config.lua 的 air1103_volume | SIP_CC 分支本地 Air1103 音量设置 |
| bridge_config.lua 的 local_audio_default | 是否默认开启 SIP_CC 本地音频，当前为 false |
| task_voice_config.lua 的 volume | 任务语音及双提示音的本地喇叭档位，范围 0～31，当前为 20 |

修改 MIC 软件增益后，需要重新创建对应重采样器，例如重新启动设备，才能应用到该音频通路。

SIP_CC 两向桥接音频由固件直接转发，不经过 single_audio.lua 的 MIC 重采样器。修改上述本地喇叭或单 SIP MIC 参数，不会改变手机与 SIP 之间的桥接增益。

当前网页及任务协议没有实现远程音量设置，本说明不将其列为已支持功能。

### 8.3 任务生效提示

task_voice_config.lua 的默认配置如下：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| enabled | true | 是否启用任务语音和双提示音 |
| volume | 20 | 提示期间的 Air1103 本地喇叭档位 |
| path | /luadb/ | tv_ok.pcm 所在目录；目录末尾保留斜杠 |
| timeout_ms | 10000 | 单次提示播放超时上限，单位毫秒 |

- 成功保存新的主动任务（put）后，播放固定的 tv_ok.pcm，不朗读任务名称、号码或目标列表。
- set_mode 实际改变运行模式时才设置待提示标记。没有主动任务的接收端就绪后，播放程序生成的两声短音，不依赖额外音频文件。
- 查询、删除任务、重复的同一请求，以及没有模式变化的 set_mode，不会新建一次提示。普通重启仅可能继续尚未消费的待提示任务，不会重播已经消费的提示。
- 播放前需确认无待重启状态、SIP 已注册、音频就绪、通话及媒体空闲，并且没有 Air1103 队列播放占用。
- 提示按每帧 320 字节、约 10 ms 的节奏发送 PCM，不停止 MIC，也不为这次任务提示复位 Air1103。来电进入非空闲状态、SOS 操作或网页停止指令会取消提示。
- 结束、超时或打断后恢复原音量：single 恢复其 volume；phone 根据当前本地音频开关恢复 air1103_volume 或静音。因此 local_audio_default=false 不会禁止任务提示临时发声。

待提示标记在播放前就已持久化清除。禁用提示、资源缺失、播放失败或中途被打断，都不会自动循环重播该提示。没有听到提示不代表任务没有保存，应读取设备配置确认。

### 8.4 phone 分支的 Air1103 就绪检查

audio_drv.lua 复用 single_config.lua 中的电源控制与等待参数，上电后初始化 exaudio，再复位 Air1103 并等待新的 MIC 帧。当前启动等待为 1500 ms，就绪检查最长为 10000 ms，检测到至少三帧新的 MIC 数据后才认为芯片响应正常。

检查结束后，无论成功还是失败，都会停止 Air1103 MIC 上行并关闭接收解析，避免持续上行影响 SIP_CC 消息处理。该分支的手机与 SIP 桥接数据仍由固件转发；Air1103 就绪检查用于确认本地音频及任务提示条件。

若出现 Air1103 no MIC response，应检查供电、GPIO22 电源控制电路、UART1 接线以及扩展库接口。仅 exaudio.setup 返回成功不再等同于硬件就绪；检查失败时 health.audio_ready 为 false，会影响网页的就绪确认和本地任务提示。

## 九、常见问题

| 现象 | 排查方法 |
| --- | --- |
| 网页没有项目或设备 | 核对登录账号、设备归属、8784_SIP 项目名称及 AirCloud 项目标识 |
| 设备在线但不能呼叫 | 分别检查 SIP 注册、音频就绪、运行分支及目标账号，云端在线不等于通话就绪 |
| 无法选择 pair 或 round | 读取设备能力，核对固件是否支持切换及单 SIP 音频所需接口 |
| 点击保存任务后设备没有变化 | 保存仅作用于浏览器草稿，还需点击“检查并下发” |
| 下发成功后没有自动呼叫 | 本工程通过 SOS 执行任务，下发配置本身不拨号 |
| 下发提示忙或版本冲突 | 等待设备空闲，重新读取配置后再操作 |
| 提示播放期间短暂显示 busy | 等提示播放结束后再操作；任务语音也会占用适配器的空闲状态 |
| 没听到“任务已生效” | 检查 enabled、提示音量、/luadb/tv_ok.pcm、play_direct 接口及 SIP/音频就绪状态；读取配置确认任务是否已保存 |
| 接收设备没有双提示音 | 确认它没有主动任务且本次确实改变了运行模式；原本已在目标模式时不会重复提示 |
| phone 分支一直音频未就绪 | 检查 Air1103 实际 MIC 响应、供电、串口和 get_rx_stats 接口，参考 8.4 |
| 检查并下发超时或暂停 | 保持页面可见，核对设备网络及重启后的 SIP、音频状态；重新读取，确认已完成的部分 |
| 删除任务后没有切回 phone | 当前设计将任务和运行模式独立保存，删除任务不切换分支 |
| 手机轮拨失败 | 检查 SIM 语音业务、号码格式、当前 phone 任务、SIP 对端及蜂窝呼叫释放日志 |
| SIP_CC 本机喇叭没有声音 | 核对本地音频开关；默认关闭本地音频与桥接通话本身是不同事项 |
| 调整单 SIP 音量后桥接音量不变 | 两者属于不同音频通路，参考第八章的参数作用范围 |

完成测试后，可将各场景的实际日志补入第七章，并记录所用底层固件版本、脚本版本及接线情况，便于复现问题。
