## 一、产品概述

### 1.1 产品定位

**IRTU 8202G** 是一款基于合宙 Air780EGP 模组的高性价比 4G 定位追踪板，面向**人员、车辆、物品、宠物**等通用定位追踪场景。以「基站定位保底 + GPS 高精度」双定位策略，配合 4 种工作模式，在**实时性**与**续航**之间动态平衡。

### 1.2 目标用户与核心场景

| 用户群 | 典型场景 | 关键诉求 |
| ------ | -------- | -------- |
| 个人用户 | 老人/儿童防走失、宠物定位 | 简单易用、走失时快速 GPS 定位 |
| 行业客户 | 车辆/货物/资产追踪 | 长续航、多设备管理、远程指令 |
| 集成商 | 定位器二次开发 | 接口标准、可配置、可 OTA |

### 1.3 产品核心价值

1. **低成本 4G Cat.1 联网**：无需网关，插卡即用，全国覆盖。
2. **双定位策略**：GPS（精度最高）+ 免费/付费基站（保底），任意环境可用。
3. **4 种工作模式**：未激活/常规/智能/GPS定位，按场景切换，平衡实时与续航。
4. **默认直连 AirCloud**：出厂无需配置，通道1 默认连接合宙云平台，开箱即上报。
5. **硬件安全**：YHM2712A 充电管理 + Air153C 看门狗默认开启，防过充、防死机。

## 三、工作模式定义（核心）

设备共 4 种模式，由 `config.DEVICE_MODE` 定义，模式值持久化存储于 kvstore，切换后重启生效。

| 模式 | 值 | 定位策略 | 上报节奏 | 功耗 | 典型用途 |
| ---- | -- | -------- | -------- | ---- | -------- |
| 未激活 | -1 | 基站 | 600s | 低 | 出厂待绑定 |
| 常规 | 0 | 仅基站 | 300s 固定 | 最低 | 日常省电追踪 |
| 智能 | 1 | 运动中 GPS / 静止基站 | 动态递增 | 中 | 实时与续航兼顾 |
| GPS定位 | 2 | GPS 常开 + 基站备选 | 30s 固定 | 最高 | 走失/寻物紧急定位 |

### 3.1 未激活模式（-1）

**入口**：出厂首次上电 / 恢复出厂后，`kvstore.get_work_mode()` 返回 -1。

**行为时序**：
1. 绿灯 **三长一短** 循环闪烁，指示可绑定状态。
2. 连接云平台（默认 AirCloud 通道1）。
3. 上报 `bind_ready` 消息，通知平台"设备在等待绑定"。
4. 等待服务端下发 `change_mode` 完成绑定。
5. 收到 `change_mode` → 保存模式 → 3 秒后重启进入目标模式。

**LED 指示**：绿灯三长一短循环（可绑定）。

### 3.2 常规模式（0）

- **定位**：仅基站，不开 GPS（最省电）。
- **上报间隔**：固定 300s（可配置，选项 60/300/600s）。
- **特殊节奏**：低电量 1800s / 充电中 60s。
- **运动影响**：不受运动状态影响，始终固定节奏。
- **适用**：长时间静态追踪、续航优先场景（如长期停放的车辆、居家老人）。

### 3.3 智能模式（1）

根据运动状态自动调节定位与上报频率，是「实时性 × 续航」的平衡方案。

**定位切换**：
| 状态 | 定位方式 | 判定 |
| ---- | -------- | ---- |
| 运动中 | GPS（失败降级基站） | 检测到震动即运动中 |
| 静止 | 基站 | 约 10s 无震动恢复静止 |

**上报间隔递增规则**（基础 180s，可配置）：
| 阶段 | 间隔 | 说明 |
| ---- | ---- | ---- |
| 静止第 1 次 | 180s | 基础间隔 |
| 静止第 2 次 | 300s | +120s |
| 静止第 3 次 | 420s | +120s |
| … | … | 每次上报递增 120s |
| 封顶 | 660s | 最多 660s |

**震动触发立即上报**：
- 震动（非冷却期）→ **立即上报一次**。
- 之后进入冷却期（默认 600s，可配置 `motion_cooldown`）。
- 冷却期内震动**不再立即上报**，按定时节奏走。
- 震动**不重置**静止间隔的递增计数。

> 运动状态判定细节：开机默认静止（基站定位）；震动即运动中；持续约 10s 无震动自动恢复静止。

### 3.4 GPS定位模式（2）

- **GPS**：常开，后台持续搜星，不上报时也不关闭。
- **上报间隔**：固定 30s（可配置）。
- **定位**：GPS 优先；有缓存直接用，无缓存走基站备选，不等 GPS。
- **LED 指示**：绿灯 **慢闪 1Hz，持续 10s 后自动熄灭**；每次上报成功重新计时 10s。
- **功耗**：最高，仅用于紧急寻物/走失定位，找到后需切回常规/智能。

## 四、指示灯定义（双 LED）

| 灯 | 引脚 | 常亮场景 | 闪烁场景 | 熄灭场景 |
| -- | ---- | -------- | -------- | -------- |
| 绿灯 | GPIO26 | 充电完成（充满）且 USB 未拔 | GPS定位模式上报后慢闪 1Hz，10s 自动灭 | 拔掉 USB / 非上述状态 |
| 黄灯 | GPIO27 | 插入充电器充电中 | — | 充满 或 拔掉充电器 |

**完整状态机**：

| 状态 | 绿灯 | 黄灯 |
| ---- | ---- | ---- |
| 待机（未充电） | 灭 | 灭 |
| 充电中 | 保持当前逻辑（GPS定位则继续慢闪，否则灭） | 常亮 |
| 充满 | 常亮 | 灭 |
| 拔掉 USB | 非慢闪时灭 | 灭 |
| GPS定位模式上报完成 | 慢闪 1Hz（10s 后自动灭，再次上报重新计时） | 保持 |
| 未激活可绑定 | 三长一短循环 | 灭 |

> 注：GPIO26 复用为 NS2520 电源、GPIO27 复用为 BLE 电源，本板无对应外设，故安全复用为指示灯。

## 五、充电管理（YHM2712A）

### 5.1 功能规格

- 单节锂电池充电管理：**恒流恒压（CC-CV）**、充满自停。
- CMD（STACMD）单总线通信，**空闲必须保持高电平**（长时间拉低会触发芯片内部看门狗复位 → 读 ID 返回 0xFF、设置电流失败）。扩展库已内置 `cmd_idle()` 处理，每次通信后自动恢复高电平。
- 默认开启（`config.CHARGE_CONFIG.ENABLE = true`）。

### 5.2 默认参数（固件）

| 参数 | 默认值 | 说明 |
| ---- | ------ | ---- |
| 充电管理开关 | 开启 | 出厂即生效 |
| CMD 引脚 | GPIO25 | 需与硬件原理图一致 |
| 浮充电压 | 4200mV（4.2V） | 或 4350mV（4.35V 高压电池） |
| 电池容量 | 400mAh | 决定充电电流档位 |
| 充电电流 | DEFAULT（≈225mA） | 可选 MIN / DEFAULT / MAX |

### 5.3 初始化成功标志

```
I/charge YHM2712A 充电初始化成功，pin=25 v_battery=4200 cap_battery=400 i_charge=DEFAULT
```

若读到 `芯片ID: 0xFF`，说明 CMD 空闲电平未拉高或接线异常（见 FAQ）。

## 六、硬件看门狗（Air153C）

### 6.1 功能规格

- 防止程序跑飞导致死机，超时自动复位设备。
- 硬件接线：**AGPIO24 → NPN → WTDOG**。
- 默认开启（`config.WDT_CONFIG.ENABLE = true`）。

### 6.2 关键参数

| 参数 | 默认值 | 说明 |
| ---- | ------ | ---- |
| 看门狗开关 | 开启 | 出厂即生效 |
| 喂狗引脚 | GPIO24 | AGPIO24 → NPN → WTDOG |
| 喂狗周期 | 180s | **必须 > 150s**（Air153C 超时固定 240s 不可改） |
| 超时时间 | 240s（固定） | 超时自动复位 |

> 喂狗周期与超时时间匹配原则：喂狗周期 > 150s（即小于超时的 240s 减去安全裕量）。

### 6.3 初始化成功标志

```
I/air153c_wdt Air153C 看门狗初始化成功，喂狗引脚:24 周期:180 秒
```

## 七、云平台连接（AirCloud 默认通道）

### 7.1 默认连接策略

| 场景 | 连接行为 |
| ---- | -------- |
| **出厂 / 无本地持久化配置** | ✅ **默认通道1 连接 AirCloud**（`config.DEFAULT_NETWORK`：AIRCLOUD/tcp/keepAlive300） |
| 平台下发过 network 配置 | 以服务端 network 为准，`conf_on[i]==1` 才激活（网页端可覆盖） |

### 7.2 AirCloud 通道细节

- 传输：`excloud` 库，TCP 传输（TLV 直发）。
- 通道编号：`cid=1`，订阅 `AIRCLOUD_SEND_1`。
- 上行：`active_mode` 构造 TLV 字段数组 → `create.send_aircloud()` → `excloud.send()`。
- 下行：`excloud.on("message")` → 统一以 `REMOTE_COMMAND` 分发 JSON 指令。
- 心跳：超过 keepAlive（300s）无数据上报时，发送 `RANDOM_DATA`（JSON：csq/eci/rsrp/band）保活。
- 断线重连：`auto_reconnect=true`，间隔 10s，最多 5 次。

### 7.3 配置平台

- 配置平台地址：**https://iot.openluat.com**（网页端定位版参数下发）。
- 设备拉取接口：`https://iot.openluat.com/api/dtu/device/{IMEI}/param?product_name=Air8202&param_ver={ver}&iccid={iccid}`。
- 流程：网页端改参数 → 下发 → 设备后台异步拉取 → 有新版则持久化并**自动重启**生效。

> 网页端默认值：充电 `enable:0`、看门狗 `on:0`（网页端默认**关闭**）；固件默认**开启**。网页端下发时以网页端为准（覆盖固件默认）。仅当无服务端配置时才使用固件默认（含默认 AirCloud 通道）。

## 九、远程指令集（服务端下发）

指令通过云通道下发，JSON 格式，支持两种写法：
- 标准：`{"command":"xxx","data":{"params":{...}}}`
- 扁平：`{"cmd":"xxx", ...}`

| 指令 | 参数 | 说明 | 回复 |
| ---- | ---- | ---- | ---- |
| change_mode | mode: 0/1/2 | 切换模式（保存→重启生效） | 0 ok |
| get_device_data | — | 立即上报一次数据 | 0 ok |
| open_light | status: 0/1 | 开关绿灯 | 0 ok |
| close_device | — | 关机 | 0 ok, shutting down |
| set_report_interval | interval_seconds: 10–86400 | 设置常规上报间隔，重启不丢 | 0 ok |
| update | — | 触发 OTA 升级检查 | 0 ok |
| fota_mode | mode: 2/3 | 切换 FOTA 模式（3=libfota3 仅合宙可升级，2=libfota2 客户自管） | 0 ok |
| call | 不支持 | 无音频硬件 | 4 SIP 不支持 |
| play_sound | 不支持 | 无音频硬件 | 4 音频不支持 |
| set_volume | 不支持 | 无音频硬件 | 4 音频不支持 |

**切换模式流程**：收到 `change_mode` → 校验模式 → 保存到 kvstore → 回复平台 `0 ok` → 3 秒后自动重启 → 进入目标模式。

## 十、低功耗与电源策略

| 条件 | 行为 |
| ---- | ---- |
| 电量 < 20% | 低电量模式：延长上报间隔（1800s）、关闭 GPS、仅基站 |
| 常规/智能上报完成后 | 轻睡眠，等下一次上报 |
| GPS定位模式 | 全功率，不睡眠 |
| 插入充电器 | 上报间隔缩为 60s，GPS 全开，不受省电限制 |
| 拔掉充电器 | 恢复当前模式间隔 |
| 智能模式震动 | 唤醒立即上报，之后重新低功耗；冷却期内震动不唤醒 |

**开机唤醒原因**（`boot_reason`）：power_on / software_reboot / reset_key / exception_reboot / watchdog / external_reboot / charge_power / timer_wakeup / uart_wakeup / pwr_key / chg_det 等。

## 十五、典型使用流程

### 15.1 出厂开箱

```
烧录固件 → 上电 → 绿灯三长一短（未激活）→ 默认连 AirCloud → 上报 bind_ready
→ 平台下发 change_mode(0/1) 绑定 → 重启 → 进入常规/智能模式 → 开始周期上报
```

### 15.2 日常追踪（智能模式）

```
智能模式 → 运动中 GPS 上报 / 静止基站 + 间隔递增 → 震动立即上报（进冷却）
→ 低电量自动降频 → 插入充电器 60s 快报 + 黄灯亮 → 充满黄灯灭绿灯亮
```

### 15.3 紧急寻物（GPS定位模式）

```
平台下发 change_mode(2) → 重启 → GPS 常开 → 每 30s 上报 + 绿灯慢闪 10s
→ 找到后下发 change_mode(0/1) 切回
```

## 十六、常见问题（FAQ）

**Q1 默认能否连接 AirCloud？**
出厂无配置时默认通道1 连接 AirCloud，开箱即上报。若平台下发过 network 配置且未启用 AirCloud 通道，则以平台配置为准（不连 AirCloud），需在网页端启用。

**Q2 充电初始化失败 / 芯片 ID 0xFF？**
CMD 空闲电平未拉高或接线异常。检查 GPIO25 接线；扩展库已内置 cmd_idle 自动拉高，需烧录含修复的固件。日志应出现 `YHM2712A 充电初始化成功`。

**Q3 看门狗不生效？**
检查 GPIO24 接线（AGPIO24 → NPN → WTDOG），确认喂狗周期 > 150s，日志应出现 `Air153C 看门狗初始化成功`。

**Q4 GPS 定位慢？**
GPS定位模式首次定位在开阔地需 30–60s，检查 GPS 天线连接与遮挡。

**Q5 耗电太快？**
检查是否处于 GPS定位模式或充电状态（60s 快报）。日常建议常规/智能模式。

**Q6 指示灯不亮？**
确认 GPIO26/27 引脚定义与硬件一致；产测可下发 LED 命令验证。
