# IRTU 宠物追踪器 - 使用文档

## 一、设备生命周期

### 1.1 整体流程

```
烧录 → 首次上电 → [产测模式] → 测试通过 → [未激活模式] → 绑定 → [常规/智能模式] → 紧急 → [寻宠模式]
```

### 1.2 关于配置平台

配置平台地址：**<https://iot_test.openluat.com>**

配置平台用于修改设备参数配置（如上报间隔、蓝牙名称、智能模式震动冷却时间等），通过 HTTP 接口下发配置，设备重启后生效。**所有实时指令由服务器端下发，不通过配置平台操作。**

### 1.3 模式说明

| 模式    | 数值 | 说明                               |
| ----- | -- | -------------------------------- |
| 产测模式  | -2 | 第一次开机自动进入，执行硬件测试，测试通过后进入未激活模式    |
| 未激活模式 | -1 | 产测通过后进入，蓝牙广播开启，可通过蓝牙或服务器下发指令切换模式 |
| 常规模式  | 0  | 固定间隔基站定位，不开 GPS，最省电，不受运动状态影响     |
| 智能模式  | 1  | 运动中 GPS、静止时基站；静止越久上报越慢，震动可立即上报   |
| 寻宠模式  | 2  | GPS 常开 + 基站备选 + 提示音 + 蓝牙广播       |

### 1.4 模式切换

模式切换通过服务器下发 `change_mode` 指令实现，设备收到后保存模式并重启进入目标模式（详见「六、远程指令」）。

- **产测模式 → 未激活模式**：测试全部通过后自动切换，或产测超时自动进入
- **未激活模式 → 常规/智能模式**：通过服务器下发 `change_mode` 指令，设备重启后进入
- **常规模式 ↔ 智能模式**：通过服务器下发 `change_mode` 指令，设备重启后切换
- **任意模式 → 寻宠模式**：通过服务器下发 `change_mode` 指令，设备重启后进入
- **寻宠模式 → 常规/智能模式**：通过服务器下发 `change_mode` 指令，设备重启后切换

> 提示：蓝牙仅在产测、未激活、寻宠模式开启；常规和智能模式下蓝牙关闭，此时只能通过服务器下发指令切换模式。

***

## 二、产测模式

设备首次烧录开机自动进入产测模式，用于验证硬件功能。

### 2.1 测试项

| 测试项  | 说明                   | 通过条件    |
| ---- | -------------------- | ------- |
| 基站定位 | 获取基站位置               | 返回有效经纬度 |
| 音频播放 | 播放 `/luadb/here.mp3` | 播放成功    |
| 平台上报 | 数据上报到平台              | 平台收到数据  |
| 指令响应 | 等待平台下发指令             | 收到并正确响应 |

### 2.2 操作流程

1. 设备上电 → 自动执行基站定位和音频播放
2. 观察日志确认定位成功、听到提示音
3. 平台收到上报数据
4. 通过服务器下发 `change_mode` 指令（`mode=0` 或 `mode=1`），配置平台（<https://iot_test.openluat.com）仅用于修改设备参数，不下发实时指令>
5. 设备收到指令后 3 秒重启，进入未激活模式

> 如果不下发指令，产测模式默认持续 300 秒（5 分钟），超时后自动进入未激活模式。

***

## 三、未激活模式

产测通过后设备重启进入未激活模式。每次开机也进入此模式（直到被平台绑定）。

**设备行为：**

- LED 三长一短闪烁
- 蓝牙广播开启，名称格式 `irtu-` 加上 IMEI 号后六位（如 `irtu-153505`），可通过蓝牙下发指令切换模式
- 连接云平台，上报就绪消息
- 等待服务器下发 `change_mode` 指令

**绑定方式（服务器下发指令）：**

```json
{"cmd":"change_mode","mode":0}
```

或

```json
{"cmd":"change_mode","mode":1}
```

设备收到后保存模式，3 秒后重启进入目标模式。

**关于配置平台（<https://iot_test.openluat.com）：>** 如需修改设备参数（如上报间隔、蓝牙名称等），在配置平台修改后设备重启生效。实时指令由服务器下发，与配置平台无关。

**超时：** 300 秒后进入低功耗/关机/重启（根据配置）。

***

## 四、日常使用模式

### 4.1 常规模式 — 值: 0

| 项目   | 说明                 |
| ---- | ------------------ |
| 定位   | 仅基站，不开 GPS         |
| 上报间隔 | 默认 300 秒（5 分钟），可配置 |
| 低电量  | 1800 秒（30 分钟）上报一次  |
| 充电中  | 60 秒上报一次           |
| 功耗   | 最低，适合长时间续航         |

### 4.2 智能模式 — 值: 1

智能模式根据运动状态自动调节上报频率，兼顾实时追踪与省电。

**上报间隔规则：**

| 状态 | 定位方式 | 上报间隔 |
| --- | --- | --- |
| 运动中 | GPS 定位（失败降级基站） | 基础间隔（默认 180 秒，网页可配置） |
| 静止时 | 基站定位 | 从基础间隔起步，每次上报递增（+120秒），越不动等得越久，封顶 660 秒 |

**震动触发立即上报：**

- 检测到震动时，若不在冷却期内，**立即上报一次**位置（不等当前间隔到期）
- 每次震动立即上报后进入 **冷却期**（网页可配置，默认 600 秒 / 10 分钟）
- 冷却期内再次震动**不再触发立即上报**，仍按定时节奏上报，防止宠物持续晃动导致频繁上报耗电
- 震动**不会重置**静止时的间隔递增，叠加节奏保持不变

**叠加节奏示例（基础间隔 180 秒）：**

```
静止上报1次 → 180秒
静止上报2次 → 300秒
静止上报3次 → 420秒
... 每上报一次递增 120 秒，最多 660 秒封顶
[震动] → 立即上报一次（进冷却期），叠加计数不变
[持续运动] → 上报间隔保持基础值，运动状态判定为静止后才恢复递增
```

> 运动状态判定：检测到震动即判定为运动中；持续约 10 秒无震动自动恢复为静止。开机时初始为静止状态（基站定位）。

**其他说明：**

| 项目 | 说明 |
| --- | --- |
| 上报间隔 | 基础间隔由网页配置（`smart_interval`），递增步长与封顶值固定 |
| 震动冷却 | 网页可配置（`motion_cooldown`），默认 600 秒，仅在开启运动检测时可配置 |
| 功耗 | 中等，运动中 GPS 较耗电，静止时基站 + 拉长间隔省电 |

### 4.3 使用建议

| 场景    | 推荐模式     |
| ----- | -------- |
| 在家活动  | 常规模式     |
| 外出散步  | 智能模式     |
| 长时间出差 | 常规模式     |
| 宠物走失  | 立即切换寻宠模式 |

## 五、寻宠模式（紧急）— 值: 2

| 项目   | 说明                            |
| ---- | ----------------------------- |
| GPS  | 常开，后台持续搜星，不上报时也不关闭            |
| 上报间隔 | 默认 30 秒，可配置                   |
| 定位   | GPS 优先，有缓存直接用，无缓存走基站备选，不等 GPS |
| 提示音  | 每次上报播放 3 次（0秒、10秒、20秒各一次）     |
| 蓝牙广播 | 开启，手机可搜索到设备                   |
| 功耗   | 最高                            |

**使用方式：**

1. 服务器下发 `{"cmd":"change_mode","mode":2}`
2. 设备重启，进入寻宠模式
3. 持续播放提示音，蓝牙广播开启
4. 每 30 秒上报一次位置
5. 找到宠物后，通过服务器切换回常规或智能模式

## 六、远程指令

所有指令由服务器端下发，通过 JSON 格式发送至设备。

### 6.1 change\_mode - 切换模式

```json
{"cmd":"change_mode","mode":0}
```

| mode | 说明   |
| ---- | ---- |
| 0    | 常规模式 |
| 1    | 智能模式 |
| 2    | 寻宠模式 |

**流程：** 收到指令 → 保存模式到存储器 → 回复平台 → 3 秒后自动重启 → 重启后进入新模式。

### 6.2 play\_sound - 播放提示音

```json
{"cmd":"play_sound","type":"9"}
```

目前只支持 type=9，播放 `/luadb/here.mp3`。

### 6.3 set\_volume - 设置音量

```json
{"cmd":"set_volume","volume":80}
```

音量范围 0（静音）到 100（最大），设置后保存，重启不丢失。

### 6.4 call - SIP 呼叫

```json
{"cmd":"call","touser":"10086"}
```

发起 SIP 语音通话，呼叫指定号码。

### 6.5 open\_light - 灯光控制

```json
{"cmd":"open_light","status":1}
```

| status | 说明   |
| ------ | ---- |
| 0      | 关闭灯光 |
| 1      | 打开灯光 |

## 七、上报数据

> 说明：设备支持多种上报通道（MQTT、TCP、UDP、合宙云 AirCloud）。
>
> - **MQTT / TCP / UDP 通道**：以 JSON 格式上报。
> - **合宙云 AirCloud 通道**：以 **TLV 格式**上报（字段编码为 `{field_meaning, data_type, value}`），不包含 msg\_id / type / ts / imei 等包装字段。

### 7.1 数据格式示例

**JSON 通道（MQTT / TCP / UDP）**：

```json
{
  "msg_id": "864317083153505-1785495863",
  "type": "property_report",
  "ts": 1785495863,
  "imei": "864317083153505",
  "data": {
    "work_mode": 0,
    "vbat": 4345,
    "bat_change": 1,
    "signal": -89,
    "gps": "34.81591,114.31024",
    "gps_status": 2,
    "step": 6,
    "temperature": 29.6,
    "air_press_pa": 993.1,
    "volume": 80
  }
}
```

### 7.1.1 AirCloud TLV 上报字段

AirCloud 通道通过 TLV 字段数组上报，字段编号（field\_meaning）与数据类型如下：

**通用字段（所有定位方式都上报）：**

| tag  | 字段             | 中文名称      | 数据类型    | 说明        |
| ---- | -------------- | --------- | ------- | --------- |
| 1290 | work\_mode     | 工作模式      | INTEGER | 0/1/2     |
| 799  | vbat           | 电池电压      | INTEGER | mV        |
| 1291 | bat\_change    | 充电状态      | INTEGER | 0/1       |
| 782  | signal         | 信号强度      | INTEGER | 负数钳位为0    |
| 512  | gps\_lng       | GNSS经度    | ASCII   | 非空才发      |
| 513  | gps\_lat       | GNSS纬度    | ASCII   | 非空才发      |
| 519  | gps\_status    | 定位方式      | ASCII   | 2/3/4/5   |
| 1292 | step           | 步数        | INTEGER | -         |
| 263  | temperature    | 温度        | FLOAT   | °C        |
| 1293 | air\_press\_pa | 气压        | FLOAT   | hPa       |
| 1294 | volume         | 音量        | INTEGER | -         |
| 772  | band           | 驻留频段      | ASCII   | "LTE B40" |
| 774  | chip\_model    | 元器件型号     | ASCII   | -         |
| 776  | boot\_reason   | 开机原因      | ASCII   | -         |
| 779  | wake\_interval | 定时唤醒间隔    | INTEGER | 秒         |
| 783  | iccid          | SIM卡ICCID | ASCII   | -         |

**卫星字段（仅 GPS 定位成功 gps\_status==2 时上报）：**

| tag | 字段           | 中文名称   | 数据类型    | 说明 |
| --- | ------------ | ------ | ------- | -- |
| 515 | top4\_cn     | 最强4星CN | ASCII   | -  |
| 516 | sat\_total   | 搜星总数   | INTEGER | -  |
| 517 | sat\_visible | 可见卫星数  | INTEGER | -  |

> 注：tag 1290-1294 为自定义扩展字段，需服务器端额外识别；其余为 AirCloud 协议标准字段。字符串字段为空时不发送（避免编码失败）。

### 7.2 字段详细说明

**msg\_id**：消息唯一编号，由设备 IMEI 号和时间戳组合生成，每条消息唯一，用于去重和追踪。

**type**：消息类型，固定为 `property_report`（属性上报），表示这是一条设备状态数据。

**ts**：时间戳，单位秒，表示数据采集的时间点。

**imei**：设备唯一标识号，15 位数字，用于区分不同设备。

**data 对象中的字段：**

| 字段             | 说明                                                                           | 示例值                |
| -------------- | ---------------------------------------------------------------------------- | ------------------ |
| work\_mode     | 当前工作模式。0=常规模式，1=智能模式，2=寻宠模式                                                  | 0                  |
| vbat           | 电池电压，单位毫伏（mV）。可由此估算电量：4200mV 以上接近满电，3500mV 以下电量较低                            | 4345               |
| bat\_change    | 充电状态。0=未充电（电池供电），1=充电中（外接电源）                                                 | 1                  |
| signal         | 信号强度，单位 dBm。数值越大（越接近 0）信号越好，-110 以下信号较差                                      | -89                |
| gps            | 定位经纬度，格式为"纬度,经度"，逗号分隔。例如 "34.81591,114.31024" 表示北纬 34.81591 度，东经 114.31024 度 | 34.81591,114.31024 |
| gps\_status    | 定位状态码，见下方详细说明                                                                | 2                  |
| step           | 计步步数，来自 DA267 加速度传感器                                                         | 6                  |
| temperature    | 温度，单位摄氏度（°C），来自 NS2520 气压温度传感器                                               | 29.6               |
| air\_press\_pa | 气压，单位百帕（hPa），来自 NS2520 气压温度传感器                                               | 993.1              |
| volume         | 当前音量，范围 0-100                                                                | 80                 |

### 7.3 定位状态码说明

| 状态码 | 含义       | 说明                                          |
| --- | -------- | ------------------------------------------- |
| 2   | GPS 定位成功 | 卫星定位成功，精度最高，误差通常在 10 米以内                    |
| 3   | 定位失败     | 所有定位方式均失败，没有有效位置数据                          |
| 4   | 免费基站定位成功 | 通过免费基站定位服务获取位置，精度取决于基站密度，城区 50-500 米        |
| 5   | 付费基站定位成功 | 通过付费基站定位服务获取位置，精度比免费基站更高，且会开启 WiFi 辅助扫描辅助定位 |

## 八、蓝牙配置说明

### 8.1 蓝牙广播名称

设备蓝牙广播名称由两部分组成：**前缀** + **IMEI 号后缀**。

**前缀：** 固定为 `irtu-`（可通过平台配置修改）。

**后缀规则（三种可选）：**

| 规则        | 说明                      | 示例（IMEI=864317083153505） |
| --------- | ----------------------- | ------------------------ |
| IMEI 号后六位 | 取 IMEI 号的最后 6 位数字作为名称后缀 | `irtu-153505`            |
| IMEI 号后四位 | 取 IMEI 号的最后 4 位数字作为名称后缀 | `irtu-3505`              |
| 完整 IMEI 号 | 使用完整的 15 位 IMEI 号作为名称后缀 | `irtu-864317083153505`   |

### 8.2 蓝牙开关状态

| 模式    | 蓝牙状态 | 说明                     |
| ----- | ---- | ---------------------- |
| 产测模式  | 开启   | 用于产测阶段发现设备             |
| 未激活模式 | 开启   | 可通过蓝牙下发指令切换模式，也可用于绑定设备 |
| 常规模式  | 关闭   | 省电，无法通过蓝牙下发指令          |
| 智能模式  | 关闭   | 省电，无法通过蓝牙下发指令          |
| 寻宠模式  | 开启   | 辅助近距离寻找设备，不用于切换模式      |

## 九、音频

目前仅支持 `/luadb/here.mp3` 这一个音频文件，在寻宠模式下每次上报自动播放。

**音频硬件参数：** ES8311 音频编解码芯片，I2C 地址 0，功放控制引脚 PA=25、DAC=2。

**无声排查步骤：**

1. 检查日志中是否有 `音频初始化失败` — 硬件初始化问题，检查 ES8311 供电和连接
2. 检查日志中是否有 `音频播放失败` — 播放参数问题
3. 确认 `here.mp3` 文件已打包进脚本区
4. 检查喇叭是否正确连接到音频输出引脚
5. 检查音量设置是否过低（默认 80，可调高到 100 测试）

***

## 十、低功耗与充电

| 条件             | 行为                              |
| -------------- | ------------------------------- |
| 电池电量低于 20%     | 自动进入低电量模式：延长上报间隔，关闭 GPS，仅使用基站定位 |
| 常规模式/智能模式上报完成后 | 进入轻睡眠状态，降低功耗，等待下一次上报            |
| 寻宠模式           | 保持全功率运行，不进入睡眠                   |
| 插入充电器          | 上报间隔缩短为 60 秒，GPS 全开，不受省电策略限制    |
| 拔掉充电器          | 恢复为当前模式的上报间隔                    |

> 智能模式下震动会唤醒设备立即上报，之后重新进入低功耗等待；冷却期内震动不会唤醒立即上报，仍由定时唤醒。

## 十一、常见问题

**Q1: 设备不上报数据？**
检查 SIM 卡是否安装、信号是否正常、MQTT 连接是否正常（日志中是否有 `CLOUD_CONNECTED`）。

**Q2: 服务端下发指令设备没反应？**
确认设备在线，检查指令 JSON 格式是否正确，检查日志中是否有 `[MQTT]` 相关输出。

**Q3: 寻宠模式听不到声音？**
检查 `here.mp3` 是否已打包、日志中是否有音频报错、喇叭连接是否正常、音量设置是否过低。

**Q4: GPS 定位慢？**
寻宠模式 GPS 常开，首次定位在开阔地带需 30-60 秒，确认 GPS 天线已连接且未被遮挡。

**Q5: 基站定位失败？**
检查网络连接是否正常，检查 AirLBS 项目 ID 和密钥是否正确配置。

**Q6: 蓝牙搜索不到设备？**
确认设备处于未激活模式或寻宠模式，其他模式蓝牙关闭属于正常现象。

**Q7: 设备耗电太快？**
检查是否处于寻宠模式（功耗最高），或是否频繁上报（充电状态每 60 秒上报一次）。日常使用建议常规模式。
