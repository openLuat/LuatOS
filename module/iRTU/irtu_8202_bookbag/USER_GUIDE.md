# IRTU 8202G 定位板 - 用户使用手册

## 一、设备概述

**IRTU 8202G** 是基于 Air780EGP 模组的定位追踪板，支持 GPS + 基站（LBS）混合定位，适用于宠物追踪、人员定位、车辆定位等场景。

**硬件能力：**

| 功能 | 说明 |
| ---- | ---- |
| 主控模组 | Air780EGP（4G Cat.1） |
| 定位 | GPS + 基站定位（免费/付费）+ WiFi 辅助 |
| 运动检测 | DA221 加速度传感器（震动检测 / 运动状态判断） |
| 充电管理 | YHM2712A 充电IC（恒流恒压、充满自停） |
| 硬件看门狗 | Air153C（防死机，默认开启，GPIO24 喂狗） |
| 电池 | 锂电池 3.7V-4.2V |
| 上报通道 | MQTT、TCP、UDP、合宙云 AirCloud |

**不支持的硬件**（本板无这些外设）：音频/喇叭、蓝牙模块、气压传感器、温度传感器、计步功能。

## 二、设备生命周期

### 2.1 整体流程

```
烧录上电 → 未激活模式（等待绑定）→ 绑定后进入常规/智能模式 → 需要时可切换 GPS定位模式
```

### 2.2 关于配置平台

配置平台地址：**<https://iot_test.openluat.com>**

配置平台用于修改设备参数配置（如上报间隔、智能模式震动冷却时间、充电管理、看门狗等），通过 HTTP 接口下发配置，设备重启后生效。**所有实时指令由服务器端下发，不通过配置平台操作。**

### 2.3 模式说明

| 模式 | 数值 | 说明 |
| ---- | -- | -------------------------------- |
| 未激活模式 | -1 | 开机默认进入，等待服务器下发指令绑定并切换模式 |
| 常规模式 | 0 | 固定间隔基站定位，不开 GPS，最省电，不受运动状态影响 |
| 智能模式 | 1 | 运动中 GPS、静止时基站；静止越久上报越慢，震动可立即上报 |
| GPS定位模式 | 2 | GPS 常开 + 基站备选 |

### 2.4 模式切换

模式切换通过服务器下发 `change_mode` 指令实现，设备收到后保存模式并重启进入目标模式（详见「五、远程指令」）。

- **未激活模式 → 常规/智能模式**：通过服务器下发 `change_mode` 指令，设备重启后进入
- **常规模式 ↔ 智能模式**：通过服务器下发 `change_mode` 指令，设备重启后切换
- **任意模式 → GPS定位模式**：通过服务器下发 `change_mode` 指令，设备重启后进入
- **GPS定位模式 → 常规/智能模式**：通过服务器下发 `change_mode` 指令，设备重启后切换

> 提示：本硬件无蓝牙模块，所有模式切换均通过服务器下发 `change_mode` 指令实现。

## 三、未激活模式

设备开机默认进入未激活模式（直到被平台绑定）。

**设备行为：**

- LED 三长一短闪烁
- 连接云平台，上报就绪消息
- 等待服务器下发 `change_mode` 指令完成绑定并切换模式

**绑定方式（服务器下发指令）：**

```json
{"cmd":"change_mode","mode":0}
```

或

```json
{"cmd":"change_mode","mode":1}
```

设备收到后保存模式，3 秒后重启进入目标模式。

## 四、日常使用模式

### 4.1 常规模式 — 值: 0

| 项目 | 说明 |
| ---- | ------------------ |
| 定位 | 仅基站，不开 GPS |
| 上报间隔 | 默认 300 秒（5 分钟），可配置 |
| 低电量 | 1800 秒（30 分钟）上报一次 |
| 充电中 | 60 秒上报一次 |
| 功耗 | 最低，适合长时间续航 |

### 4.2 智能模式 — 值: 1

智能模式根据运动状态自动调节上报频率，兼顾实时追踪与省电。

**上报间隔规则：**

| 状态 | 定位方式 | 上报间隔 |
| --- | --- | --- |
| 运动中 | GPS 定位（失败降级基站） | 基础间隔（默认 180 秒，网页可配置） |
| 静止时 | 基站定位 | 从基础间隔起步，每次上报递增（+120秒），越不动等得越久，封顶 660 秒 |

**震动触发立即上报：**

- 检测到震动时，若不在冷却期内，**立即上报一次**位置（不等当前间隔到期）
- 每次震动立即上报后进入 **冷却期**（网页可配置，默认 600 秒 / 10 分钟）
- 冷却期内再次震动**不再触发立即上报**，仍按定时节奏上报，防止宠物持续晃动导致频繁上报耗电
- 震动**不会重置**静止时的间隔递增，叠加节奏保持不变

**叠加节奏示例（基础间隔 180 秒）：**

```
静止上报1次 → 180秒
静止上报2次 → 300秒
静止上报3次 → 420秒
... 每上报一次递增 120 秒，最多 660 秒封顶
[震动] → 立即上报一次（进冷却期），叠加计数不变
[持续运动] → 上报间隔保持基础值，运动状态判定为静止后才恢复递增
```

> 运动状态判定：检测到震动即判定为运动中；持续约 10 秒无震动自动恢复为静止。开机时初始为静止状态（基站定位）。

**其他说明：**

| 项目 | 说明 |
| --- | --- |
| 上报间隔 | 基础间隔由网页配置（`smart_interval`），递增步长与封顶值固定 |
| 震动冷却 | 网页可配置（`motion_cooldown`），默认 600 秒，仅在开启运动检测时可配置 |
| 功耗 | 中等，运动中 GPS 较耗电，静止时基站 + 拉长间隔省电 |

### 4.3 使用建议

| 场景 | 推荐模式 |
| ----- | -------- |
| 在家活动 | 常规模式 |
| 外出散步 | 智能模式 |
| 长时间出差 | 常规模式 |
| 宠物走失 | 立即切换 GPS定位模式 |

## 五、GPS定位模式 — 值: 2

| 项目 | 说明 |
| ---- | ----------------------------- |
| GPS | 常开，后台持续搜星，不上报时也不关闭 |
| 上报间隔 | 默认 30 秒，可配置 |
| 定位 | GPS 优先，有缓存直接用，无缓存走基站备选，不等 GPS |
| 功耗 | 最高 |

**使用方式：**

1. 服务器下发 `{"cmd":"change_mode","mode":2}`
2. 设备重启，进入 GPS定位模式
3. 每 30 秒上报一次位置
4. 找到目标后，通过服务器切换回常规或智能模式

## 六、远程指令

所有指令由服务器端下发，通过 JSON 格式发送至设备。

### 6.1 change_mode - 切换模式

```json
{"cmd":"change_mode","mode":0}
```

| mode | 说明 |
| ---- | ---- |
| 0 | 常规模式 |
| 1 | 智能模式 |
| 2 | GPS定位模式 |

**流程：** 收到指令 → 保存模式到存储器 → 回复平台 → 3 秒后自动重启 → 重启后进入新模式。

### 6.2 open_light - 灯光控制

```json
{"cmd":"open_light","status":1}
```

| status | 说明 |
| ------ | ---- |
| 0 | 关闭灯光 |
| 1 | 打开灯光 |

### 6.3 close_device - 关机

```json
{"cmd":"close_device"}
```

设备收到后回复并关机。

### 6.4 set_report_interval - 设置上报间隔

```json
{"cmd":"set_report_interval","interval_seconds":300}
```

设置后保存，重启不丢失。范围 10-86400 秒。

### 6.5 get_device_data - 触发立即上报

```json
{"cmd":"get_device_data"}
```

设备收到后立即上报一次当前数据。

### 6.6 update - 触发OTA升级

```json
{"cmd":"update"}
```

触发固件升级检查。

### 6.7 fota_mode - 切换FOTA模式

```json
{"cmd":"fota_mode","mode":3}
```

mode: 3=libfota3（只能合宙人员根据客户IMEI升级），2=libfota2（IoT平台，客户自行管理）。

### 6.8 不支持指令

以下指令因本硬件无对应外设，设备收到后会返回"不支持"：

- `call`（SIP 通话）
- `play_sound`（播放提示音）
- `set_volume`（设置音量）

## 七、上报数据

> 说明：设备支持多种上报通道（MQTT、TCP、UDP、合宙云 AirCloud）。
>
> - **MQTT / TCP / UDP 通道**：以 JSON 格式上报。
> - **合宙云 AirCloud 通道**：以 **TLV 格式**上报（字段编码为 `{field_meaning, data_type, value}`），不包含 msg_id / type / ts / imei 等包装字段。

### 7.1 数据格式示例

**JSON 通道（MQTT / TCP / UDP）：**

```json
{
  "msg_id": "864317083153505-1785495863",
  "type": "property_report",
  "ts": 1785495863,
  "imei": "864317083153505",
  "data": {
    "work_mode": 0,
    "vbat": 4345,
    "bat_change": 1,
    "signal": -89,
    "gps": "34.81591,114.31024",
    "gps_status": 2,
    "position_active_report": 1,
    "iccid": "8986031993312345678",
    "chip_model": "Air8202",
    "boot_reason": "power_on",
    "band": "LTE B3",
    "wake_interval": 300,
    "top4_cn": "35,32,30,28",
    "sat_total": 10,
    "sat_visible": 8
  }
}
```

**字段说明：**

| 字段 | 类型 | 说明 |
| ---- | ---- | ---- |
| msg_id | string | 消息ID，格式 `IMEI-时间戳` |
| type | string | 上报类型：`startup` / `property_report` / `bind_ready` / `command_reply` |
| ts | number | Unix 时间戳 |
| imei | string | 设备IMEI号 |
| work_mode | number | 工作模式：0=常规 1=智能 2=GPS定位 |
| vbat | number | 电池电压(mV) |
| bat_change | 0/1 | 是否在充电 |
| signal | number | 信号强度 |
| gps | string | 纬度,经度 |
| gps_status | number | 定位方式：2=GPS 3=失败 4=免费基站 5=付费基站 |
| position_active_report | number | 上报标志，固定1 |
| iccid | string | SIM卡ICCID |
| chip_model | string | 元器件型号，固定 `Air8202` |
| boot_reason | string | 开机原因 |
| band | string | 驻留频段，如 `LTE B3` |
| wake_interval | number | 本次上报间隔(秒) |
| top4_cn | string | 最强4颗卫星CN值（仅GPS成功时非空） |
| sat_total | number | 搜星总数（仅GPS成功时） |
| sat_visible | number | 可见卫星数（仅GPS成功时） |

### 7.2 AirCloud TLV 上报字段

AirCloud 通道通过 TLV 字段数组上报，字段编号（field_meaning）与数据类型如下：

**通用字段（所有定位方式都上报）：**

| tag | 字段 | 中文名称 | 数据类型 | 说明 |
| ---- | -------------- | --------- | ------- | --------- |
| 1290 | work_mode | 工作模式 | INTEGER | 0/1/2 |
| 799 | vbat | 电池电压 | INTEGER | mV |
| 1291 | bat_change | 充电状态 | INTEGER | 0/1 |
| 782 | signal | 信号强度 | INTEGER | 负数钳位为0 |
| 512 | gps_lng | GNSS经度 | ASCII | 非空才发 |
| 513 | gps_lat | GNSS纬度 | ASCII | 非空才发 |
| 519 | gps_status | 定位方式 | ASCII | 2/3/4/5 |
| 772 | band | 驻留频段 | ASCII | "LTE B40" |
| 774 | chip_model | 元器件型号 | ASCII | 固定 "Air8202" |
| 776 | boot_reason | 开机原因 | ASCII | - |
| 779 | wake_interval | 定时唤醒间隔 | INTEGER | 秒 |
| 783 | iccid | SIM卡ICCID | ASCII | - |

**卫星字段（仅 GPS 定位成功 gps_status==2 时上报）：**

| tag | 字段 | 中文名称 | 数据类型 | 说明 |
| --- | ------------ | ------ | ------- | -- |
| 515 | top4_cn | 最强4星CN | ASCII | - |
| 516 | sat_total | 搜星总数 | INTEGER | - |
| 517 | sat_visible | 可见卫星数 | INTEGER | - |

> 注：tag 1290-1291 为自定义扩展字段，需服务器端额外识别；其余为 AirCloud 协议标准字段。字符串字段为空时不发送（避免编码失败）。

### 7.3 定位状态码说明

| 状态码 | 含义 | 说明 |
| --- | -------- | ------------------------------------------- |
| 2 | GPS 定位成功 | 卫星定位成功，精度最高，误差通常在 10 米以内 |
| 3 | 定位失败 | 所有定位方式均失败，没有有效位置数据 |
| 4 | 免费基站定位成功 | 通过免费基站定位服务获取位置，精度取决于基站密度，城区 50-500 米 |
| 5 | 付费基站定位成功 | 通过付费基站定位服务获取位置，精度比免费基站更高，且会开启 WiFi 辅助扫描辅助定位 |

## 八、充电管理（YHM2712A）

设备支持通过 YHM2712A 充电IC 管理单节锂电池充电，实现恒流恒压充电、充满自停。

### 8.1 配置项（网页端 → 传感器 tab）

| 配置项 | 默认值 | 说明 |
| ---- | ---- | ---- |
| 充电管理 | **开启** | 总开关，默认开启 |
| CMD引脚 | **25** | YHM2712A 的 CMD（STACMD 单线通信）引脚，**需根据硬件原理图确认** |
| 截止电压 | 4200 | 电池充电截止电压：4.2V（4200mV）或 4.35V（4350mV，高压电池） |
| 电池容量 | 400 | 电池容量(mAh)，决定充电电流大小 |
| 充电电流 | 默认 | 充电电流模式：最小 / 默认 / 最大（默认取**默认**档） |

> 说明：固件默认配置参考官方库示例（`cap_battery=400, i_charge=CCDEFAULT`）。扩展库已内置 **CMD 空闲保持高电平** 处理（YHM2712A 的 CMD 为单总线，空闲必须为高电平，长时间拉低会触发芯片内部看门狗复位导致通信失败）。

### 8.2 配置流程

> 固件默认已开启充电管理（GPIO25/4.2V/400mAh/默认电流），出厂即生效，一般无需额外配置；如确需调整，按以下步骤：

1. 网页端定位版参数 → **传感器** tab
2. 充电管理 → 开启
3. 选择 CMD 引脚（默认 25，需确认硬件接线）
4. 设置截止电压、电池容量、充电电流
5. 保存配置，设备重启后生效

### 8.3 验证

设备日志中看到以下信息表示充电管理初始化成功：

```
I/charge YHM2712A 充电初始化成功，pin=xx v_battery=xxxx cap_battery=xxx i_charge=DEFAULT
```

## 九、硬件看门狗（Air153C）

设备支持通过 Air153C 硬件看门狗防止死机。开启后，若程序跑飞，看门狗会自动复位设备。

### 9.1 配置项（网页端 → 传感器 tab）

| 配置项 | 默认值 | 说明 |
| ---- | ---- | ---- |
| 硬件看门狗 | **开启** | 总开关，默认开启 |
| 喂狗GPIO | **24** | 驱动 Air153C 喂狗信号的 GPIO 引脚（硬件接线：**AGPIO24 → NPN → WTDOG**） |
| 喂狗时间 | 180 | 自动喂狗周期(秒)，需大于 150 秒（Air153C 超时固定 240s，不可改） |

### 9.2 配置流程

> 固件默认已开启看门狗（GPIO24/180s），出厂即生效，一般无需额外配置；如确需调整，按以下步骤：

1. 网页端定位版参数 → **传感器** tab
2. 硬件看门狗 → 开启
3. 选择喂狗 GPIO 引脚（默认 24，**需确认与硬件接线一致：AGPIO24 → NPN → WTDOG**）
4. 设置喂狗时间
5. 保存配置，设备重启后生效

### 9.3 验证

设备日志中看到以下信息表示看门狗初始化成功：

```
I/air153c_wdt Air153C 看门狗初始化成功，喂狗引脚:xx 周期:xx 秒
```

## 十、低功耗与充电

| 条件 | 行为 |
| -------------- | ------------------------------- |
| 电池电量低于 20% | 自动进入低电量模式：延长上报间隔，关闭 GPS，仅使用基站定位 |
| 常规模式/智能模式上报完成后 | 进入轻睡眠状态，降低功耗，等待下一次上报 |
| GPS定位模式 | 保持全功率运行，不进入睡眠 |
| 插入充电器 | 上报间隔缩短为 60 秒，GPS 全开，不受省电策略限制 |
| 拔掉充电器 | 恢复为当前模式的上报间隔 |

> 智能模式下震动会唤醒设备立即上报，之后重新进入低功耗等待；冷却期内震动不会唤醒立即上报，仍由定时唤醒。

## 十一、常见问题

**Q1: 设备不上报数据？**
检查 SIM 卡是否安装、信号是否正常、MQTT 连接是否正常（日志中是否有 `CLOUD_CONNECTED`）。

**Q2: 服务端下发指令设备没反应？**
确认设备在线，检查指令 JSON 格式是否正确，检查日志中是否有 `[MQTT]` 相关输出。

**Q3: GPS 定位慢？**
GPS定位模式 GPS 常开，首次定位在开阔地带需 30-60 秒，确认 GPS 天线已连接且未被遮挡。

**Q4: 基站定位失败？**
检查网络连接是否正常，检查 AirLBS 项目 ID 和密钥是否正确配置。

**Q5: 设备耗电太快？**
检查是否处于 GPS定位模式（功耗最高），或是否频繁上报（充电状态每 60 秒上报一次）。日常使用建议常规模式。

**Q6: 充电管理不生效？**
检查日志是否有 `YHM2712A 充电初始化成功`；若显示"未配置 CMD 引脚"，说明网页端未配置引脚；若显示"加载 exs_yhm2712a 库失败"，检查库文件是否打包。

**Q7: 看门狗不生效？**
检查日志是否有 `Air153C 看门狗初始化成功`；若显示"未配置喂狗 GPIO 引脚"，说明网页端未配置引脚；确认喂狗时间大于 150 秒。
