# 电动车仪表盘 · Aurora Cockpit（Air8607 / 1024x600）

LuatOS + AirUI（LVGL9）真机 UI 工程。版面不是换皮，而是**重排信息密度**：
中心 408px 表盘 + 左右各一列 232px 卡片 + 底部 976px 数据带，
把常见仪表「中间一个表盘、四周全是黑」的空白填成有层级的内容。

- 视觉基调：近黑画布 + 1px 发丝描边卡片 + 三色霓虹（青 `#22A8F5` / 紫 `#A78BFA` / 品红 `#F472B6`）
- 双主题：`dark` Neon Noir / `light` Neon Daylight（右上圆钮切换，落 `fskv`）
- 交互：模式胶囊（顶栏循环 / 左栏直选）、点击电池卡模拟插枪充电

## 结构（现象 → 处理）

| 现象 | 根因 | 处理 |
|--------|------|---------|
| 每个实心圆外一圈白线 | `airui.shape` 的 `fill=true` 仍画描边，未传 `color/width/opacity` → 白 + 1px + 不透明 | 全部圆心显式补 `color=fill_color, opacity=0`（`ui_icon`/`ui_dial`/`ui_topbar` 统一） |
| 随时可能出滚动条 | `airui.container` 的 `scrollable` 默认 true | `ui_widget` 所有容器统一 `scrollable=false`，并登记内容区做越界自检 `log.warn` |
| 每帧重绘 2×614k 像素 | 动态 shape 建在 `(0,0,1024,600)` | 静态层 408×408、动态层 412×412，均按表盘包围盒建对象 |
| 指针 + 进度弧两次全屏失效 | 两个 shape 各刷新一次 | 共用同一包围盒，按 15Hz / 5Hz 分级失效，值不变跳过 |
| 30fps 造表 GC 抖动 | `render` 里每帧新建 items | `W.si(shape, key, build)`：key 未变不执行 `build` |
| 30fps 造字符串 GC 抖动 | `render` 里每帧 `tostring` / 拼 `ODO .. KM` / `util.fmt` | 先比整数刻度，变了才格式化（`ui_dial` / `ui_cards` / `ui_bottom`） |
| 整屏 shape 拉高每帧重绘 | 侧光 / 氛围光都建在 `1024x600` | 侧光拆左右两块 `385x600`、氛围光裁到 `1024x130`（内容本就在这个范围内） |
| hzfont 缓存挤占堆 | 5 档字号 × `cache_size 2048` | 降到 `256`：界面固定文案约 60 字，2048 会白占几十 MB 并把 LVGL 堆逼到碎片化 |
| `ui_anim` 死代码、空的 `destroy` | 无引用 / 遍历 `R` 被 pcall 吞错 | 删除 `ui_anim.lua`，销毁统一走 `W.destroy_pages()` |

## 刷新分级（`app_config.ANIM`）

| 层 | 频率 | 说明 |
|----|------|------|
| 指针 | 15Hz（66ms） | 角度量化到整数度，`key` 不变不重绘 |
| 进度弧 | 5Hz（200ms） | `key = end_angle*4 + mode`，换模式必换色 |
| 电量段条 | 6.7Hz（150ms） | 段位按 SOC 量化 |
| 指示灯 | 10Hz | 转向灯 1Hz 闪烁（`sim.blink`），亮/暗两套色值 |
| LIVE 呼吸点 | 1.3Hz | 750ms 翻转 alpha（70/255） |
| 文本 | 每帧比对 | `W.st` 内容没变不调 `set_text` |
| 时钟 / 日期 | 1Hz | `os.date("*t")` |

主循环 33ms 一拍（约 30fps），`ui.tick(dt)` 依次推进仿真与各组件。

## airui 能力边界（硬约束）

- **无旋转 / 渐变 / 阴影 / 动画**：指针靠每帧重算端点角度；渐变环用 8 段纯色 arc 近似；
  发光用低透明度同色填充；指示灯「暗」态用 `cfg.dim_hex()` 压暗而不是透明度。
- **弧线只能折线近似**：环形进度用 `line` + `round_start/round_end` 每 1° 一段（最多 270 段），
  内圈弧用 `arc` 图元（仅 1px 无圆头，作为衬线）。
- **容器 `set_color(c, opa)` 只改背景，不带子控件**：明暗靠两套色值，不用父容器 alpha。
- **`on_click` 只能写在创建参数里**：所以回调由 `ui.lua` 生成闭包下传。
- **hzfont 行高 = 字号 + 3**：`W.label` 自动兜底；最小字号 16，标题只用 ASCII（不赌符号字形）。

### 设计稿减法（只动 html，固件待同步）

第一版 html 把固件的每个字段都画上了，结果每个数字都对得上、但**第一眼看不出哪个数字是什么**。
这一版按「同一个数字只出现一次 + 每个数字都得有中文标签或单位」收敛：

| 原来 | 现在 | 原因 |
|------|------|------|
| 表盘 9 个刻度数字 | 0 / 40 / 80 / 120 / 160 五个 | 密排小字与中心大字抢注意力 |
| 表盘内 `CHRONO` + `ODO 12860 KM` | 删除 | CHRONO 无语义；ODO 与底部带重复 |
| 底部 4 栏 RANGE/ODO/TRIP/AVG | 3 栏 总里程 / 本次里程 / 平均速度 | 续航移进电池卡，一个数字不再出现两处 |
| 电池卡 `RANGE 186 KM` | `可行驶 186 km` | 说人话，别用字段名 |
| 功率卡 `EFFICIENCY 24 Wh/km` | 删除，改条下 `0 / 4 / 8 kW` 量程 | 效率是工程师指标；条没有刻度等于没信息 |
| 温度卡 `MOTOR` / `CTRL` | `电机` / `控制器`，单位写进标题 | 缩写看不懂 |
| 骑行卡 RIDE + AVG 两列 | 只留 `本次骑行时长 0:03:24` | 均速在底部带已有；时长改 `h:mm:ss` 防误读 |
| 指示灯 `TURN LEFT … BRAKE ASSIST` | `左转 / 远光 / 制动 / 右转 / 电池 / 防滑` | 全大写长词是最大噪音源 |
| 顶栏 `GPS / 4G / BT` | 删除 | 纯装饰，真机没有对应数据源 |
| 模式 `ECO/NORMAL/SPORT` | `经济 / 标准 / 运动` | 与中文界面统一 |
| 日期 `TUE`、`LIVE` | `周二`、`实时` | 同上 |

数字层级现在两级：车速 / 电量 64 → 里程/时长 34 → 标签 16，且每级颜色不同。
（原第四级「温度 22」随温度卡下线一起消失，见下方「右列重排」一节。）

`luac -p` 与 `layout_check.py` 不受影响（本轮只动设计稿）。固件 `code/` 仍是英文标签 + 4 栏底带，
**同等待视觉确认后一并改**，同步点：`ui_indicators` 的名称表、`ui_cards` 的标题与副标题、
`ui_bottom` 的栏数、`ui_topbar` 的 GPS 标签、`app_config.MODES` 增加中文名。

### 透明表盘 + 档位氛围色

两个改动互相成全：表盘中间的实心圆盘去掉，背后的光才透得上来；底部再铺一层档位色的氛围光，
整个界面就跟着 ECO/NORMAL/SPORT 变色。

- **表盘透明**：`buildDial` 不再画 `face_r` 那块实心圆（原来暗色是 `#0B0916`，把背景全遮死了），
  只留 `glow_r` 一层 `fill-opacity:0.16` 的雾光 + 1px 细边（`opacity:0.30`）。
  刻度、指针、轴心盖仍然是实心，中心大数字对比度不受影响。
- **底部氛围光**：新增 `#amb`（`left:0;top:0;1024x600`、`pointer-events:none`，盖在卡片之上但不挡点击），
  两层径向渐变 `58%x22% at 50% 100%` + `95%x50% at 50% 104%`，颜色 `var(--mode-col)`，
  alpha `0.20`（暗）/`0.13`（亮）。因为整屏铺满，几何上不可能越界。
- **档位色统一入口**：`setMode` 一处写 `--mode-col`（底部氛围）和 `--glow-fill`
  （`= mix(档位色, bg, 0.72)`，同时喂 `#screen::before` 中心辉光和 `dialGlow`），
  切档时表盘雾光、中心辉光、底部光晕一起变。
- **验证方式**：截图后按屏幕坐标采样像素（`k=1.0466`，`screen` 居中偏移 `24,36`），
  三档底带同一坐标分别为 `(15,31,45)` 青 / `(29,24,46)` 紫 / `(37,21,39)` 品红，
  参照点（右列卡片内部）恒为背景色 `(13,11,23)`——说明染色只发生在底部；
  表盘内 `(512,180)` 三档为 `(12,48,60)/(39,33,63)/(56,28,49)`，而不再是固定的 face 色，证明圆盘确实透明了。
  另外支持 `?mode=1/2/3` 直接进档位，便于复现对比图。

> 固件侧注意：LVGL 9 **没有径向渐变**。真机同步时用 `bg_grad`（`dir=ver`，底部亮→上方透明）
> 铺一条线性渐变，或叠 2~3 个同心 `shape` 圆递减 alpha 近似，效果等价、成本都很低。
> 表盘透明则是纯删代码：去掉 `ui_dial` 里 face 圆与描边，保留雾光圆并把 alpha 降到 0.16。

### 玻璃卡片

上层卡片改成半透明，背景透上来。**前提是背景必须有东西可透**——所以这一节是两件事一起做的，
只做一半会得到「8 个描边浮在纯黑上」的幽灵框。

- **背景侧光**：`#orbs` 两束圆心落在屏外的径向光（`at -7% 48%` / `at 107% 42%`，
  半径 `47% 73%`），颜色统一取 `--mode-col`，亮色主题用 `--orb-a:0.62` 整体压一档。
  ~~早期是三个 `border-radius:50%` 实心圆（左 `-80,16 430x296`、右 `676,-36 430x300`、
  表盘下 `266,326 492x300`，alpha `.14/.12/.11`）~~：单层 opacity = 硬边，真机上一眼看得出「三个圆」，

### 背景去硬边：三个圆 → 两束侧光

真机反馈「背景三个圆形太突兀，底部那个大圆弧反而好看」。原因不在"圆"，在**硬边**：

| | 旧的三色斑 | 底部大圆弧 |
|---|---|---|
| alpha 层数 | 单层恒定 `36 / 31 / 28` | 6 层同心叠加，每层 `9` |
| 圆心 | 都在屏**内**（`135,164` / `891,114` / `512,476`） | 在屏**外**（`cy 624 / 600`） |
| 看到的结果 | 完整椭圆，边界 alpha 一步归零 → 硬边圆斑 | 只有弧顶，外层逐级淡出 → 看不到轮廓 |

底部弧光好用，靠的正是后面这两条；三个色斑一条都没满足，所以扎眼。改法：

- **左/右**：拆成 2 束 × 6 层同心椭圆，圆心移到屏外 `cx = -70 / 1094`，`cy = 274`（卡片中线），
  半径 `155/215/275/335/395/455`（等距 +60），opa `23/19/16/13/10/8`。
  最外层渗到 `x = 385 / 639`，探进表盘两侧但不越过中心 512，中间仍是干净的。
- **中间（原 `512,476` 那个）**：直接删掉——表盘已有随档位变色的雾光，底部又有 `amb` 大弧，叠着只会变浑。
- **底部 `amb`**：不动（你说好看的那个就是它）。

侧光梯度验算（左束，`dx = x + 70`，六层叠加后的**合成 alpha %**，`1-Pi(1-ai)`）：

| x | dx | 层数 | 青（经济） | 紫（标准 ×1.05） | 品红（运动 ×1.03） |
|---|---|---|---|---|---|
| 24 | 94 | 6 | 30.3% | 31.7% | 30.9% |
| 110 | 180 | 5 | 23.4% | 24.7% | 23.7% |
| 160 | 230 | 4 | 17.2% | 18.2% | 17.2% |
| 210 | 280 | 3 | 11.7% | 12.4% | 11.7% |
| 256 | 326 | 3 | 11.7% | 12.4% | 11.7% |
| 310 | 380 | 2 | 6.9% | 7.3% | 6.9% |
| 385 | 455 | 1 | 3.1% | 3.1% | 3.1% |
| 500 | 570 | 0 | 0 | 0 | 0 |

青的 alpha 低但色亮、紫/品红 alpha 高但色暗，乘上各自线性亮度后**有效亮度完全对齐**
（青 `0.303×0.349=0.1059`、紫 `0.318×0.336=0.1066`、品红 `0.309×0.347=0.1070`，差 **<1.1%**），
所以三档看起来一样大、一样显眼。右束镜像（`dx = 1094 - x`）。

**为什么必须是 6 层而不是 4 层**：第一版用 `156/372/264/480` 四层，层数沿 x 几乎不变，
左列卡片 `dx 94..326` 全落在"最内层之外"的同一档 → 整张卡一个 alpha，真机上看就是"一片均匀的浅色"。
半径必须等距铺开，层数才会在卡片宽度内真正逐级递减。

**半径为什么是 455 而不是 380**：真机反馈"环还要再大一些"，半径整体 ×1.2。
注意扩大半径会让固定宽度的卡片落在**更靠内**的区间（层数变多 → 卡片整体变亮、梯度变缓），
所以同时把外侧两层 opa 从 `4/5` 提到 `5/6`，否则边缘更淡、环反而看起来更小——这是两个必须一起改的量。

**档位补偿 `GLASS.orbA = {1.00, 1.05, 1.03}`**：几何比值是
`青的线性亮度 / 该色的线性亮度`。sRGB 必须**先线性化**再按 `0.2126R+0.7152G+0.0722B` 加权：

| 档位 | 色值 | 线性亮度 L | 几何比值 | 叠加回代后取值 |
|---|---|---|---|---|
| 经济 | `#22A8F5` | 0.349 | 1.00 | **1.00** |
| 标准 | `#A78BFA` | 0.336 | 0.349/0.336 = 1.04 | **1.05** |
| 运动 | `#F472B6` | 0.347 | 0.349/0.347 = 1.01 | **1.03** |

> 为什么 1.04 还要回代成 1.05：alpha 叠加是 `1-Pi(1-ai)`，不是线性相加，
> 乘 1.04 后合成略低于目标，所以要按叠加结果反解。
>
> 青色先后被推蓝两次（`188° → 196° → 202°`），线性亮度一路从 0.531 掉到 0.349，
> 与紫/品红的差距从 55% 收敛到 3~4%，补偿系数才从 `1.66/1.62` 降到 `1.05/1.03`。
> 补偿量变小不代表可以删——差 3% 时外圈仍会提前截止，肉眼就是"紫的环小一圈"。

> 踩过的坑：第一版直接拿 8bit 原始值算，得出"只差 15~20%"，给了 `1.18 / 1.28`。
> 实际线性亮度差 **55~60%**，补偿远远不够——真机反馈就是"绿的环明显更大，另外两个小一圈"。
> 外圈 opa 提不上去就到不了可见阈值，光会提前截止，这才是"变小"的机制（不是几何不同）。
