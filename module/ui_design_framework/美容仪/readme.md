# 美容仪 · AirUI 真机界面

LuatOS + AirUI（底层 LVGL9）单屏界面，对应 `docs/美容仪UI效果稿.html` 的落地实现。
屏 1024×600 RGB，触摸 GT911（i2c1）。

**双主题**：日间「米白 + 墨青」（`美容仪UI效果稿.html`）与夜间「深蓝科技」
（`美容仪UI深蓝科技稿.html`），点顶栏右侧胶囊按钮即时切换，上电默认日间。

```
美容仪/
├─ code/            运行期脚本（连同 6 张 png 一起进 luadb）
├─ docs/            效果稿 / 出图脚本 / 打包脚本（不进固件）
└─ README.md
```

## 1. 烧录

1. `code/` 下 12 个 `.lua` + 6 个 `mode_*.png` 全部放进 luadb 根目录；
2. `main.lua` 为入口（`PROJECT = "beauty_device"`）；
3. 上电顺序：power → lcd(RGB 1024×600) → airui.init → 字体（16/18/28）→ 触摸 → 状态恢复 → 建界面 → 背光淡入 → 33ms 主循环。

设备树/引脚全在 `app_config.M.HW`，换板只改这一处；型号、时序、固件与依赖库的完整清单见 **§0 硬件与固件环境**。

## 2. 分层

单向依赖：`main` → `ui` → `ui_*` 页面模块 → `ui_widget` 安全原语 → `airui`。

| 文件 | 职责 |
|---|---|
| `app_config.lua` | 双色板（`PALETTE.day/night`）/ 硬件 / 动画参数 / 布局尺寸，**唯一改数值的地方** |
| `app_state.lua` | 6 种模式、档位、倒计时、运行态；fskv 落盘（可选，没有也不崩） |
| `ui_widget.lua` | 唯一控件入口：`box / bar / label / text_mid / num / shape / polyline / press / image / image_raw / tween` + 主题登记与重涂 `repaint / set_color / set_border / set_items` |
| `ui_topbar.lua` | 品牌、主题切换胶囊、电量胶囊、时钟、发丝线 |
| `ui_carousel.lua` | 单焦点轮播（左露边 / 焦点 / 右露边）+ 页码点 + 微缩过场 |
| `ui_overview.lua` | 三张概览卡：模式/档位/时长 + 10 段进度线 |
| `ui_tray.lua` | 连接态、电量、提示文案、开始/暂停主按钮 |
| `ui.lua` | 页面装配、三卡与轮播同步、每帧 tick |
| `drv_*.lua` | lcd / tp / power 驱动（从 `电动车仪表盘` 复用） |

**所有控件只走 `ui_widget`**，禁止裸调 `airui.button/container` 做热区或显隐。

`ui_widget` 内置几何收敛：容器创建时登记 `cw/ch = 外框 − 2×border_width`，
每个子控件创建前把 `x/w`、`y/h` 夹进 `[bw, bw+cw] × [bw, bw+ch]`，
越界则收缩并按 tag 去重打日志（`[uiw] 越界已收敛`）。真机上看到这条日志，
说明布局算错了，要回去改数字，不是靠兜底。

## 3. 微缩过场（切模式的动画）

真机上唯一能做缩放的手段是 `airui.image` 的 `zoom`（256 = 100%），所以：

1. `render(i)` 换 `src`，三槽同步；
2. `animate()` 立刻 `set_zoom(基准×107%)` + `set_opacity(130)`，6 帧（每帧 33ms）收到 `基准 / 255`；
3. `token` 自增作废旧 tween 的后续帧 —— 连续点箭头时不会两个动画抢同一个 zoom。

`基准` 不是固定 256：日间是 256（图铺满裁切层），夜间是 210（图缩进暖白窗口内，
见 §7）。起止点必须一起按基准折算，否则从 274 直接掉到 210 会有一次「猛缩」。

两个容易踩的坑，已在代码里绕开：

- **不能用 `fit="cover"` 后再动画**：`update_align()` 会把 pivot 强制成 `(0,0)`
  并把 scale 改成覆盖缩放值，`set_zoom` 会顶掉它，图变成 1:1 且从左上角放大（往右下漂）。
- 因此图片一律用 `image_raw`（`fit="center"` + widget 尺寸 = 图片原始尺寸），
  外面套一层无描边的裁切容器，图按 `(容器−图)/2` 负偏摆进去居中裁切：
  焦点槽 `(418−420)/2 = −1, (262−280)/2 = −9`，侧槽 `−94 / −37`。
  `fit="center"` 不动 pivot，默认 `(50%,50%)` 按原始尺寸算，才是绕画面中心推近。

## 4. 图片资源规格（硬门槛）

`docs/gen_mode_png.py` 生成 6 张 `mode_*.png`：**420×280，单 IDAT 块**。

- 硬件解码只认单个 IDAT：`PIL` 默认会切出几十个块 → 真机直接拒（日志 `multiple IDAT blocks`），
  所以脚本里手写 PNG（整幅像素 → 一个 zlib 流 → 一个 IDAT）；
- 解码内存 `w×h×4 = 470,400` 字节/张，同屏 3 张约 1.41MB，Air1603（4MB 缓存）余量充足；
- 换成更大底图前先算 `w×h×4`，超缓存就是「日志干净、图不显示」。

改图流程：改 `docs/img/mode_*.png` → `python docs/gen_mode_png.py` → 覆盖 `code/mode_*.png`。

## 6. 已知限制

- **时钟**：`os.date` 无 RTC/NTP 时显示 `00:00`（本工程未接网络，也不做 SNTP）。
  要真时间就接 `rtc`/`sntp` 后重启一次主循环的时钟刷新即可（`ui_topbar.tick` 每秒刷一次）。
- **电量**：两个位置都预留了 `set_batt(0..99)`，当前是占位值（`78`），接 ADC 后调用即可。
  胶囊里只有两位数字格，`100%` 会被钳到 `99`；百分号是独立 label（`num` 的窄格 5px 装不下 16 号字形）。
- **档位/模式落盘**：`fskv` 存在且 `init` 成功才生效；PC 模拟器上直接跳过。
- 会变的数字全部走 `U.num`（等宽格），禁止整串 `set_text`：hzfont 数字不等宽，
  模式页码 `04 / 06`、倒计时 `15:00`、时钟一变就会左右跳。

## 7. 深蓝科技风效果稿

`docs/美容仪UI深蓝科技稿.html` + `docs/preview_blue.png`

色板（对比度已实测，相对 `bg #070C16`）：

|---|---|---|---|
| `bg` | `#070C16` | — | 页面底（近黑蓝） |
| `panel` | `#0C1626` | 1.16:1 | 卡片底（与亮色同级，仍必须配描边） |
| `line2` | `#28405F` | 1.90:1 | 块轮廓（暗底要更硬） |
| `ink` / `ink2` / `ink3` | `#E6EFFC` / `#A9BDD6` / `#7A8FA8` | 16.1 / 9.7 / 5.8 | 三档文字 |
| `blue` | `#4C8DFF` | 5.9:1 | 描边 / 刻度 / 进度（**不当按钮底**） |
| `sky` | `#7DD3FC` | — | 高光点缀（角标、当前项、辉光芯） |

两条与亮色稿不同的处理：

1. **蓝色分工**：亮蓝 `#4C8DFF` 压白字只有 3.1:1，当不了按钮底；
   按钮底用 `#1D4ED8`（白字 7.5:1），`blue / sky` 只做文字、描边、辉光、刻度。
2. **器件照片不做任何调色**（这一版的核心取舍）：六张图是米白底，机身白 250 ≈ 背景 249，
   抠图分不开，染色后又变成青蓝全息图、认不出是器械。所以图片 `filter: none`，
   改用「深色相框 + 居中样本窗」（`--pad` 控内缩、`--zoom` 控缩放），
   白底照片嵌在深蓝面板里，器械保持真实颜色。
   代价：白窗亮面积仍偏大，焦点只能靠蓝色发光描边 + 侧卡 `opacity` 变暗区分。
   要根治只能重出**深底产品图**（暗背景 + 浅色机身），那时白窗问题自然消失。

### 7.2 深框亮窗怎么在真机上做的（不改几何）

效果稿是「图片内缩 `--pad` + `object-fit:contain` + 暖白窗底」。真机不能照搬：
改 `fit` 会走 `update_align()` 把 pivot 强制成 `(0,0)`，之后的 `set_zoom`
变成以左上角为原点放大，动画会往右下漂（§3 的坑）。

所以 `ui_carousel.window_layers()` 用三层叠出等价观感，**几何一个数字都不动**：

| 层 | 内容 | 日间 | 夜间 |
|---|---|---|---|
| 垫层 | `win` 色容器，尺寸 = 内缩后的窗口 | `opa=0`（被图盖住） | `opa=255` 暖白 |
| 图片 | 仍是出血图（`image_raw`，`fit="center"`） | `zoom=256` 铺满整层 | `zoom=210` 缩进窗口 |
| 遮边条 | 4 条 `card` 色细容器，厚 `--pad` | `opa=0` 不可见 | `opa=255` 深蓝相框 |

窗口尺寸：焦点 `418−2×16 = 386×230`，侧卡 `232−2×10 = 212×186`。
夜间再给侧卡图片 `set_opacity(140)`，表达效果稿的 `.side{opacity:.55}`。

因为六张图是米白底，缩小后四周露出的就是垫层的暖白，和效果稿的白窗一致；
产品本身一个像素都不改色 —— 这是刻意的：白底产品图染色会变成青蓝全息图，
认不出是器械。

代价与效果稿相同：白窗亮面积仍偏大，焦点靠 `glow` 描边与侧卡变暗区分。
要根治只能重出**深底产品图**（暗背景 + 浅色机身），那时垫层与遮边条都可以拆掉。

## 8. 主题切换机制

### 8.1 原地覆盖 + 重涂，不重建页面

`cfg.C` 是全工程唯一活表，各 UI 模块顶部 `local C = cfg.C` 捕获的是**表引用**。
所以切主题只覆盖 `C` 的键值，控件一个都不销毁：模式、档位、倒计时全部保留，
也不会有 LVGL 对象泄漏（容器没有 `del` 路径，重建就是泄漏）。

`ui.set_theme(name)` 的调用顺序是死的，颠倒会出问题：

```
cfg.use_theme(name)      覆盖 C，并按「旧色值 → 新色值」重建 cfg.map
  ↓
W.repaint()              遍历登记表，把每个控件刷成新色；返回下发条数
  ↓
car.apply_theme()        摆正展示窗显隐：遮边条 opa、垫层 opa、基准 zoom、侧卡 opacity
  ↓
car.render(ST.S.i)       页码点与长条按新色落位
  ↓
top.set_theme(name)      顶栏按钮文案回写
```

`apply_theme` 必须在 `repaint` 之后：`repaint` 会用登记里的 `opa` 回填容器颜色，
先摆显隐的话会被刷回创建时的全透明，暗色下就是「相框不见了」。
反过来，`W.set_color()` 会同步写回登记，所以再怎么来回切都不会错位。

`repaint()` 返回 0 说明登记表是空的（控件没走 `ui_widget`，不该发生），
此时**回滚色板并打 `log.error`**，不做全量重建 —— 重建会丢状态。

### 8.2 为什么强调色要拆成 fill / glow

日间只有一个墨青，同一个值既当按钮底又当 1px 线条都没问题；夜间不行：

| 角色 | 日间 | 夜间 | 用途 | 依据 |
|---|---|---|---|---|
| `fill` | `#2C6E63` | `#1D4ED8` | 按钮底 / 档位条 / 进度段 / 页码长条 | 白字 7.5:1，当底必须够深 |
| `glow` | `#2C6E63` | `#4C8DFF` | 卡片描边 / 品牌圆环 / 状态点 / 顶栏竖条 | 5.9:1，细线在深底才够亮 |
| `on_fill` | `#FFFFFF` | `#FFFFFF` | 压 `fill` 底的文字与图标 | — |

`#4C8DFF` 压白字只有 3.1:1，当不了按钮底；`#1D4ED8` 当细线在 `#070C16` 上又糊成黑缝。

### 8.3 颜色传「令牌名」还是「色值」

`ui_widget` 的所有 `color` 形参既接受数值也接受字符串：

```lua
W.box(page, 0, 0, 100, 40, { color = "card" })   -- 令牌名：每次重涂直接取 cfg.C.card
W.label(page, 0, 0, 80, { color = C.ink3 })      -- 色值：走 cfg.map 旧值→新值
```

**日间 `fill` 与 `glow` 是同一个值**，而映射表的键是「旧色值」，一个键只能映射一个
目标色 —— 传色值这两个角色必然串味。所以凡是有多语义的令牌（`fill/glow/on_fill/win`
以及 `card/bg`）一律传名字，不进映射表；只有 `ink/ink2/ink3/line/line2` 这些值唯一的才传色值。

### 8.4 运行时改色必须走 `W.set_color`

`render()` / `set_lv()` / `set_prog()` / `set_run()` 里如果直接 `obj:set_color(...)`，
登记值会停在旧色，切到夜间再切回日间时映射对不上，表现是「一部分控件颜色不回来」。

同理托盘图标：`PLAY/PAUSE` 曾经是模块级常量表，`C.card` 在模块加载时就被固化成
日间的白色，切到夜间后按钮变成亮蓝底、白图标还压在上面（1.4:1）。
现在 `icon_items(run)` 每次按当前色板现算，并用 `W.set_items` 同步登记。
