## 一、通用方法：提示词的四层结构 + 一条优先级

### 第 0 层：先定优先级（新增）

> 「按 **P0 不崩/不卡 > P1 交互正确 > P2 像素还原** 的顺序做。每改一处，先说明影响哪一层；P0 没过不要做 P2。」

作用：AI 很容易一上来抠颜色、字号，结果刷新任务每帧报错、点击一次重建整页，演示时直接卡死。先把“能跑住”写成第一目标，后面的视觉优化才不会反复推倒。

### 第 1 层：素材 + 一句定位（不给抽象需求）

> 「参考这个视频/截图，逐屏复刻。**先出一份 1024×600 的 `preview.html` 1:1 预览稿**，再按稿子写 Lua。」

前五个项目都有 `preview.html`；音乐播放器没有单独预览稿，直接把 `docs/index.html` 当作唯一视觉真源。

作用：把视觉争议关进浏览器。Lua 侧只做"1:1 移植"，这是返工最少的一条。

### 第 2 层：硬件与框架事实前置成"不可协商项"

> 点亮顺序：供电轨 GPIO12/56/44/52 → `display.init("custom",{rgb时序})` → `airui.init(w,h)` →
> 首帧后背光 PWM3 → `airui.font_load(hzfont)` → `i2c.setup` → `tp.init("gt911")` → `airui.device_bind_touch`；
> 核心库不 `require`；`exwin` 必须 `require` 且勾"添加默认lib"。

作用：这类错误（`airui.init` 前建控件卡死、`font_load` 前调 airui 总线错误）表现为死机重启，
最难定位。写成前置约束后六个工程的 `main.lua` 点亮段几乎一致。

### 第 3 层：分层与文件结构写死

> 「`code/` 下 `main.lua`（点亮）/ `theme.lua`（配色+控件+页面工厂）/ `mock.lua`（数据）/
> `page_xxx.lua`（页面），`docs/` 放其余资料，`readme.md` 归档；其他工程不要动。」

作用：六工程同构，`theme.lua` 持续沉淀通用能力，新工程开局直接复用。
最终还统一成 `code / docs / readme.md` 三件套，并补齐 `docs/.gitkeep`。

### 第 4 层：验收可执行，并且必须真跑

> 「写断言跑给我看：模式切换后不能有残影、96 kHz 必须 60 根谱线、拖动进度条读数到 `02:00`、
> 长跑 6000 帧控件数不能涨。」

作用：把"我觉得改好了"变成 `PASS / FAIL`。两条链：

- 浏览器侧 `test_ui.js`：Playwright 逐行为触发 + 断言 DOM 文本 + 截图存档
- Lua 侧 `run.js`（fengari 跑真 Lua）+ `test2~test5` + `test_long`：**热区反查控件**后断言

## 二、逐项目复盘

### 2.1 天气预报（AirUI 第 1 个工程）

**参考**：Windows 11 天气应用深色版 · `1024×600`

#### 你的提示词（按阶段）

1. **立项**：「参考 Win11 天气应用深色版，做一个 AirUI 页面，先出 `preview.html` 1:1 预览稿，尺寸 1024×600。」
2. **结构**：「两页：页面 1 当前天气（城市名/天气图标/温度大字 40 号/体感/提示语/6 项指标条 +
   9 个 tab 的每小时预报）；页面 2 天气详细信息（12 张指标卡）。顶栏按钮互相切换，**不要页面滚动**，一屏放下。」
3. **数据行为**：「数据用 mock 虚拟。按 **城市×日期 固定缓存**，来回切视图数值不能变；少数指标 1.5s 随机游走模拟实时读数。」
4. **细节还原**（这一串决定了成品像不像）：「9 个 tab 各带 html 同款图例；概览/湿度/气压/可见度/体感温度要有**面积图渐变填充**；
   风速 tab 要小时风向箭头；云量要圆角胶囊柱；每个 tab 有**附加线开关**（体感温度/阵风/露点）；
   点城市名弹下拉（我的位置 + 4 城市，各带图标温度）。」
5. **约束**：「零 PNG，太阳/月亮/云/雨/雷阵雨图标全部 shape 画；字号 ≥16；双主题（顶栏月亮/太阳切换）。」
6. **修 bug（原话类型）**：
   - 「点列表只有标题高亮，主体不变」→ `mock.S.view` 存的是中文键，分支却写 `== "list"`
   - 「图表区整块空白」→ 读了 airui 句柄的 `.w/.h`，得 nil 被 pcall 吞
   - 「屏幕划不动了」→ 用了 `airui.touch_subscribe`
   - 「滑动卡顿」→ 全屏半透明面板逐像素混合
   - 「点了没反应」→ 回调里销毁了被点控件所在子树
7. **收尾**：「详情页拆成独立页面（12 卡不挂在长滚动里）；hzfont cache 提到 2048；写 readme 已知注意事项。」

#### 踩的坑

| 现象 | 根因 | 规避（落地位置） |
|---|---|---|
| 点列表只有标题高亮 | `mock.S.view` 存中文「图表/列表」，判断写 `"list"` | 分支用同一个值；theme 里定义键常量 |
| 图表区整块空白 | 读句柄 `.w/.h` 得 nil → 运算错误被 pcall 吞 | 布局 rect 全存局部变量（`page_weather.lua` 已改） |
| 屏幕划不动 | `airui.touch_subscribe` 接管/破坏输入管线 | **任何情况都不使用** |
| 滑动卡顿 | ①全屏半透明 `color_opacity` 逐像素混合 ②图表渐变填充整图混合 ③hzfont 缓存小反复栅格化 | ①`theme.blend()` 离线预混合 ②`cfg.fill=false` 只概览保留 ③cache 2048（失败回退 1024） |
| 点了没反应 | 回调内销毁锚点容器（use-after-free，错误被 pcall 吞） | 所有 `on_click` 走 `defer()`（`sys.timerStart(fn,30)`）+ 防抖 |
| 切页白屏 | 先 open 新窗再 close 旧窗 | 先 close 栈顶再 open |
| 报 `attempt to call a nil value`（bind_root） | 部分固件 `exwin` 没有 `bind_root` | `if exwin.bind_root then pcall(...) end` |
| 动态控件重复叠加 | 动态区子控件直接挂 scroll 容器 | 挂**锚点容器**，销毁锚点=整块销毁 |
| 环形/太阳弧线画不出 | `shape` 的 arc/ellipse 不可靠 | 多段折线 `ARC()`/`ELL()` 拼 |
| 实心圆消失 | `width=0` 被固件丢弃 | 实心圆 `width>=1`，圆心/半径四舍五入 |

#### 沉淀到通用层的规则

- 双调色板 `theme.cur + theme.PALETTES.dark/light`，`theme.C` 就地覆写（不换表）
- `defer()` 延迟重建 / 关闭弹层，成为之后四个项目的标准动作
- `theme.blend()` 离线预混合（后项目全部复用）
- 中文键要么全用中文、要么全用英文常量，不许混

#### 验收方式

离线桩自测：双页构建、城市下拉、9 tab 切换、附加线开关、日期卡切数据、主题切换、返回切页，`errors = 0`、控件越界 `warns = 0`。

### 2.2 3D打印机（AirUI 第 2 个工程）

**参考**：B 站《HMI串口屏-3D打印机案例》（兕腾科技）逐屏复刻 · `1024×600`

#### 你的提示词（按阶段）

1. **立项**：「复刻这个视频里的 3D 打印机 HMI，逐屏 1:1，UI 结构/配色/文案与视频一致。先出 `preview.html` 1024×600 定稿设计稿。」
2. **屏清单**：「首页三张大卡（打印/准备/设置）；打印-文件列表（左侧 5 个 .obj + 分页 `|< < 1/3 > >|`，右侧预览图+名称/日期+打印按钮）；
   打印中（2×2 指标 喷头 170/200°C、风扇 60%、热床 60/60°C、层高 0.1MM + 停止/暂停 + 进度条）；
   准备（移动轴/进退料/风扇/冷却/说明）；移动轴（单位胶囊 0.1/1/10MM + XYZ 数字框 + 十字方向键 + Z 键）；
   进退料（喷头温度滑块 + 进料 85.0MM / 出料 95.0MM）；设置（左竖排菜单 + 6 卡）；关于；网络 WiFi 弹窗；调平 3×3；软键盘。」
   外加 3 类弹窗：「是否进行一键调平」「是否停止打印?」「打印完成!」。
3. **约束**：「**零图片贴图**，图标全部 SVG/自绘，实机用 shape/line 复刻；全 UI 最小 16 号（标题 26~34）。」
4. **实现方式**：「单个 exwin 页 + 内部 `nav(name)` 切屏，重建统一 `defer()` 30ms；进度 0→100 每 120ms 递增（约 12 秒）。」
5. **交互细节**：「点任意 .obj 行右侧预览图/名称/日期同步切换；翻页 3 页 15 个模型；打印把当前选中模型带入打印中页；
   暂停→弹窗是继续/否停止；停止→弹窗是回文件列表（**不是首页**）；到 100% 弹「打印完成!」；
   移动轴按单位步进、⌂ 单轴归位；进退料出料弹橙色数字键盘；调平 3×3 格内 5 个数字可点 + 底部「已完成 N/5 点」。」
6. **修 bug（原话类型）**：
   - 「牛奶盒底部阴影没了、马克杯把手残缺、WiFi 图标只剩一个圆点」→ arc/ellipse 不渲染
   - 「卡片点两下才有反应」→ 子控件拦触摸
   - 「多行文案被裁成一行」→ 单 label 只显示一行
   - 「面包屑每段多出一倍空白、`>` 被推很远」→ 中文按 `#txt` 算宽
   - 「输入框内多一条灰底线 + 右侧灰竖线」→ container 判定溢出画滚动条
   - 「切浅色后这块黑底黑字」→ 固定黑底配 `C.text`
7. **收尾**：「用 Playwright 把上面每条交互都点一遍并断言文本，截图存 `shots/`；离线桩 33 项全过，`errors=0`、`warns=0`。」

#### 踩的坑（readme 归档 8 条）

| 现象 | 根因 | 规避 |
|---|---|---|
| 阴影/把手/WiFi 图标残缺、密码锁图标变小方块 | `shape` 的 `arc`/`ellipse` 图元实机不渲染 | 只用 line/circle/rect，弧线与椭圆环用多段折线 `ARC()`/`ELL()` 近似 |
| 图元整批不显示 | 小数坐标 | 坐标一律 `math.floor` 取整 |
| 卡片"点两下才响应" | 先画图标文字再设卡片 `on_click`，子控件拦触摸 | 画完内容后压一层 `theme.hit` 透明热区 |
| 面包屑/侧边菜单出现"方框/下划线" | `button` 默认带底色描边 | 改用 `label + hit` |
| 多行文案只显示一行 | 单个 `label` 不换行 | `dialog` 按 `\n` 拆多行 label 并自适应高度 |
| 面包屑空白过多 | 中文 3 字节/字 | 按 `floor((#txt+2)/3)` 折字数再乘字宽 |
| 输入框内多灰底线/右侧灰竖线 | `container` 内容溢出 → LVGL 画滚动条 | 输入框用 `airui.shape` 画填充+描边（shape 不可滚动），文字与热区挂对话框容器 |
| 浅色主题下黑底黑字 | 固定黑底 + `C.text` | 改用 `C.input` 随主题反转 |

#### 沉淀到通用层的规则

- `theme.icon` 模板：按 100×100 设计稿缩放，全部 line/circle/rect，共 29 种
- `theme.hit` 热区：解决"点两下"，后续项目全部采用
- `theme.txt`：调用方给"视觉块"，内部下移 y、收紧 h 到 `size*1.28`
- `theme.slider`：深轨 + 指示 + 旋钮，喷头温度/亮度/速度三处复用
- 切屏统一 `defer()`，进度驱动 `build` 返回 `(update, 120)`

#### 验收方式（`test_ui.js`，14 段）

文件列表选中→缩略图变；翻页/末页/首页；打印中名称与进度；暂停弹窗；继续后进度；停止弹窗→回列表；
100% 完成弹窗；移动轴切 10MM 后 X-；设置 PLA 改 200 + 灯光/声音切换；系统设置卡片数；WiFi 名称/密码掩码；
调平选中格与「已完成 N/5」；关于行选中。全部断言 DOM 文本，并截图存档。

### 2.3 智慧农场（AirUI 第 3 个工程）

**参考**：完竣世界《智慧农业数据可视化大屏》8 页 · 去掉中央地图 · 深青绿科技风

#### 你的提示词（按阶段）

1. **立项**：「参考这个智慧农业大屏的 8 个页面，**去掉每页中央的大幅地图/图片**，左右数据面板自适应铺满整屏。先出 `preview.html`。」
2. **规格**：「每页 2 列×3 行栅格、6 个面板，顶部 8 个导航按钮切页（当前页薄荷绿高亮）」，
   并给出逐页面板表（总览：基本信息/作物分布/产量预测/水肥/土壤/设备运行 …）。
3. **自适应**：「要能在 800×480 和 1024×600 上都跑，用 `display.getSize()` 读实际分辨率，失败回退默认。」
4. **允许贴图**：「图标用 emoji PNG，环形图/雷达图用预渲染贴图，雷达 3 帧用 `animimg` 轮播。」
5. **实现约束**：「面板四角括号用 shape 画；环形图**不要用弦线拼弧**（粗描边会畸形），用珠链圆环方案；chart 轴/图例禁用改自绘。」
6. **修 bug（原话类型）**：
   - 「页面后半截空白、数据全是 --」→ `tonumber(string.gsub(...))` 多返回值
   - 「柱子全挤在左边」→ chart `point_count` 没设
   - 「曲线断断续续」→ `set_values` 只收整数
   - 「文字整体跑到屏幕顶部导航区」→ 派生坐标漏加 `a.y`
   - 「`42.3%` 被折成两行」→ label 宽度只给 40
   - 「所有按钮都不触发」→ 漏 `airui.device_bind_touch`
   - 「图片不显示，日志 multiple IDAT blocks」
   - 「环形图像畸形粗条」→ width>4 + 圆头
7. **收尾**：「readme 写「已知注意事项」；Luatools 脚本区加 `code/` + `code/img`（40 个 PNG，保持目录）。」

#### 踩的坑（readme 归档 14 条，摘要）

| 现象 | 根因 | 规避 |
|---|---|---|
| 页面后半空白、数据 `--`、图表无数据 | 多返回值直接内联：`tonumber(string.gsub(s,p,r))` 把替换次数当 base | 多返回值先赋值取第一个；构建段 pcall + traceback |

| PNG 不显示 + `multiple IDAT blocks` | Air1603 PNG 硬件解码器不支持多 IDAT（浏览器导出 >32KB 会分块） | 全部重编码为单 IDAT（pngjs `chunkSize: 0x1000000`） |
| 贴图尺寸不对/被裁 | `airui.image` / `animimg` 不缩放，按原始尺寸从左上画 | 预缩放到控件尺寸：`ic_*` 16×16、`donut*` 193×143、`radar*` 286×143 |
| 环形图像畸形粗条 | 固件对粗描边 line（width>4 + 圆头）渲染不可靠 | 改"珠链圆环"：沿圆周每 10° 一颗 circle，按占比点亮 |
| 所有按钮无响应 | 缺 `airui.device_bind_touch(dev)` | `i2c.setup(1, i2c.SLOW)` → `tp.init("gt911",{})` → `device_bind_touch` 三步 |
| 屏幕黑屏/卡死 | RGB 屏固件不自动点亮；`airui.init` 前建控件卡死、之前 `font_load` 总线错误 | 严格点亮顺序，每步 pcall + 日志 |
| 切页白屏/残影 | 先开后关 | `sys.publish("SWITCH_PAGE")` 先开新窗再关旧窗（后续项目改用先关后开/预建 set_hidden） |
| 合并报"多余的 require" | 核心库已预加载 | 核心库不 `require`，扩展库必须 `require` |
| 换了固件字体不对 | 固件未内置中文字库 | `airui.font_load` 加 `path` 指向文件系统 ttf |

#### 沉淀到通用层的规则

- 分辨率自适应模板（`display.getSize()` + 默认 1024×600）
- 单 IDAT PNG + 预缩放规范（唯一使用贴图的项目，反过来定义了"零贴图"的价值）
- `theme.chart` 封装：禁用轴图例、整数化、`set_point_count`
- `theme.progress` 用 `shape:set_items()` 自绘（后来音频频谱的图元方案源头）

#### 验收方式

#### 踩的坑

**A. 死机与掉帧（本项目独有）**

| 现象 | 根因 | 规避 |
|---|---|---|
| 跑 1~2 分钟 HardFault（ramdump） | `set_items` 无条件 `lv_obj_invalidate`，传空表也会把整个 shape 标脏；6 个 shape 全刷≈每帧重绘整屏 → LVGL 堆高频 malloc/free 打爆 → `lv_malloc` 返回 NULL → 固件没判空 | `put()` 两件套：`drawn[sh]` 记录状态，空图元且已清空时**直接 return**；`set_text` 内容没变不重设（省矢量字栅格化） |
| 几分钟后 `task event too much` 断言（复位原因 6） | `sys.timerLoopStart` 固定周期投递，与回调耗时无关，帧一重就积压 | `sys.taskInit + sys.wait`：跑完本帧才开始计时，永不积压 |
| 环形模式卡顿 | ①线宽 6 + 圆头（每段两个小圆填充）②1 个空心盘沿 + 3 个脉冲弧（arc 逐行算 mask） | 线宽 6→5、去圆头；唱盘全改实心圆叠色，一个 arc 都不画；扩散环改静态淡环（只画一次） |
| 侧柱/HUD 也每帧刷 | 无差别全量重绘 | 侧柱每 3 帧重绘（省 2/3 的 32 个 rect）；HUD 文字每 10 帧刷一次；冻结时降到每 10 帧 |
| 波形太密、帧成本高 | 折线 63 段 + 淡线 22 段 | 63→31 段、22→14 段（视觉几乎无差） |

**B. 视觉与交互**

| 现象 | 根因 | 规避 |
|---|---|---|
| 谱线来回毛刺、不像真实频谱 | 直接线性跟随目标值 | "快升慢降"：上升 `k*1.15`、下降 `k*0.75`，抖动幅值收到 ±0.035 |
| 切模式留残影 | 只建新图元不清旧的 | 切柱状/波形/环形时主动清空上一模式 shape 图元（`put(sh, {})`） |
| 切主题后胶囊文字/谱线不变色 | 已创建控件的颜色不会变 | `theme.toggle_theme()` 就地覆写 → `sys.timerStart(function() theme.rerender_page() end, 30)` 重建整页（事件外） |
| 拖动进度条与自动推进打架 | 程序写 slider 触发回调被当用户操作 | `seek_hold` 计数锁 + `sync` 位标记程序回写 |
| 切歌"看着没变" | accent 撞色（Afterglow 外圈与上一首同色） | 四首 accent 互不相同 + 断言"主色互不重复" |
| 提示条文字超出内容区 | 中文宽度按字节算 | 按字数折算（316 ≤ 318 通过） |
| 带边框容器出现滚动条下划线 | 子控件溢出 | 4 个子控件全部收进边框内 |

**C. 工程约束类**

| 坑 | 规避 |
|---|---|
| 单 shape 图元 >32 吞后半段 | 分批建 shape（峰值正好 32，达上限即为设计值） |
| shape 容器范围不够 → 图元被裁剪 | 容器盖住整块图形 |
| 小数坐标丢整批图元 | 全取整 |
| 点击回调里重建子树 | 只改状态 + `set_color/set_text/set_hidden`，重建走 timer |

#### 沉淀到通用层的规则

- 帧循环模板：`build` 返回 `(update, interval)`，`make_page` 用 `taskInit+wait` 起帧
- `put()` 批量图元（后续所有 shape 动画的标配）
- 性能预算三件套：`set_items ≤3/帧`、`shape ≤32 图元`、`6000 帧控件数不增长`
- 主题切换必须在事件外重建（`sys.timerStart(fn,30)`）
- 交互热点用 `theme.hit` 反查断言（离线桩能"点"真控件）

| 现象 | 根因 | 规避 |
|---|---|---|
| 按下播放偶发卡住，频谱/时间全停 | 刷新 task 没有逐帧 `pcall`，任意一帧异常直接让 task 退出；按键回调还活着，看起来像“卡住” | 每帧 `pcall(function() ... end)`，异常只 `log.error("music","tick error: ...")`，下一帧继续 |
| 按一次播放要等明显一下 | `toggle_play()` 同步刷新播放/曲库/收藏/迷你条四个区域，一次点击几十次 `set_items` | `refresh_all()`：当前可见页立即刷，其他页 `theme.defer` 延后一帧 |
| 进度条拖动时读数乱跳 | 程序 `set_value` 触发 slider 回调，被当成用户拖动写回 `P.t` | `p_syncing`/`vol_syncing` 重入守卫提到函数首行；滑杆回调也先判断 sync 位 |
| 极小概率切歌后停住 | 随机模式用 `while nxt == P.i do nxt = math.random(n) end`，理论上有长时间不退出风险 | 改成 `((P.i - 1 + math.random(n - 1)) % n) + 1`，一次算出不同曲目 |
| 某个控件为 nil 时刷新直接报错 | `pcall(R.x.method, R.x, ...)` 在 `pcall` 外先索引 `R.x.method`，nil 时已经抛错 | 新增 `call(obj, method, ...)`：先判空再取方法，再 `pcall` |
| 空图元也每帧重绘 | `set_items` 无条件 invalidate，空表也会把整块 shape 标脏 | `put()` 用 `drawn[sh]` 记录状态，空图元且已清空直接 return；`set_text` 同值不重设 |

**B. 输入与滑杆**

| 现象 | 根因 | 规避 |
|---|---|---|
| 搜索键盘挡住表格、挡住搜索/取消 | 输入栏和键盘各自定位，层叠关系不清 | 按 `y=-20, h=250` 算键盘顶边，输入框和“收起/搜索/取消”栏整体放在键盘上沿，并使用不透明底板 |
| 点取消后键盘还留着 | 先销毁面板/输入框，键盘没先隐藏 | `close_search_input()` 先 `kb:hide()`，再 `theme.defer` 销毁输入层 |
| 键盘收起后展不开 | 只调用了 `hide()`，没有恢复入口 | 搜索栏加“收起键盘/展开键盘”按钮；展开依次尝试 `show()`、`set_hidden(false)`、重建键盘并 `attach_keyboard` |
| 滑杆拖不动 / 拖了没反应 | 透明 slider 的触控区小于视觉轨道；回调参数不稳定 | 扩大透明触控区；回调 `tonumber(v)`，取不到时 `get_value()` 兜底 |
| 点按钮要点两下 | 子 label / shape 拦触摸 | 可点区域最后压一层 `theme.hit` 透明热区 |

**C. 视觉与布局**

| 现象 | 根因 | 规避 |
|---|---|---|
| 夜间迷你条轨道、按钮、图标糊成一片 | 深色底复用了日间 `track/btn/line` | 增加 `track2/btn2/mini/mini_border` 夜间专用色；播放键整颗琥珀实色，符号固定白色；上一首/下一首 22 号 |
| 播放键不是“全黄”，中间发浅 | 外圈实色 + 内层 `mix(playbg, white, 0.14)` 渐变圆 | 去掉内层圆，只留一颗 `C.playbg` 实色圆；符号改 `C.white` |
| 循环图标偏小、偏下 | `20×20` 容器 + 20 号 symbol | `24×24` 容器、22 号 symbol，放在 46×46 按钮正中间 |
| 队列时间列对不齐 TRACKS 的 A | 时间 label 的 x 随行内容变化 | 固定 `x=424`、左对齐，表头与行共用同一基准 |
| 排序菜单与“默认排序”错位 | 菜单挂 screen，x 没加页面偏移 `PX` | 菜单 `x = PX + 584`，与按钮同基准 |
| 卡片/空态底部多一条白线 | 带边框容器 + 子控件溢出，LVGL 画滚动条 | 卡片改无边框 `theme.box()`；子控件全部收进卡片范围 |
| 标签框偏小、文字挤 | 框高和字号不够 | 标签框加高、字号 18，按内容重新排两行 |
| 主题按钮白天/夜间方向不清 | 只用文字/颜色区分 | 加一条 2×14 指示线：白天在左，夜间在右 |

#### 沉淀到通用层的规则

- 刷新任务模板：`sys.taskInit + sys.wait(100)` + **每帧 pcall** + 帧计数；异常不退出循环
- 点击刷新模板：`refresh_all()` 可见页立即刷，隐藏页 `theme.defer`；禁止在点击回调里同步刷全部页面
- 滑杆三件套：透明 slider 扩大触控区 + `get_value()` 兜底 + `p_syncing/vol_syncing` 重入守卫
- nil-safe 调用：`call(obj, method, ...)` 统一替代 `pcall(obj.method, obj, ...)`
- 输入法模板：键盘 `y=-20/h=250`，输入栏贴键盘上沿；关闭顺序 `hide() → defer destroy`
- 主题模板：`theme.apply()` 就地覆写 `C` + `theme.register/recolor`，不整页重建
- 页面模板：四屏预建 + `set_hidden`；迷你条只在非播放屏出现

#### 验收方式

当前没有 Playwright/离线桩，采用**手工 + 日志**验收：

- 连续按播放/暂停 20 次，界面不冻结，频谱/时间持续刷新；
- 连续开合键盘 10 次，取消后无残留、无遮挡；搜索/取消/收起/展开都可用；
- 进度条、音量条各拖动 10 次，读数跟手，松手后不被自动推进覆盖；
- 主题切换 10 次，颜色原位变化，无白屏/残影；
- 连续运行 10 分钟，日志无 `tick error`，控件数量不持续增长；
- lint 0 error（仅保留 AirUI/LuatOS 全局对象的 warning）。

## 五、踩坑总表（平台级，20 类）

| 类别 | 坑 | 规避 |
|---|---|---|
| 点亮链路 | `airui.init` 前建控件卡死；`font_load` 前调 airui 总线错误；RGB 屏不自动点亮 | 严格顺序 + 每步 pcall/日志 |
| 触摸 | 漏 `device_bind_touch` → 全部按钮无响应；`touch_subscribe` 破坏输入管线 | 三步走；永不用 touch_subscribe |
| 库 | 核心库 `require` 报多余；扩展库漏 `require` 合并失败 | 核心库不 require，`exwin` 必须 require |
| 页面栈 | 先开后关 → 白屏；部分固件无 `bind_root` | 先 close 再 open；`if exwin.bind_root then pcall` |
| 切屏 | destroy + 重建 → 残影/错位/慢 | 预建 + `set_hidden`（门铃）或内部 nav + defer 重建（打印机） |
| 文本 | label 顶部对齐；单 label 只显示一行；中文字宽按字节算 | `theme.txt` 收紧 h；多行拆分；按字数折算 |
| 布局 | 子控件超父容器被裁剪；container 溢出画滚动条；派生坐标漏加父 rect | 热区独立建；溢出区改 shape；派生坐标带 `a.y` |
| shape 绘图 | arc/ellipse 不渲染；小数坐标丢整批；图元 >32 吞后半段；容器范围不够被裁剪；`width=0` 实心圆被丢 | 折线拼弧；全取整；32 一批；容器盖满；`width>=1` |
| chart | `set_values` 只收整数；`point_count` 默认 120/24；轴/图例坐标不受控 | 取整；`set_point_count`；禁用轴图例自绘 |
| 图片 | PNG 多 IDAT 硬件不解码；贴图不缩放 | 单 IDAT 重编码；预缩放 |
| 事件 | 回调里销毁自身（use-after-free，pcall 吞错） | `timerStart(fn,30)` |
| 性能 | `timerLoopStart` 积压断言死机；空 `set_items` 打爆堆；全屏半透明混合；圆头/arc 逐行 mask | `taskInit+wait`；`put()` 跳过；`blend()` 预混合；去圆头/不用 arc |
| 主题 | 切主题后已建控件颜色不变；固定底色配主题文字 | 就地覆写 + 事件外重建；固定底用 `C.input` |
| 数据/编码 | 中文键与英文判断不一致；`tonumber(gsub())` 多返回值；中文宽度 | 键常量统一；先赋值；折算字数 |
| 硬件外设 | 背光 `setDuty` 需 start/open 态；拖动高频刷 PWM 闪烁 | 兜底 setup+start；60ms 节流 |
| 工程管理 | 脚本区漏 `img/` 目录；空 `docs/` 进不了 git | 烧录清单写进 readme；`docs/.gitkeep` |
| 刷新任务 | 帧循环没有逐帧 pcall，单帧异常让 task 永久退出，表现为“突然不动” | 每帧 pcall + 日志；异常不 break |
| 长帧 | 一次点击同步刷新多个隐藏页面，产生几十次 `set_items` | 可见页立即刷，隐藏页 `defer` 延后 |
| 交互回写 | 程序 `set_value` 触发 slider 用户回调，自动推进与拖动互相覆盖 | `p_syncing/vol_syncing` + 回调首行守卫 |
| 输入法 | 键盘位置与输入栏分层不清；关闭顺序错误导致键盘残留 | 键盘 `y=-20/h=250`，输入栏贴键盘上沿；`hide()` → `defer` 销毁 |

## 八、最值得保留的经验

1. **设计稿先行**：前五个项目用 `preview.html`，音乐播放器用 `docs/index.html`，Lua 只做 1:1 移植。六个项目零例外，返工最少。
2. **验收可执行化**：把"看起来对"翻译成断言（热区反查、计数埋点、长跑对照）。
   "141 → 141"这种对照，比任何肉眼检查都可信；音乐播放器则用“连续 20 次操作 + 日志无 tick error”兜住偶发卡死。
3. **踩坑进注释，不进记忆**：`theme.lua` 头部"务必遵守"清单从 4 条涨到 15 条，
   新工程开局读一遍就少踩一轮——这是六个项目里复用率最高的一份资产。
4. **约束前置，而不是事后修补**：`timerLoopStart`、`arc` 不可用、32 图元上限、字号 ≥16 这些，
   一旦写进提示词就不再犯；写成"事后 bug"每次都要重新定位一遍。
5. **反馈给现象，不给评价**："点两下才响应"能直接定位到触摸链路，"不好看"只能靠猜。
6. **能跑住 > 像**：音乐播放器先暴露了“按播放偶发卡死”，根因是刷新 task 无 pcall、一次点击刷四页、滑杆回写重入。先做 P0（不崩/不卡），再谈像素还原。
7. **刷新任务必须异常隔离**：任何帧循环都要“每帧 pcall + 日志 + 下一帧继续”，不要让单帧异常把整个 task 摘掉。
8. **交互状态要可重入**：滑杆、键盘、主题切换都要有 sync 位或开合状态，否则程序回写和用户操作会互相覆盖。
9. **输入法是独立子系统**：键盘位置、输入栏层级、关闭顺序要单独设计；`hide()` 只是隐藏，不等于销毁，也不等于能再次展开。
